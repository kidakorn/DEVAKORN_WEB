คู่มือฝึกฝีมือ — เล่ม 1

โปรเจกต์ฝึกมือ Flutter
สำหรับเวลาว่าง

รวมโปรเจกต์เดี่ยวขนาดเล็ก เรียงจากง่ายไปยาก แต่ละอันฝึกทักษะคนละจุด ไม่ต้องทำครบทุกอันหรือทำตามลำดับเป๊ะ ๆ เลือกอันที่สนใจที่สุดตอนว่างได้เลย

เอกสารนี้แยกจากแผนงานหลักของระบบ POS ที่กำลังวางแผนอยู่ ใช้เป็นที่ฝึกทักษะย่อยก่อนหรือระหว่างที่รอเริ่มงานจริง
1

ระดับง่าย

ทำคนเดียวจบใน 3–7 วัน

Todo List พร้อมเก็บข้อมูลในเครื่อง

2–4 วัน

แอปจดสิ่งที่ต้องทำ เพิ่ม/ลบ/ติ๊กเสร็จ ข้อมูลอยู่ในเครื่องอย่างเดียว ไม่มี backend

จะได้เรียนรู้ ควรทำเป็นโปรเจกต์แรกสุด เพราะไม่มี backend มากวนใจ ได้โฟกัสแค่ widget, state management (Riverpod), และ local storage (sqflite หรือ Hive) ล้วน ๆ เป็นการปูพื้นฐานก่อนไปแตะโปรเจกต์ที่มี backend
ขั้นตอน
  1. สร้างโปรเจกต์ Flutter ใหม่ด้วยคำสั่ง flutter create
  2. ออกแบบหน้าจอหลักด้วย widget พื้นฐาน (Scaffold, ListView)
  3. สร้าง model ง่าย ๆ สำหรับ todo item (title, isDone)
  4. ติดตั้ง Riverpod แล้วผูก state เป็นลิสต์ของ todos
  5. เพิ่มฟังก์ชันเพิ่ม/ลบ/ติ๊กเสร็จ ทดสอบว่าหน้าจออัปเดตถูก
  6. ติดตั้ง Hive หรือ sqflite เพื่อเก็บข้อมูลถาวรในเครื่อง
  7. โหลดข้อมูลตอนเปิดแอป และบันทึกทุกครั้งที่มีการแก้ไข
  8. ทดสอบปิดแอปแล้วเปิดใหม่ ข้อมูลต้องยังอยู่ครบ
▸ Prompt สั่ง Agent 
งานนี้เป็นโปรเจกต์ฝึกฝีมือเดี่ยว แยกจากระบบ POS หลัก ชื่อโปรเจกต์: Todo List พร้อมเก็บข้อมูลในเครื่อง

กติกาที่ต้องทำตามตลอดงานนี้:
- เสนอแผนย่อยก่อนเริ่มเขียนโค้ดเสมอ แล้วรอฉันอนุมัติก่อนลงมือ
- ทำทีละขั้นตอนตามลิสต์ด้านล่าง อย่าข้ามหรือรวมหลายขั้นตอนโดยไม่แจ้ง
- อธิบายเหตุผลทุกการตัดสินใจทางเทคนิค ฉันไม่มีพื้นฐาน Flutter มาก่อน ให้อธิบายในระดับที่คนเริ่มต้นเข้าใจได้
- ห้ามใช้ emoji ที่ใดทั้งสิ้น ไม่ว่าในโค้ด คอมเมนต์ หรือข้อความตอบกลับ
- คอมเมนต์โค้ดที่ไม่ตรงไปตรงมาให้บอกว่าทำไมถึงเขียนแบบนั้น ไม่ใช่แค่บอกว่าทำอะไร

ขั้นตอนที่ต้องทำ:
1. สร้างโปรเจกต์ Flutter ใหม่ด้วยคำสั่ง flutter create
2. ออกแบบหน้าจอหลักด้วย widget พื้นฐาน (Scaffold, ListView)
3. สร้าง model ง่าย ๆ สำหรับ todo item (title, isDone)
4. ติดตั้ง Riverpod แล้วผูก state เป็นลิสต์ของ todos
5. เพิ่มฟังก์ชันเพิ่ม/ลบ/ติ๊กเสร็จ ทดสอบว่าหน้าจออัปเดตถูก
6. ติดตั้ง Hive หรือ sqflite เพื่อเก็บข้อมูลถาวรในเครื่อง
7. โหลดข้อมูลตอนเปิดแอป และบันทึกทุกครั้งที่มีการแก้ไข
8. ทดสอบปิดแอปแล้วเปิดใหม่ ข้อมูลต้องยังอยู่ครบ

หลังจบแต่ละขั้นตอน สรุปให้ฉันทราบว่าทำอะไรไปบ้าง ทดสอบอย่างไร แล้วรอฉันยืนยันก่อนไปขั้นถัดไป

2–3 วัน

กรอกชื่อเมือง แล้วแสดงอุณหภูมิ/สภาพอากาศ โดยเรียก API ฟรีจากภายนอก (เช่น OpenWeatherMap)

จะได้เรียนรู้ ฝึกเรียก REST API จากแหล่งภายนอก, จัดการ loading/error state (พิมพ์ชื่อเมืองผิด, เน็ตหลุด), และ parse JSON เป็น Dart object — ตรงกับสิ่งที่ต้องทำตอนแอป Flutter คุยกับ backend NestJS ของโปรเจกต์ POS
ขั้นตอน
  1. สมัคร API key ฟรีจากผู้ให้บริการ เช่น OpenWeatherMap
  2. สร้างโปรเจกต์ Flutter ใหม่
  3. ออกแบบหน้าจอ: ช่องกรอกชื่อเมือง ปุ่มค้นหา พื้นที่แสดงผล
  4. เขียนฟังก์ชันเรียก API ด้วย package http
  5. แปลง JSON response เป็น Dart object
  6. แสดงผลอุณหภูมิและสภาพอากาศบนหน้าจอ
  7. จัดการ error กรณีพิมพ์ชื่อเมืองผิดหรือเน็ตหลุด แสดงข้อความที่เข้าใจง่าย
  8. เพิ่ม loading indicator ระหว่างรอข้อมูลจาก API

แอปแชทเรียลไทม์แบบง่าย

1–2 สัปดาห์

ห้องแชทเดียว ทุกคนพิมพ์แล้วเห็นข้อความของกันและกันทันที ไม่ต้องมีระบบเพิ่มเพื่อน/ห้องส่วนตัว

จะได้เรียนรู้ ฝึก WebSocket ตั้งแต่ต้นจนจบในสเกลเล็ก ก่อนไปเจอของจริงที่ซับซ้อนกว่าในเฟส 6 ของ POS (real-time sync สต็อก) จะเข้าใจแนวคิด "server broadcast ข้อมูลไปหาหลาย client พร้อมกัน" โดยไม่ปนกับ logic ธุรกิจที่ซับซ้อน
ขั้นตอน
  1. Setup backend เปล่าด้วย NestJS
  2. เพิ่ม WebSocket gateway (เช่น Socket.io)
  3. สร้าง endpoint รับข้อความแล้ว broadcast ไปทุก client ที่เชื่อมต่ออยู่
  4. Setup โปรเจกต์ Flutter เชื่อมต่อ WebSocket (package socket_io_client)
  5. ออกแบบหน้าจอแชท (ช่องพิมพ์ข้อความ + รายการข้อความ)
  6. ทดสอบเปิดแอปสองเครื่อง (หรือสอง emulator) พิมพ์แล้วดูว่าอีกเครื่องเห็นทันที
  7. เพิ่มชื่อผู้ส่งแสดงคู่กับข้อความ
  8. ถ้าอยากยากขึ้น ลองเพิ่มการแจ้งเตือนเมื่อมีข้อความใหม่

1–2 สัปดาห์

ผู้ใช้เลือกวันเวลาที่ว่างเพื่อจอง (เช่น จองคิวร้านตัดผมสมมติ) ระบบกันไม่ให้จองเวลาเดียวกันซ้ำ

จะได้เรียนรู้ ฝึกปัญหาแบบเดียวกับการตัดสต็อกใน POS — กันไม่ให้สองคนจองเวลาเดียวกันพร้อมกันได้ (concurrency) แต่สเกลเล็กกว่ามาก เหมาะเป็นตัวซ้อมก่อนไปเจอเฟส 2 (Inventory + Orders) ของ POS จริง
ขั้นตอน
  1. ออกแบบ schema: ตาราง slots (วันเวลา, สถานะว่าง/ถูกจอง)
  2. Setup backend NestJS + PostgreSQL
  3. เขียน API ดึงเวลาที่ว่างในแต่ละวัน
  4. เขียน API จองคิว ต้องมี transaction + lock กันจองเวลาเดียวกันซ้ำ
  5. Setup Flutter แสดงปฏิทิน/รายการเวลาที่ว่าง
  6. เพิ่มหน้ายืนยันการจอง
  7. ทดสอบยิง request จองเวลาเดียวกันพร้อมกันสองครั้ง ต้องมีแค่ครั้งเดียวสำเร็จ

  2. ออกแบบ endpoint ที่ต้องการ เช่น ดูสต็อกสินค้า หรือค้นหาข้อมูลลูกค้า
  3. เขียน API wrapper ด้วย LANSA หรือ Node.js ที่ไปเรียกข้อมูลจาก DB2 for i
  4. ทดสอบ API ตัวกลางนี้ด้วย Postman ก่อนแตะ Flutter
  5. Setup โปรเจกต์ Flutter เชื่อมกับ API ตัวกลาง
  6. ออกแบบหน้าจอแสดงผลข้อมูล (รายการ, ค้นหา, รายละเอียด)
  7. จัดการ error กรณี AS400 ตอบช้าหรือ timeout
  8. ทดสอบให้ครบกับข้อมูลจำลองก่อนพิจารณาต่อกับข้อมูลจริง
