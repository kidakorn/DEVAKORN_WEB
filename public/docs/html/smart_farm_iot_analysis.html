01

§ภาพรวมระบบ

หลังตรวจ code.gs เพิ่มเติม พบว่าระบบจริงมี 2 เส้นทางคำสั่งที่แยกจากกัน: (1) ESP32 poll-based — บอร์ดอ่านเซนเซอร์/รีเลย์เอง แล้วไปเช็ค/รายงานสถานะกับ Google Sheet เป็นระยะ และ (2) LINE Bot แบบแชท — ผู้ใช้พิมพ์คำสั่งใน LINE (เช่น on_off_fan, mode_1) เข้า Webhook ของ Apps Script โดยตรง ซึ่งไปแก้ค่าในชีต "control" ชีตเดียวกับที่ ESP32 อ่านอยู่ — สองเส้นทางนี้ "คุยกัน" ผ่านชีต ไม่ได้เชื่อมตรงถึงกัน

เชื่อมต่อแบบมีสาย (SPI/I2C/Digital) WiFi (ใช้งานได้) WiFi (บริการปิดแล้ว/ควรตรวจสอบ)

§แผนพัฒนาต่อ — ไม่ใช้ฮาร์ดแวร์จริง

เนื่องจากยังไม่มีอุปกรณ์ในมือ แบ่งงานเป็น 4 ระยะ ใช้การจำลอง (simulation) แทนของจริงทุกจุด แล้วค่อยเสียบฮาร์ดแวร์จริงตอนท้ายเมื่อพร้อม

01สัปดาห์ 1–2

Refactor + Security

  • ย้าย WiFi password / LINE token / รหัสกล้อง ไปไว้ในไฟล์ secrets.h แยกต่างหาก แล้วใส่ใน .gitignore
  • แก้บั๊ก 3 จุด: pin สลับกันใน sensor_read.ino, sum_soil_all = soil_1_1, และ now_day = now.minute()
  • ย้ายพินรีเลย์ออกจาก GPIO 0 และ 12 ไปพินอื่นที่ไม่ใช่ strapping pin
  • เขียน README + pin-map diagram ให้คนอื่นเข้าใจระบบได้โดยไม่ต้องไล่โค้ดทีละไฟล์
02สัปดาห์ 2–3

ตั้งค่าสภาพแวดล้อมจำลอง (ไม่ใช้ฮาร์ดแวร์จริง)

  • ใช้ Wokwi (wokwi.com) จำลอง ESP32 — รองรับ DHT22, ตัวต้านทานปรับค่าได้แทนเซนเซอร์ดิน, LED แทนรีเลย์ และเชื่อม WiFi ออกอินเทอร์เน็ตจริงได้ จึงยิง HTTP ไป Google Apps Script ได้เหมือนของจริง
  • ย้ายจาก Arduino IDE มาเขียนใน VS Code + PlatformIO พร้อมปลั๊กอิน Wokwi (มีไฟล์ wokwi.toml รันจำลองในตัว) — ตอบโจทย์ที่อยากใช้ VS Code ร่วมกับ AI agent
  • ทดสอบ logic 3 โหมดปลูก (เมลอน/แตงโม/สตอเบอร์รี่) ด้วยค่าจำลอง เพื่อยืนยันว่ารอบให้น้ำ/ปุ๋ยถูกต้องหลังแก้บั๊ก
03สัปดาห์ 3–4

ปิดช่องโหว่ + ต่อยอด LINE Bot ที่มีอยู่แล้ว

  • ข่าวดี: ไม่ต้องสร้าง LINE Bot ใหม่ — code.gs มี Messaging API webhook + reply ที่ใช้งานได้จริงอยู่แล้ว (คำสั่ง on_off_fan, mode_1 ฯลฯ)
  • ย้าย Channel Access Token จากที่ฝังในโค้ดไปเก็บใน PropertiesService ของ Apps Script แทน
  • เพิ่มการตรวจสอบ x-line-signature ใน doPost() ก่อนประมวลผล event ป้องกันคนนอกยิง POST ปลอมเข้ามาสั่งงาน
  • ตรวจสอบ/เพิ่ม doGet(e) ให้ตรงกับที่เฟิร์มแวร์ยิง http.GET() เข้ามาจริง
  • เพิ่มฟังก์ชัน pushMessage() ใช้ token เดิมของ Messaging API แทน LINE.notify เดิม สำหรับส่งรูปกล้อง/แจ้งเตือนน้ำหมดเชิงรุก (เก็บ userId จาก event แรกที่ผู้ใช้ทักมา)
04สัปดาห์ 4–5

เว็บแดชบอร์ด + เตรียมส่งงาน

  • ทำหน้าเว็บอ่านค่าจาก Google Sheet ผ่าน Apps Script Web App แสดงกราฟความชื้นดิน/อุณหภูมิย้อนหลังด้วย Chart.js พร้อมปุ่มควบคุม manual
  • รวบรวม README, diagram, วิดีโอสาธิตจากผลจำลอง Wokwi ให้ครบสำหรับการส่งงาน
  • เมื่อฮาร์ดแวร์จริงพร้อม ค่อยสลับจาก Wokwi ไปทดสอบกับบอร์ดจริงโดยแทบไม่ต้องแก้โค้ด logic เลย

§รูปแบบการส่งงาน — GitHub หรือ ZIP?

อาจารย์กำหนดให้ส่งเป็นไฟล์ zip อยู่แล้ว — คำแนะนำคือทำทั้งสองแบบไปพร้อมกัน โดยใช้ GitHub เป็นที่ทำงานหลัก แล้ว export เป็น zip ตอนส่งจริง

📦 ส่งเป็น ZIP อย่างเดียว

  • ตรงตามฟอร์แมตที่อาจารย์กำหนดไว้แล้ว ไม่ต้องอธิบายเพิ่ม
  • ไม่ต้องสมัคร/ดูแลบัญชี GitHub
  • ❌ ไม่มีประวัติการแก้ไข (version history) เวลาแก้บั๊กหรือทำงานกับ AI agent จะย้อนดูของเก่าไม่ได้
  • ❌ แก้ไขร่วมกับเพื่อนในกลุ่มพร้อมกันลำบาก ต้องส่งไฟล์กันเอง

🐙 ทำเป็น GitHub repo

  • มี commit history เห็นว่าแก้อะไรไปบ้าง เหมาะกับตอนทำงานร่วมกับ AI agent (diff ชัดเจน)
  • อาจารย์ตรวจโค้ดผ่านเบราว์เซอร์ได้เลย ไม่ต้องดาวน์โหลด
  • เก็บเป็นพอร์ตโฟลิโอต่อยอดใช้สมัครงาน/ฝึกงานได้
  • ⚠ ต้องระวังไม่ push secrets ขึ้นไป (ใช้ .gitignore)
