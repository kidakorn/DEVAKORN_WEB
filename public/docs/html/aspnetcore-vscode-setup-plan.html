SETUP-PLAN / aspnetcore-vscode / rev.1

Setup Plan — เตรียม VS Code สำหรับ ASP.NET Core แยกตามแนวทาง frontend

แผนเตรียมสภาพแวดล้อมพัฒนา แบ่งเป็นส่วนที่ต้องทำร่วมกันทุกแนวทาง และส่วนที่ต่างกันตาม frontend ที่เลือก (Razor Pages / Blazor / Web API + React)

เป้าหมาย
ติดตั้ง tooling บน VS Code ให้พร้อมเขียนโค้ดและ debug ASP.NET Core ได้ทันที
ขอบเขต
ครอบคลุมการติดตั้งเท่านั้น ไม่รวมการเขียน business logic หรือเชื่อมต่อ IWS/SQL Server จริง
สิ่งที่ต้องเลือกก่อน
แนวทาง frontend หนึ่งใน 3 แบบด้านล่าง (ทำแยกกัน ไม่ต้องทำทุกแบบ)
สารบัญ
  1. ส่วนที่ทำร่วมกันทุกแนวทาง
  2. แนวทาง A — Razor Pages
  3. แนวทาง B — Blazor Server
  4. แนวทาง C — Web API + React

ส่วนที่ทำร่วมกันทุกแนวทาง (ทำก่อนเสมอ)

1ติดตั้ง .NET SDK

VS Code ไม่มี SDK มาให้ ต้องโหลดแยกจาก dotnet.microsoft.com เลือกเวอร์ชัน LTS ล่าสุด (.NET 8 หรือใหม่กว่า)

ตรวจสอบว่าติดตั้งสำเร็จด้วยคำสั่ง:

dotnet --version
2ติดตั้ง extension บน VS Code

เปิด Extensions panel (Ctrl+Shift+X) แล้วติดตั้งตัวนี้เป็นอย่างน้อย:

C# Dev Kit          (publisher: Microsoft)
C#                  (ติดมาพร้อม C# Dev Kit อัตโนมัติ)
.NET Install Tool   (ติดมาพร้อม C# Dev Kit อัตโนมัติ)

หลังติดตั้งแล้ว restart VS Code หนึ่งครั้งเพื่อให้ extension โหลด SDK ที่เจอในเครื่องให้ครบ

3ตรวจสอบว่า debug ได้จริง

สร้างโปรเจกต์ทดสอบเปล่าๆ เพื่อยืนยันว่า setup พร้อมก่อนเริ่มงานจริง:

dotnet new web -o hello-test
cd hello-test
code .

ใน VS Code กด F5 — ถ้า extension ทำงานถูกต้อง จะมี prompt ให้สร้าง launch.json อัตโนมัติ กด generate แล้วลอง set breakpoint ในไฟล์ Program.cs ทดสอบ step debug ได้เลย

ไฟล์ที่เกี่ยวข้อง: .vscode/launch.json, .vscode/tasks.json (generate อัตโนมัติ ไม่ต้องเขียนเอง)
แนวทาง A — ภาษาเดียวล้วน
Razor Pages
C# + HTML ในไฟล์เดียวกัน (.cshtml) ไม่ต้องแตะ JavaScript framework เลย
เหมาะกับ
  • ทีมที่ไม่อยากเรียน JS framework เพิ่ม
  • UI ไม่ซับซ้อน (ฟอร์ม, ตาราง, รายงาน)
  • อยากเริ่มงานเร็วที่สุดในบรรดา 3 แนวทาง
ข้อจำกัด
  • UI โต้ตอบแบบ real-time ทำได้จำกัด
  • ถ้าอนาคตอยากทำ mobile app ต้องเขียน backend แยกใหม่
A1สร้างโปรเจกต์
dotnet new webapp -o InternalApp
cd InternalApp
code .

webapp template คือ Razor Pages ในตัว ได้โฟลเดอร์ Pages/ พร้อมตัวอย่างหน้าแรกมาให้ทันที

A2ติดตั้ง EF Core สำหรับต่อ SQL Server
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Tools
A3รันและตรวจสอบ
dotnet watch run

dotnet watch จะ reload หน้าเว็บอัตโนมัติทุกครั้งที่แก้ไฟล์ .cshtml หรือ .cs สะดวกกว่า dotnet run เฉยๆ ตอนพัฒนา

ไฟล์ที่เกี่ยวข้องหลัก: Pages/*.cshtml, Pages/*.cshtml.cs, Program.cs, appsettings.json
แนวทาง B — ภาษาเดียวล้วน แต่โต้ตอบได้มากกว่า
Blazor Server
เขียน component ด้วย C# ทั้งหมด อัพเดท UI ผ่าน SignalR แบบ real-time
เหมาะกับ
  • ทีมถนัด C# ล้วน ไม่อยากรู้ JS เลย
  • UI ต้องโต้ตอบเยอะกว่า Razor Pages (filter/update แบบไม่ reload หน้า)
  • ใช้งานในวง LAN บริษัท (latency ต่ำ เหมาะกับ Blazor Server)
ข้อจำกัด
  • ต้องมี connection ค้างไว้ตลอด (SignalR) ถ้าเน็ตหลุดบ่อยจะกระทบ UX
  • ไม่เหมาะกับผู้ใช้จำนวนมากพร้อมกันมากๆ (ทุก session กิน memory ฝั่ง server)
B1สร้างโปรเจกต์
dotnet new blazorserver -o InternalApp
cd InternalApp
code .
B2ติดตั้ง extension เสริมสำหรับ Blazor

ติดตั้งเพิ่มจาก Extensions panel เพื่อให้ syntax highlighting ของไฟล์ .razor ทำงานถูกต้อง:

vscode-icons          (ไม่บังคับ แต่ช่วยแยกไฟล์ .razor ให้เห็นชัด)

C# Dev Kit ที่ติดตั้งไปแล้วในขั้นตอนร่วม รองรับ .razor ในตัวอยู่แล้ว ไม่ต้องติดตั้งอะไรเพิ่มเพื่อ debug

B3ติดตั้ง EF Core และรัน
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet watch run
ไฟล์ที่เกี่ยวข้องหลัก: Components/Pages/*.razor, Components/Layout/*.razor, Program.cs
ข้อควรระวัง: ถ้า deploy ผ่าน reverse proxy หรือ load balancer ต้องเปิด WebSocket support ให้ SignalR เชื่อมต่อได้ ไม่งั้น Blazor Server จะใช้งานไม่ได้เลย ควรแจ้ง infra team ล่วงหน้าพร้อมกับเรื่องขอ access SQL Server
แนวทาง C — แยก backend/frontend ชัดเจน
ASP.NET Core Web API + React
backend ส่ง JSON อย่างเดียว frontend เป็นโปรเจกต์ React แยกต่างหาก
เหมาะกับ
  • ต้องการ UI ที่ซับซ้อนหรือ interactive มากที่สุดในกลุ่มนี้
  • วางแผนทำ mobile app ในอนาคต (แชร์ backend เดิมได้)
  • ทีมมีหรือจะมีคนถนัด JS/React แยกจากคนถนัด C#
ข้อจำกัด
  • ต้อง setup และ deploy 2 โปรเจกต์แยกกัน
  • ทีมต้องรู้ทั้ง C# และ JS/TS อย่างน้อยฝั่งใดฝั่งหนึ่งคนละคน
C1ติดตั้ง Node.js (สำหรับฝั่ง React)

ดาวน์โหลด Node.js LTS จาก nodejs.org แล้วตรวจสอบ:

node --version
npm --version
C2สร้าง backend (Web API)
dotnet new webapi -o InternalApp.Api
cd InternalApp.Api
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
code .
C3สร้าง frontend (React + TypeScript)
npm create vite@latest InternalApp.Web -- --template react-ts
cd InternalApp.Web
npm install

แนะนำ Vite แทน Create React App เพราะ dev server เร็วกว่ามาก และเป็นตัวที่ชุมชน React แนะนำเป็นค่าเริ่มต้นในปัจจุบัน

C4ติดตั้ง extension เสริมสำหรับ React
ES7+ React/Redux/React-Native snippets   (publisher: dsznajder)
ESLint                                    (publisher: Microsoft)
Prettier - Code formatter                 (publisher: Prettier)
C5รันสองโปรเจกต์พร้อมกัน

ต้องเปิด terminal 2 หน้าต่างแยกกันใน VS Code (Terminal → Split Terminal):

cd InternalApp.Api && dotnet watch run
cd InternalApp.Web && npm run dev

frontend เรียก backend ผ่าน URL ที่ dotnet watch แสดงตอนรัน (ปกติ https://localhost:5001) ต้องตั้งค่า CORS ฝั่ง Web API ให้อนุญาต origin ของ Vite dev server (ปกติ http://localhost:5173) ก่อน frontend จะเรียกได้

ไฟล์ที่เกี่ยวข้องหลัก: InternalApp.Api/Controllers/*.cs, InternalApp.Web/src/*.tsx, InternalApp.Api/Program.cs (ตั้งค่า CORS)
แผนนี้ครอบคลุมเฉพาะการเตรียมสภาพแวดล้อมพัฒนา ยังไม่รวมการเชื่อมต่อ IWS หรือ SQL Server จริง และยังไม่รวมการตั้งค่า deploy/production ซึ่งควรวางแผนแยกเป็นเอกสารต่างหากเมื่อเลือกแนวทางสุดท้ายแล้ว
