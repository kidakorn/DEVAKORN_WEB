Environment Setup Guide

คู่มือติดตั้งเครื่องมือทั้งหมด

รวมทุกเครื่องมือที่โปรเจ็ค Smart Farm IoT ต้องใช้ (นอกเหนือจากตัว IDE เขียนโค้ด) ตั้งแต่เฟิร์มแวร์ แอปมือถือ ไปจนถึง backend และบอท LINE — ทำตามลำดับ ข้อไหนยังไม่จำเป็นตอนนี้จะบอกไว้ว่ารอได้

สารบัญ
ภาพรวม — เครื่องมือไหนใช้ตอนไหน 1. Git for Windows 2. Flutter + Android Studio 3. PlatformIO (เฟิร์มแวร์) 4. Wokwi (จำลองไม่ต้องมีฮาร์ดแวร์) 5. Google Apps Script 6. LINE Developers Console 7. GitHub 8. Node.js + clasp (ตัวเลือกเสริม)
ภาพรวม

เครื่องมือไหนใช้ตอนไหน

เรียงตามความจำเป็นตอนนี้ — ไม่ต้องติดตั้งทุกอย่างพร้อมกัน ทำตามลำดับ "ตอนนี้" ก่อน

เครื่องมือใช้ทำอะไรสถานะ
Git for Windowsเก็บเวอร์ชันโค้ดทั้งโปรเจ็ค จำเป็นสำหรับ Flutter ด้วยต้องมีตอนนี้
Flutter + Android Studioสร้างแอปมือถือ (Phase 2 ข้อ 3)ต้องมีตอนนี้
Wokwiจำลอง ESP32 โดยไม่ต้องมีฮาร์ดแวร์จริง — ใช้มาตั้งแต่ Phase 0น่าจะมีอยู่แล้ว
Google Apps Scriptรัน backend (Code.gs) — เว็บล้วน ไม่ต้องติดตั้งใช้งานผ่านเว็บ
LINE Developers Consoleจัดการบอท token/webhook — ตั้งไว้แล้วตั้งแต่ Phase 1น่าจะมีอยู่แล้ว
PlatformIOคอมไพล์/อัปโหลดเฟิร์มแวร์ขึ้น ESP32 จริงรอ Phase 3 (มีฮาร์ดแวร์)
GitHubโฮสต์ repo ไว้โชว์พอร์ตโฟลิโอทำตอนไหนก็ได้
Node.js + claspดัน Code.gs ผ่าน command line แทนก็อปวางตัวเลือกเสริม
สรุปสั้น ๆ: ตอนนี้พี่ต้องติดตั้งแค่ Git + Flutter + Android Studio เพื่อทำ Phase 2 ข้อ 3 (Flutter app) ต่อได้ ส่วนที่เหลือน่าจะเคยตั้งไว้แล้วในเซสชันก่อน ๆ (Wokwi, LINE) หรือรอไว้ก่อนได้ (PlatformIO รอมีฮาร์ดแวร์จริง)
1

Git for Windows

ต้องมีตอนนี้

ทำไมต้องมี: เป็นเครื่องมือเก็บเวอร์ชันโค้ด (version control) ที่ repo ทั้งโปรเจ็คใช้อยู่ และ Flutter tooling เองก็เรียกใช้ Git เบื้องหลังตอนติดตั้ง — ถ้ายังไม่มี Flutter จะติดตั้งไม่ผ่าน

  1. ไปที่ git-scm.com/download/win ดาวน์โหลดตัวติดตั้งเวอร์ชันล่าสุด (ตัวติดตั้งจะเลือกให้อัตโนมัติตาม Windows 64-bit)
  2. รันตัวติดตั้ง กด Next ไปเรื่อย ๆ ด้วยค่า default ได้เลย (ค่าเริ่มต้นของ Git for Windows เหมาะกับผู้เริ่มต้นอยู่แล้ว) จุดที่ควรเช็คให้แน่ใจคือ "Git from the command line and also from 3rd-party software" ต้องถูกเลือกไว้
  3. ติดตั้งเสร็จแล้ว ปิด terminal ที่เปิดค้างอยู่ทั้งหมด แล้วเปิดใหม่ (สำคัญ เพราะค่า PATH จะยังไม่อัปเดตถ้าไม่เปิด terminal ใหม่)
  4. ตั้งค่าชื่อ/อีเมลที่จะโชว์ในทุก commit (ทำครั้งเดียว ใช้ได้ตลอด): 
    git config --global user.name "ชื่อพี่"
git config --global user.email "อีเมลพี่"
เช็คว่าติดตั้งสำเร็จ: เปิด terminal พิมพ์ git --version ถ้าขึ้นเลขเวอร์ชัน (เช่น git version 2.4x.x) แปลว่าใช้ได้แล้ว
2

Flutter SDK + Android Studio

ต้องมีตอนนี้ — ใช้ทำ Phase 2 ข้อ 3

ทำไมต้องมี: Flutter SDK คือชุดเครื่องมือหลักสำหรับเขียนแอป ส่วน Android Studio ให้ Android SDK + emulator (มือถือจำลอง) ที่ใช้ทดสอบแอประหว่างพัฒนา — ต้องมีทั้งคู่ ขาดตัวใดตัวหนึ่งจะรันแอปไม่ได้

  1. เปิด VS Code ไปที่ Extensions (Ctrl+Shift+X) ค้นหา Flutter เลือกตัวที่พัฒนาโดย Dart Code กด Install (ตัว Dart extension จะติดตั้งตามมาอัตโนมัติ)
  2. เปิด Command Palette (Ctrl+Shift+P) พิมพ์ Flutter: New Project — ถ้ายังไม่เคยมี Flutter SDK ในเครื่อง VS Code จะเสนอให้ดาวน์โหลดและตั้งค่าให้อัตโนมัติ (ไม่ต้องโหลด .zip เองแล้วไปตั้ง PATH มือ วิธีนี้ง่ายสุดสำหรับคนเพิ่งเริ่ม)
  3. ดาวน์โหลด/ติดตั้ง Android Studio จาก developer.android.com/studio ตอนติดตั้งเลือก component ที่เกี่ยวกับ Android SDK ให้ครบ (ตัวติดตั้งจะเลือกให้อัตโนมัติถ้าใช้ค่า default)
  4. เปิด Android Studio ครั้งแรก ไปที่ Settings → Plugins ค้นหา Flutter กด Install (จะติดตั้ง Dart ให้ด้วยถ้าถาม)
  5. สร้าง Android Virtual Device (emulator) ผ่าน Android Studio → Device Manager → Create Device เลือกรุ่นมือถือที่อยากจำลอง (เลือกรุ่นกลาง ๆ เช่น Pixel ก็พอ)
  6. เปิด terminal ใหม่ พิมพ์ flutter doctor -v เพื่อตรวจสอบว่าทุกอย่างครบ ถ้ามีอะไรค้าง (เช่น Android licenses) มันจะบอกคำสั่งแก้ให้เอง โดยทั่วไปคือ: 
    flutter doctor --android-licenses
    แล้วพิมพ์ y ยอมรับทุกข้อ
  7. เปิด Developer Mode ใน Windows — จำเป็นสำหรับสร้าง symlink ตอน build โปรเจ็คที่มี plugin (เกือบทุกโปรเจ็ค Flutter จริงจะมี plugin) ถ้าไม่เปิดจะเจอ error "Building with plugins requires symlink support" ตอน build ทีหลัง: 
    start ms-settings:developers
    จะเปิดหน้า Settings ให้เลย เปิดสวิตช์ Developer Mode เป็น ON แล้วรีสตาร์ทเครื่อง (แนะนำให้รีสตาร์ท แม้บางครั้งไม่รีก็ใช้ได้ แต่รีชัวร์กว่า)
  8. ทดสอบด้วยโปรเจ็คทิ้งขว้าง (throwaway) ก่อนเริ่มงานจริง เพื่อให้แน่ใจว่าทุกอย่างพร้อมจริง ๆ: 
    flutter create test_app
cd test_app
flutter run
    เลือก emulator หรือมือถือจริงที่ต่อไว้เป็น target ถ้าแอปตัวอย่าง (นับเลขเวลากดปุ่ม +) รันขึ้นมาได้ แปลว่าเครื่องพร้อมทำ Phase 2 ข้อ 3 จริงแล้ว ลบโฟลเดอร์ test_app ทิ้งได้เลยหลังทดสอบผ่าน
เช็คว่าติดตั้งสำเร็จ: รัน flutter doctor -v อีกครั้ง ถ้าเห็นเครื่องหมายถูกสีเขียวที่ "Flutter", "Android toolchain", "Android Studio" ถือว่าพร้อมใช้งานแล้ว (เครื่องหมาย ✗ ที่ "Xcode"/"VS Code" ข้ามได้ ไม่จำเป็นสำหรับงานนี้)
หมายเหตุ: ไม่ต้องติดตั้ง Xcode/iOS toolchain เพราะพัฒนา iOS บน Windows ทำไม่ได้อยู่แล้ว — แผนตอนนี้โฟกัส Android ก่อนตามที่คุยกันไว้ ถ้าอยากได้ iOS ในอนาคตต้องมี Mac เพิ่ม
ถ้าอยากทดสอบบนมือถือจริงแทน emulator: เข้า Settings → About phone กดที่ "Build number" รัว ๆ 7 ครั้งเพื่อปลดล็อก Developer options แล้วเข้า Developer options เปิด "USB debugging" ต่อสาย USB เข้าเครื่อง แล้ว Flutter จะเห็นเครื่องจริงเป็นอีก target หนึ่ง
3

PlatformIO IDE (VS Code Extension)

รอ Phase 3 — มีฮาร์ดแวร์จริงค่อยติดตั้ง

ทำไมต้องมี: ใช้คอมไพล์และอัปโหลดเฟิร์มแวร์ (.ino/.cpp) ขึ้น ESP32 จริงผ่านสาย USB — ตอนนี้ยังไม่มีฮาร์ดแวร์ ทดสอบผ่าน Wokwi ล้วน จึงยังไม่จำเป็นต้องติดตั้งตอนนี้ แปะขั้นตอนไว้ให้ล่วงหน้าสำหรับตอนถึง Phase 3

  1. เปิด VS Code ไปที่ Extensions ค้นหา PlatformIO IDE กด Install (ใช้เวลาสักพัก เพราะโหลด core tools เพิ่มเบื้องหลัง)
  2. รีสตาร์ท VS Code หลังติดตั้งเสร็จ จะเห็นไอคอน PlatformIO (รูปมด) ที่แถบซ้าย
  3. ติดตั้ง USB driver ให้ตรงกับชิปที่บอร์ด ESP32 ใช้ (เช็คจากบอร์ดที่จะซื้อ): ถ้าเป็นชิป CP210x โหลดจากเว็บ Silicon Labs, ถ้าเป็น CH340 โหลดจากเว็บผู้ผลิตชิปนั้น — ไม่มี driver จะเสียบสาย USB แล้ว Windows ไม่รู้จักบอร์ด
  4. เปิดโปรเจ็คเฟิร์มแวร์ที่มี platformio.ini อยู่แล้ว (ทำไว้ตั้งแต่ Phase 0) PlatformIO จะสแกน dependency ให้อัตโนมัติ
เช็คว่าติดตั้งสำเร็จ: ต่อบอร์ด ESP32 จริงเข้าเครื่อง แล้วกดปุ่ม ✓ (compile) ที่แถบล่างของ VS Code ถ้า compile ผ่านและเห็นพอร์ต COM ของบอร์ดในแถบล่าง แปลว่าพร้อมอัปโหลดจริงแล้ว
4

Wokwi (จำลอง ESP32)

น่าจะตั้งไว้แล้วตั้งแต่ Phase 0

ทำไมต้องมี: จำลองวงจร ESP32 + เซนเซอร์ทั้งหมดโดยไม่ต้องมีฮาร์ดแวร์จริง — เป็นตัวที่ใช้ทดสอบมาตลอด Phase 0-2 แปะไว้เผื่อพี่สลับเครื่องหรือต้องตั้งค่าใหม่

  1. สมัครบัญชีฟรีที่ wokwi.com (ใช้ผ่าน browser ได้เลย ไม่ต้องติดตั้งอะไร)
  2. ถ้าอยากรันจำลองจากภายใน VS Code โดยตรง (สะดวกกว่าเปิดเว็บแยก) ติดตั้ง extension Wokwi for VS Code จาก Extensions
  3. ผูกบัญชี Wokwi กับ extension (จะมีปุ่ม "Connect to Wokwi" ขึ้นมาให้กดตอนเปิดใช้ครั้งแรก) แผน Free ใช้ได้กับโปรเจ็คที่มี wokwi.toml อยู่แล้ว (มีไฟล์นี้ในโปรเจ็คตั้งแต่ Phase 0)
เช็คว่าใช้งานได้: เปิดโฟลเดอร์เฟิร์มแวร์ที่มี wokwi.toml กด F1 พิมพ์ Wokwi: Start Simulator ถ้าจำลองวงจรขึ้นมาและ Serial Monitor พิมพ์ log ออกมา แปลว่าใช้งานได้ปกติ
5

Google Apps Script

ใช้งานผ่านเว็บ ไม่ต้องติดตั้ง

ทำไมต้องมี: เป็นที่รัน backend (Code.gs) ทั้งหมดของโปรเจ็ค — รับข้อมูลเซนเซอร์, คุยกับ LINE Bot, เก็บ token ใน Script Properties ทำงานผ่าน browser ล้วน ไม่มีอะไรให้ติดตั้งลงเครื่อง

  1. ใช้บัญชี Google เดิมที่สร้างชีต sheet1/control ไว้แล้วตั้งแต่ก่อนเริ่มโปรเจ็คนี้ (ดูขั้นตอนสร้างชีตใหม่ได้ใน google-sheet-setup.md ถ้าต้องสร้างใหม่)
  2. เปิด Google Sheet ที่ใช้อยู่ → Extensions → Apps Script จะเปิดตัวแก้ไข Code.gs ในแท็บใหม่
  3. ทุกครั้งที่แก้โค้ดใน Apps Script editor ต้องกด Deploy → Manage deployments → แก้ไข (ไอคอนดินสอ) → Version: New version → Deploy ใหม่ ไม่งั้น URL Web App เดิมจะยังใช้โค้ดเวอร์ชันเก่าอยู่ — จุดนี้เป็นจุดที่คนพลาดกันบ่อย
หมายเหตุ: ถ้าอยากดัน Code.gs จากเครื่อง (เช่นให้ Claude Code แก้ไฟล์ในเครื่องแล้วอัปขึ้น Apps Script อัตโนมัติ) ต้องใช้เครื่องมือเสริมชื่อ clasp — ดูหัวข้อ 8 ด้านล่าง (เป็นตัวเลือกเสริม ไม่จำเป็น)
6

LINE Developers Console

น่าจะตั้งไว้แล้วตั้งแต่ Phase 1

ทำไมต้องมี: เป็นที่จัดการ Channel Access Token / Channel Secret และตั้งค่า Webhook URL ให้ LINE ส่ง event เข้ามาที่ Apps Script — ใช้ผ่านเว็บล้วน แปะขั้นตอนไว้เผื่อต้องตั้งค่าใหม่หรือ token หมดอายุ

  1. ไปที่ developers.line.biz/console ล็อกอินด้วยบัญชี LINE เดิมที่สร้าง Provider ไว้
  2. เข้า Channel ที่เป็น Messaging API ของโปรเจ็คนี้ → แท็บ Messaging API
  3. ถ้า token หมดอายุหรือต้องออกใหม่ กด Issue ที่ Channel access token (long-lived) แล้วนำค่าไปใส่ใน Script Properties ของ Apps Script (ไม่ใช่ฝังในโค้ดตรง ๆ ตามที่ตัดสินใจไว้ใน Phase 1)
  4. ตรวจว่า Webhook URL ชี้ไปที่ URL ล่าสุดของ Apps Script Web App (URL จะเปลี่ยนทุกครั้งที่ deploy เป็น "New version" ถ้าตั้ง deployment แบบ auto-update URL คงเดิมได้ ให้เช็คด้วยปุ่ม Verify ข้าง Webhook URL)
เช็คว่าใช้งานได้: กดปุ่ม Verify ข้าง Webhook URL ใน console ถ้าขึ้น "Success" แปลว่า LINE เชื่อมกับ Apps Script ได้ปกติ
7

GitHub

ทำตอนไหนก็ได้ ไม่บล็อกงานอื่น

ทำไมต้องมี: เก็บ repo ทั้งโปรเจ็คไว้บนคลาวด์ ใช้โชว์เป็นพอร์ตโฟลิโอได้ตามที่เคยคุยไว้ว่าอยากได้ผลงานไปสมัครงาน — ใช้ Git (หัวข้อ 1) เป็นเครื่องมือคุยกับ GitHub

  1. สมัครบัญชีที่ github.com ถ้ายังไม่มี
  2. กด New repository ตั้งชื่อ (เช่น smart-farm-iot) เลือก Private หรือ Public ก็ได้ตามต้องการ
  3. ในเครื่อง เปิด terminal ไปที่โฟลเดอร์โปรเจ็ค รันคำสั่งเชื่อม repo (แทน URL ด้วยของพี่เอง): 
    git init
git add .
git commit -m "initial commit"
git branch -M main
git remote add origin https://github.com/USERNAME/smart-farm-iot.git
git push -u origin main
เช็คว่าสำเร็จ: รีเฟรชหน้า repo บน GitHub เห็นไฟล์ทั้งหมดขึ้นแล้ว แปลว่า push สำเร็จ
อย่าลืม: เช็ค .gitignore ว่ากันไฟล์ secrets (เช่น secrets.h) ไม่ให้หลุดขึ้น GitHub ก่อน push ทุกครั้ง — มีไฟล์นี้เตรียมไว้แล้วตั้งแต่ Phase 0
8

Node.js + clasp

ตัวเลือกเสริม ไม่จำเป็นตอนนี้

ทำไมอาจอยากมี: ปกติแก้ Code.gs ต้องเปิด browser ไปวางโค้ดใน Apps Script editor เอง — clasp (Command Line Apps Script Projects ของ Google) ให้ push โค้ดจากเครื่อง (ที่ Claude Code แก้ไฟล์ให้) ขึ้น Apps Script ได้โดยตรงผ่าน terminal สะดวกกว่าถ้าจะแก้บ่อย ๆ แต่ไม่ใช่สิ่งจำเป็นต่อการทำโปรเจ็คให้เสร็จ

  1. ติดตั้ง Node.js (LTS version) จาก nodejs.org ตัวติดตั้งมี npm มาให้ในตัวอยู่แล้ว
  2. เปิด terminal รัน npm install -g @google/clasp เพื่อติดตั้ง clasp แบบ global
  3. รัน clasp login จะเปิด browser ให้ล็อกอินด้วยบัญชี Google เดียวกับที่สร้าง Apps Script ไว้
  4. เปิดที่ script.google.com/home/usersettings เปิดสวิตช์ "Google Apps Script API" ให้เป็น ON (clasp จะเชื่อมต่อไม่ได้ถ้าปิดอยู่)
  5. ในโฟลเดอร์ backend/apps-script/ รัน clasp clone [scriptId] (เอา scriptId จาก URL ของ Apps Script editor) เพื่อผูกโฟลเดอร์นี้กับโปรเจ็คบนคลาวด์
