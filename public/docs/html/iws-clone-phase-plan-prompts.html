IWS Clone — Extension Plan

Phase Plan + Agent Prompts

5 phase ต่อยอดจาก RPG source จริงที่วิเคราะห์ไว้ แต่ละ phase มี prompt สั่ง agent พร้อมใช้ทันที ก็อปวางได้เลย

1
Bulk/List Endpoint
แก้ปัญหาที่ค้างมานาน — priority สูงสุด

🎯 เพิ่ม endpoint ดึงข้อมูลทั้งหมด (ไม่ต้องใส่ key) ตาม pattern จาก MINPOP.SQLRPG

  • สร้าง GET /api/operators — คืน array operator ทั้งหมด
  • จำกัดจำนวนสูงสุด (เลียนแบบ 9999 limit ใน RPG) กันดึงข้อมูลเยอะเกินจน server ค้าง
  • เผื่อ pagination (?limit=50&offset=0) ไว้ตั้งแต่ต้น แม้ยังไม่ใช้จริงตอนนี้
Prompt 
เพิ่ม endpoint bulk list ให้ IWS clone นี้ ตาม pattern จาก MINPOP.SQLRPG 
ที่ดึงข้อมูลทั้งตารางแบบ array (ไม่ใช่ key-based lookup แบบ minpop เดิม)

งานที่ต้องทำ:
1. สร้าง routes/operators.js ใหม่ (แยกจาก routes/minpop.js เดิม 
   ห้ามแก้ minpop.js เดิม)
2. เพิ่ม GET /api/operators รองรับ query param ?limit= และ ?offset= 
   (default limit=100, จำกัดสูงสุดไม่เกิน 9999 แถวต่อครั้ง เลียนแบบ 
   limit ที่เจอใน RPG ต้นฉบับ)
3. ใช้ lib/queryRunner.js ที่มีอยู่แล้ว (ห้ามเขียน connection logic ใหม่)
4. Response format: { P_ISFOUND: "1"/"0", DATA: [...], TOTAL: number }
5. เพิ่ม route นี้ใน server.js
6. ห้ามแก้ routes/minpop.js, routes/talinf.js, lib/db.js เดิมเลย
ไฟล์ที่แตะ: routes/operators.js (ใหม่), server.js (เพิ่ม 1 บรรทัด)
2
Resolve Chain Helper
Generalize จาก CHKASSY pattern

🎯 ดึง logic "หา code → resolve name จากตารางอื่น → ถ้าไม่เจอปล่อยว่าง" จาก talinf.js มาทำเป็นฟังก์ชันกลาง ใช้ซ้ำได้กับ endpoint อื่น

  • สร้าง lib/resolveField.js — ฟังก์ชัน generic รับ (table, keyColumn, keyValue, targetColumn)
  • Refactor routes/talinf.js ให้เรียกใช้ helper นี้แทนการเขียน query ซ้อนมือ
Prompt 
สร้าง generic resolve helper จาก pattern ที่เจอใน routes/talinf.js 
(การ query หา code แล้ว resolve name จากตารางอื่น ถ้าไม่เจอให้ปล่อยว่าง 
ไม่ throw error)

งานที่ต้องทำ:
1. สร้าง lib/resolveField.js มีฟังก์ชัน:
   async function resolveField(table, keyColumn, keyValue, targetColumn)
   คืนค่า string ว่าง "" ถ้าไม่เจอ หรือ throw error เฉพาะกรณี DB connection พัง
   (ไม่ throw กรณีแค่ไม่เจอข้อมูล)
2. ใช้ lib/queryRunner.js เดิมเป็นฐาน ห้ามเขียน connection logic ใหม่
3. Refactor routes/talinf.js ให้เรียกใช้ resolveField() แทนโค้ด query 
   ซ้อนกัน 3 ชั้นที่มีอยู่ตอนนี้ — ผลลัพธ์ response ต้องเหมือนเดิมทุกประการ
4. เขียน unit test ง่ายๆ เช็คว่า resolveField คืนค่าว่างถูกต้องเมื่อไม่เจอ 
   ข้อมูล ไม่ throw error
5. ห้ามเปลี่ยน response format ของ /api/talinf ที่มีอยู่แล้ว
ไฟล์ที่แตะ: lib/resolveField.js (ใหม่), routes/talinf.js (refactor)
3
Input Validation Middleware
มาตรฐานเดียวกันทุก endpoint

🎯 ทำ middleware เช็ค query param ก่อนเข้า route ทุกตัว เลียนแบบการเช็ค parameter ที่เจอใน MINPOP03.SQLRPG

  • เช็คว่า param จำเป็นมีค่าไหม, ความยาวเกินกำหนดไหม
  • ตอบ error format สม่ำเสมอ ({ error: string, field: string })
Prompt 
สร้าง input validation middleware กลางสำหรับ Express routes ทั้งหมด 
เลียนแบบการเช็ค parameter length/empty ที่เจอใน MINPOP03.SQLRPG

งานที่ต้องทำ:
1. สร้าง lib/validateParams.js มีฟังก์ชัน 
   validateParams(rules) ที่คืน Express middleware
   rules เป็น object เช่น { empid: { required: true, maxLength: 6 } }
2. ถ้า validation ไม่ผ่าน ตอบ 400 พร้อม format: 
   { error: "message", field: "ชื่อ field ที่ผิด" }
3. เอาไปใช้กับ routes/minpop.js, routes/talinf.js, routes/operators.js 
   (ถ้า phase 1 ทำแล้ว) แทน if-check ที่เขียนซ้ำอยู่ตอนนี้ในแต่ละไฟล์
4. ห้ามเปลี่ยน business logic อื่นนอกจากส่วน validation
5. ทดสอบว่า error message เดิมที่เคยได้ (เช่น "empid is required") 
   ยังคงข้อความเดิมหรือใกล้เคียง ไม่ทำให้ frontend ที่เชื่อมอยู่พัง
ไฟล์ที่แตะ: lib/validateParams.js (ใหม่), routes/*.js (แก้เพิ่ม middleware)
4
JSON Escape Utility
เตรียมไว้เผื่อใช้ (priority ต่ำ)

🎯 เตรียม utility escape อักขระพิเศษ เผื่อวันไหนต้อง build JSON string เอง (ไม่ใช้ res.json() อัตโนมัติ) — จาก pattern ใน GETMINPOP.SQLRPG

  • Node.js ปกติไม่ต้องใช้เพราะ JSON.stringify/res.json() escape ให้อัตโนมัติอยู่แล้ว
  • ทำไว้เป็น reference/utility เผื่อ debug หรือ export CSV/text format ในอนาคต
Prompt 
สร้าง utility function escapeText(str) ใน lib/textUtils.js 
สำหรับ escape อักขระพิเศษ (quote, newline, backslash) 
เลียนแบบ concept จาก GETMINPOP.SQLRPG ที่ escape ก่อน build JSON string มือ

งานที่ต้องทำ:
1. สร้าง lib/textUtils.js มีฟังก์ชัน escapeText(str) 
   คืน string ที่ escape แล้วปลอดภัยสำหรับใส่ใน JSON string หรือ CSV
2. เขียน comment อธิบายว่านี่คือ utility สำรอง เผื่ออนาคตต้อง build 
   response แบบ manual string (ปกติ res.json() ของ Express จัดการให้แล้ว 
   ไม่ต้องเรียกใช้ฟังก์ชันนี้ในโค้ดปกติ)
3. ไม่ต้องเอาไปใช้ใน route ไหนตอนนี้ แค่เตรียมไว้เป็น utility เฉยๆ
ไฟล์ที่แตะ: lib/textUtils.js (ใหม่, ยังไม่ต้องเรียกใช้จริง)
5
Config-driven Endpoint
ใหญ่สุด ทำท้ายสุด — "IWS Studio จิ๋ว"

🎯 ระบบที่เพิ่ม endpoint ใหม่แค่เขียน config (table, key, join chain) ไม่ต้องเขียนไฟล์ route ใหม่ทุกครั้ง — เลียนแบบ generic engine (GENHANDHELD/MINPOP03)

  • ทำหลัง phase 1-3 เสร็จก่อน เพราะต้องพึ่ง resolveField, validateParams, queryRunner ที่มีอยู่แล้ว
  • Config เป็นไฟล์ JSON/JS เช่น config/endpoints/talinf.json ระบุ table, key field, join chain ที่ต้องการ
  • มี 1 route กลาง (routes/dynamic.js) อ่าน config แล้วสร้าง response ให้อัตโนมัติ
Prompt (ทำหลังสุด หลัง phase 1-3 เสร็จแล้วเท่านั้น) 
สร้างระบบ config-driven endpoint ให้ IWS clone นี้ เลียนแบบ 
generic JSON engine ที่เจอใน GENHANDHELD.SQLRPG/MINPOP03.SQLRPG 
(RPG ตัวนั้นรับชื่อ table+keys แล้ว generate JSON อัตโนมัติ)

ก่อนเริ่ม เช็คว่ามีไฟล์เหล่านี้อยู่แล้วหรือยัง (ต้องมีก่อนถึงทำต่อได้):
- lib/queryRunner.js
- lib/resolveField.js  
- lib/validateParams.js
ถ้ายังไม่มีครบ ให้หยุดแล้วแจ้งกลับมาก่อน อย่าทำต่อ

งานที่ต้องทำ:
1. ออกแบบ schema ของ config file เช่น:
   {
     "table": "MYLIB.TALINF",
     "keyColumn": "CNASSY",
     "keyParam": "lotno",
     "selectColumns": ["CDDEVC", "CDWINP", "CNMARK", "CNWEFR"],
     "resolves": [
       { "sourceColumn": "CDDEVC", "table": "MYLIB.MDVICE", 
         "keyColumn": "CDDEVC", "targetColumn": "NMDEVC", 
         "responseKey": "DEVICE_NAME" }
     ]
   }
2. สร้าง config/endpoints/ folder เก็บไฟล์ config แบบนี้ 
   (สร้างตัวอย่าง talinf.json จาก logic ที่มีอยู่แล้วใน routes/talinf.js)
3. สร้าง routes/dynamic.js — 1 route กลางที่:
   - อ่าน config ตามชื่อ endpoint จาก URL param
   - validate input ด้วย lib/validateParams.js
   - query หลักด้วย lib/queryRunner.js
   - resolve field เพิ่มเติมด้วย lib/resolveField.js ตามที่ config ระบุ
4. ทำเป็น "เพิ่มเติม" ไม่ใช่แทนที่ — เก็บ routes/talinf.js, 
   routes/minpop.js เดิมไว้ทำงานคู่ขนานได้ ยังไม่ต้องลบทิ้ง
5. ทดสอบว่า config ของ talinf ให้ผลลัพธ์เหมือนกับ routes/talinf.js 
   เดิมทุกประการก่อนค่อยพิจารณาย้ายมาใช้จริง
ไฟล์ที่แตะ: config/endpoints/*.json (ใหม่), routes/dynamic.js (ใหม่)
