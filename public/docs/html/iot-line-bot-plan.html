1
Firmware (ESP32)

เชื่อม WiFi + MQTT, อ่านเซนเซอร์, ควบคุม relay ผ่านคำสั่ง MQTT

  • Subscribe device/{id}/cmd → สั่ง relay
  • Publish device/{id}/sensor ทุก 10 วิ
AGENT PROMPT · PHASE 1
เขียนโค้ด Arduino (C++) สำหรับ ESP32 ในไฟล์ /firmware/main.ino ที่ทำสิ่งต่อไปนี้:
1. เชื่อมต่อ WiFi (ใช้ค่าจาก config.h ที่แยกไฟล์ต่างหาก)
2. เชื่อมต่อ MQTT broker ด้วย library PubSubClient
3. Subscribe topic "device/{DEVICE_ID}/cmd" รับ payload เช่น "ON"/"OFF" แล้วสั่ง digitalWrite ที่ relay pin
4. อ่านค่าจากเซนเซอร์ DHT22 (ใช้ library DHT sensor library) ทุก 10 วินาที
5. Publish ค่าที่อ่านได้เป็น JSON ไปที่ topic "device/{DEVICE_ID}/sensor" รูปแบบ
   {"temp": 28.5, "humidity": 60.2, "ts": 1732000000}
6. ใส่ reconnect logic เมื่อ WiFi/MQTT หลุด
แยก DEVICE_ID, WIFI_SSID, WIFI_PASSWORD, MQTT_BROKER, MQTT_PORT ไว้ใน /firmware/config.h

Mock Device

จำลอง ESP32 ด้วยสคริปต์ Node.js — ทำ Phase 2 เป็นต้นไปได้ทันที ไม่ต้องรอสั่งซื้อบอร์ด ใช้ topic เดียวกับ firmware จริงทุกประการ พอมีบอร์ดค่อยสลับ ไม่ต้องแก้ backend

  • mock-device/index.js — publish sensor ทุก 10 วิ
  • subscribe cmd topic แล้ว log สถานะ relay
AGENT PROMPT · PHASE 1.5
สร้างสคริปต์ Node.js ใน /mock-device/index.js ที่จำลองอุปกรณ์ ESP32 โดยไม่ต้องมี hardware จริง:
1. เชื่อมต่อ MQTT broker จาก env MQTT_BROKER_URL (ใช้ library "mqtt")
2. ทุก 10 วินาที publish JSON ไปที่ topic "device/sensor-temp-1/sensor"
   รูปแบบ {"temp": <สุ่ม 26-38>, "humidity": <สุ่ม 45-75>, "ts": <timestamp>}
3. Subscribe topic "device/relay-light-1/cmd" เมื่อได้รับ "ON"/"OFF" ให้ log สถานะปัจจุบันออกทาง console
4. จัดการ reconnect/error เบื้องต้น และปิดการเชื่อมต่ออย่างสะอาดตอน SIGINT
5. สร้าง package.json ที่มี dependency "mqtt"
ให้ topic ตรงกับที่ /firmware จะใช้ทุกตัวอักษร เพื่อให้สลับไปใช้ ESP32 จริงทีหลังได้โดยไม่แก้ backend
2
Backend Skeleton + MQTT Bridge

Node.js server เชื่อม MQTT ได้ และเก็บ state ล่าสุดของแต่ละอุปกรณ์

  • src/mqtt.js, src/deviceStore.js
  • GET /health, GET /devices
AGENT PROMPT · PHASE 2
สร้าง Node.js backend ใน /backend ใช้ Express โดย:
1. ติดตั้งและตั้งค่า mqtt (npm package "mqtt") ให้เชื่อมต่อ broker จาก env MQTT_BROKER_URL
2. สร้างไฟล์ src/mqtt.js: subscribe topic "device/+/sensor", เมื่อได้ข้อความให้ parse JSON
   แล้วเก็บลง in-memory store (src/deviceStore.js) พร้อม timestamp ล่าสุด
   และ export ฟังก์ชัน publishCommand(deviceId, command) สำหรับส่งคำสั่งไปที่ "device/{id}/cmd"
3. สร้าง src/server.js เป็น Express app พร้อม endpoint GET /health และ GET /devices
   ที่คืนสถานะอุปกรณ์ทั้งหมดจาก deviceStore
4. ใช้ dotenv โหลดค่าจาก .env
ยังไม่ต้องเชื่อม LINE ในเฟสนี้
3
LINE Bot Integration

Webhook รับ-ตอบข้อความ และแปลคำสั่งภาษาไทยเป็นคำสั่งอุปกรณ์

  • POST /webhook + signature validation
  • คำสั่งพื้นฐาน: "เปิดไฟ" / "ปิดไฟ" / "อุณหภูมิ"
AGENT PROMPT · PHASE 3
เพิ่มการเชื่อมต่อ LINE Messaging API เข้ากับ backend ที่มีอยู่:
1. ติดตั้ง @line/bot-sdk และตั้งค่า middleware validate signature ด้วย LINE_CHANNEL_SECRET
2. สร้าง POST /webhook ใน src/server.js ที่รับ event ประเภทข้อความ (message.text)
3. สร้าง src/line.js ที่ export ฟังก์ชัน:
   - replyMessage(replyToken, text)
   - pushMessage(userId, text)  // ใช้สำหรับแจ้งเตือนภายหลัง
4. เขียน logic แยกคำสั่งพื้นฐานในข้อความ (case-insensitive, ภาษาไทย):
   - "เปิดไฟ" -> เรียก publishCommand("relay-light-1", "ON") แล้วตอบ "เปิดไฟเรียบร้อย"
   - "ปิดไฟ" -> publishCommand("relay-light-1", "OFF") แล้วตอบ "ปิดไฟเรียบร้อย"
   - "อุณหภูมิ" หรือ "อุณหภูมิตอนนี้" -> ดึงค่าล่าสุดจาก deviceStore ของ sensor-temp-1 แล้วตอบกลับ
   - ข้อความอื่นๆ -> ตอบวิธีใช้งานสั้นๆ
5. อย่าลืม validate ว่า channel access token/secret มาจาก .env
4
Threshold Alerts

แจ้งเตือนอัตโนมัติเมื่อค่าเซนเซอร์เกินกำหนด พร้อม cooldown กันสแปม

  • src/alertRules.js + subscribers store
  • คำสั่ง "สมัครแจ้งเตือน" / "ยกเลิกแจ้งเตือน"
AGENT PROMPT · PHASE 4
เพิ่มระบบแจ้งเตือนอัตโนมัติในฝั่ง backend:
1. สร้าง src/alertRules.js เก็บ config เช่น
   { "sensor-temp-1": { metric: "temp", max: 35, min: null, cooldownMinutes: 15 } }
2. ใน src/mqtt.js เมื่อได้รับ sensor data ใหม่ ให้เช็คกับ alertRules
   ถ้าเกิน max หรือต่ำกว่า min ให้เรียก pushMessage ไปยัง LINE user ที่ subscribe (เก็บ userId ไว้ใน subscribers store)
3. ต้องมี cooldown ป้องกันการแจ้งเตือนถี่เกินไป (ไม่ส่งซ้ำภายใน cooldownMinutes สำหรับ device+เงื่อนไขเดิม)
4. เพิ่มคำสั่งใน LINE bot: "สมัครแจ้งเตือน" เพื่อบันทึก userId ผู้ใช้เข้า subscribers store
   และ "ยกเลิกแจ้งเตือน" เพื่อลบออก
5
Database & Persistence

ย้ายจาก in-memory เป็น SQLite เพื่อเก็บข้อมูลถาวร

  • ตาราง devices, sensor_logs, subscribers, alert_rules
  • GET /devices/:id/history
AGENT PROMPT · PHASE 5
เปลี่ยน backend จาก in-memory store ให้ใช้ SQLite ผ่าน library better-sqlite3:
1. สร้าง src/db.js เชื่อมต่อไฟล์ data.sqlite และสร้างตารางถ้ายังไม่มี:
   - devices(id TEXT PRIMARY KEY, name TEXT, type TEXT, last_state TEXT, updated_at INTEGER)
   - sensor_logs(id INTEGER PRIMARY KEY AUTOINCREMENT, device_id TEXT, temp REAL, humidity REAL, ts INTEGER)
   - subscribers(user_id TEXT PRIMARY KEY, created_at INTEGER)
   - alert_rules(device_id TEXT PRIMARY KEY, metric TEXT, max_value REAL, min_value REAL, cooldown_minutes INTEGER)
2. แก้ deviceStore.js, alertRules.js, subscribers logic ให้อ่าน/เขียนผ่าน db.js แทน in-memory
3. ทุกครั้งที่ได้ sensor data ใหม่ ให้ insert ลง sensor_logs ด้วย
4. เพิ่ม endpoint GET /devices/:id/history?limit=50 คืนค่า log ล่าสุด

Testing & Deployment

ทดสอบ end-to-end, containerize, deploy จริง

  • docker-compose.yml (backend + mosquitto)
  • Unit test + คู่มือ deploy
AGENT PROMPT · PHASE 6
เตรียมโปรเจ็คสำหรับ deploy:
1. สร้าง docker-compose.yml ที่รวม service: backend (build จาก /backend), mosquitto (image eclipse-mosquitto)
2. เขียน Dockerfile สำหรับ /backend
3. เขียน unit test (ใช้ jest) สำหรับ:
   - การ parse คำสั่งข้อความภาษาไทยใน Phase 3
   - การเช็ค threshold + cooldown ใน Phase 4
4. เขียน /docs/deploy.md อธิบายขั้นตอน:
   - รัน ngrok http 3000 เพื่อทดสอบ LINE webhook ตอน dev
   - ตั้งค่า Webhook URL ใน LINE Developers Console
   - deploy ขึ้น Railway หรือ Render พร้อม environment variables ที่ต้องตั้ง
7
Security Hardening

ปิดช่องโหว่พื้นฐานก่อนใช้งานจริง

  • Rate limit webhook, MQTT TLS + auth
  • Validate/sanitize payload ก่อนเขียน DB
AGENT PROMPT · PHASE 7
เพิ่มมาตรการความปลอดภัยให้ backend:
1. เพิ่ม rate limiting (เช่น express-rate-limit) ที่ endpoint /webhook
2. เปลี่ยนการเชื่อมต่อ MQTT ให้ใช้ TLS (mqtts://) พร้อม username/password จาก env
   และปฏิเสธ topic/device_id ที่ไม่อยู่ใน whitelist ของตาราง devices
3. Sanitize input จาก MQTT payload ก่อน insert ลง database (validate เป็นตัวเลขจริง ไม่ crash เมื่อ payload ผิดรูปแบบ)
4. เพิ่ม logging (เช่น winston หรือ pino) แยก error/info level แทน console.log
วิธีใช้: วาง prompt ของแต่ละ phase ให้ agent ทำทีละขั้นตามลำดับ และรีวิวโค้ดก่อนไป phase ถัดไปเสมอ — โดยเฉพาะ Phase 1 ที่ควรทดสอบกับบอร์ดจริงก่อน
