PART A
แนวคิดการเขียนโปรแกรม (ยังไม่มีโค้ด)
01โปรแกรมคืออะไร

โปรแกรม คือ ชุดคำสั่งที่บอกให้คอมพิวเตอร์ทำอะไรบางอย่าง ทีละขั้น ทีละขั้น เหมือนสูตรอาหารที่บอกว่า "ทำขั้นที่ 1 ก่อน แล้วค่อยทำขั้นที่ 2" คอมพิวเตอร์เองไม่ได้ฉลาดหรือคิดเองได้ มันแค่ทำตามคำสั่งที่เราเขียนไว้ ทีละบรรทัดอย่างเคร่งครัด

เปรียบเทียบ: ถ้าเราสั่งให้เพื่อนชงกาแฟโดยบอกแค่ "ชงกาแฟให้หน่อย" เพื่อนอาจจะเข้าใจเองว่าต้องทำอะไรบ้าง แต่คอมพิวเตอร์ทำแบบนั้นไม่ได้ เราต้องบอกละเอียดทุกขั้น เช่น "ต้มน้ำ" → "ใส่กาแฟ 2 ช้อน" → "เทน้ำร้อนลงไป" → "คนให้เข้ากัน" การเขียนโปรแกรม คือการเขียนคำสั่งละเอียดขนาดนั้นให้คอมพิวเตอร์ทำตาม

ภาษาโปรแกรม (เช่น C# ที่เรากำลังจะเรียน) คือภาษาที่มนุษย์ใช้เขียนคำสั่งเหล่านั้น ให้คอมพิวเตอร์เข้าใจได้

02Source Code กับการรันโค้ด ต่างกันยังไง

Source code คือ ตัวหนังสือที่เราพิมพ์เขียนคำสั่งไว้ในไฟล์ (ยังไม่ได้ทำงานอะไร แค่เป็นตัวอักษรอยู่ในไฟล์)

การรันโค้ด (run) คือ การสั่งให้คอมพิวเตอร์อ่าน source code นั้น แล้วทำตามคำสั่งจริงๆ ทีละบรรทัด

เปรียบเทียบ: source code เหมือนสูตรอาหารที่เขียนไว้ในกระดาษ ส่วนการรันโค้ด คือตอนที่เรา "ลงมือทำตามสูตรนั้นจริงๆ" ในครัว สูตรอาหารเฉยๆ ไม่ทำให้เกิดอาหารขึ้นมา ต้องมีคนลงมือทำตามถึงจะได้อาหารจริง

สำหรับภาษา C# ตัวที่ทำหน้าที่ "อ่านแล้วรันตามคำสั่ง" เรียกว่า .NET (อ่านว่า ดอท-เน็ต) เราจะติดตั้งมันในหัวข้อถัดไป

PART B
C# ทีละก้าวเล็กๆ
03เขียนบรรทัดแรก (Hello World)

ก่อนเขียนโค้ด ต้องติดตั้งเครื่องมือ 2 อย่างก่อน:

อย่างแรก — ติดตั้ง .NET SDK จาก dotnet.microsoft.com/download เลือกเวอร์ชัน LTS (เวอร์ชันที่แนะนำ) แล้วติดตั้งตามขั้นตอนของโปรแกรมติดตั้งปกติ

อย่างที่สอง — เปิด VS Code แล้วติดตั้ง extension ชื่อ "C# Dev Kit" (กดที่ไอคอน Extensions ด้านซ้าย พิมพ์ค้นหา แล้วกด Install)

ตรวจสอบว่าติดตั้งสำเร็จ เปิด terminal ใน VS Code (กด Ctrl+`) แล้วพิมพ์:

dotnet --version

ถ้าเห็นตัวเลขเวอร์ชัน (เช่น 8.0.100) แปลว่าเรียบร้อย ถ้าขึ้น error ว่าไม่รู้จักคำสั่งนี้ แปลว่ายังติดตั้งไม่สำเร็จ ต้องกลับไปข้อแรกก่อน

ตอนนี้ลองสร้างโปรแกรมแรกในชีวิต ที่แค่ print ข้อความออกมา:

mkdir hello-world
cd hello-world
dotnet new console
dotnet run

คำสั่ง dotnet new console คือการสร้างโปรแกรมเปล่าๆ แบบง่ายที่สุดให้ ส่วน dotnet run คือการสั่งรันโปรแกรมนั้น ถ้าทำถูกต้อง จะเห็นคำว่า Hello, World! ปรากฏขึ้นมาในหน้าจอ terminal

ลองทำ: เปิดไฟล์ Program.cs ที่ถูกสร้างขึ้นมา (อยู่ในโฟลเดอร์ hello-world) จะเห็นบรรทัดเดียวที่เขียนว่า Console.WriteLine("Hello, World!"); ลองแก้ข้อความในเครื่องหมายคำพูด เป็นชื่อตัวเองแล้วรัน dotnet run ใหม่ ดูว่าข้อความเปลี่ยนไหม
04ตัวแปรคืออะไร

ตัวแปร คือ ที่สำหรับเก็บค่าไว้ใช้ในภายหลัง เหมือนกล่องที่มีชื่อติดไว้ ใส่ของลงไปแล้วเรียกของนั้นออกมาใช้ทีหลังได้ โดยเรียกผ่านชื่อกล่อง

เปรียบเทียบ: เหมือนเขียนชื่อกำกับบนกล่องเก็บของ เช่น กล่องชื่อ "อายุ" ใส่เลข 25 ไว้ข้างใน ทีหลังพอเราพูดถึง "อายุ" คอมพิวเตอร์ก็รู้ว่าหมายถึง 25

ในภาษา C# การสร้างตัวแปรเขียนแบบนี้:

int age = 25;
string name = "Somchai";

อ่านว่า "สร้างตัวแปรชื่อ age เก็บค่าเป็นตัวเลข 25" และ "สร้างตัวแปรชื่อ name เก็บค่าเป็นข้อความ Somchai" คำว่า int และ string ด้านหน้า คือการบอกว่าของในกล่องนี้เป็น "ชนิด" ไหน ซึ่งจะอธิบายละเอียดในหัวข้อถัดไป

ลองทำ: ในไฟล์ Program.cs เดิม เพิ่มบรรทัด int age = 25; ไว้ก่อนบรรทัด Console.WriteLine แล้วเปลี่ยนบรรทัดนั้นเป็น Console.WriteLine(age); รันดูว่าเห็นเลข 25 ปรากฏขึ้นมาไหม
05ชนิดข้อมูล (Data Type)

ทำไมต้องบอกคอมพิวเตอร์ว่าของในกล่องเป็น "ตัวเลข" หรือ "ข้อความ" เพราะแต่ละชนิดทำงานต่างกัน เช่น ตัวเลขเอามาบวกลบคูณหารกันได้ แต่ข้อความบวกกันไม่ได้ในความหมายเดียวกัน (บวกข้อความคือการต่อกันแทน) การบอกชนิดไว้ล่วงหน้าช่วยให้คอมพิวเตอร์เตือนเราได้ทันทีถ้าทำอะไรผิดประเภท เช่น เอาข้อความไปหารตัวเลข

ชนิดข้อมูลพื้นฐานที่ใช้บ่อยที่สุด:

int quantity = 10;        // ตัวเลขจำนวนเต็ม
decimal price = 25.50m;   // ตัวเลขทศนิยม (ใช้กับเงินเสมอ)
string name = "Somchai";  // ข้อความ
bool isActive = true;     // ค่าจริง/เท็จ (true หรือ false เท่านั้น)
ทำไมต้อง decimal สำหรับเงิน: ตัวเลขทศนิยมแบบปกติ (เรียกว่า double หรือ float) อาจคำนวณเงินแล้วเพี้ยน เล็กน้อยจากการปัดเศษของคอมพิวเตอร์ ภาษา C# เลยมีชนิดพิเศษชื่อ decimal ที่แม่นยำกว่าสำหรับงานเงินโดยเฉพาะ
ลองทำ: เพิ่มตัวแปร 4 ชนิดข้างบนในโปรแกรมเดิม แล้วลอง Console.WriteLine แต่ละตัวดูทีละบรรทัด สังเกตว่าแสดงผลต่างกันยังไง
06การตัดสินใจ (if/else)

ในชีวิตจริงเราตัดสินใจตลอดเวลา เช่น "ถ้าฝนตก ให้พกร่ม ถ้าไม่ตก ก็ไม่ต้องพก" โปรแกรมก็ต้องตัดสินใจแบบนี้ได้เหมือนกัน เรียกว่า if/else (ถ้า.../ไม่งั้น...)

int age = 25;

if (age >= 18)
{
    Console.WriteLine("เป็นผู้ใหญ่แล้ว");
}
else
{
    Console.WriteLine("ยังไม่บรรลุนิติภาวะ");
}

อ่านว่า "ถ้า age มากกว่าหรือเท่ากับ 18 ให้ print ว่าเป็นผู้ใหญ่ ไม่งั้นให้ print อีกอันแทน" สังเกตว่าคอมพิวเตอร์จะเลือกทำแค่ทางใดทางหนึ่งเท่านั้น ไม่ทำทั้งสองทาง

เครื่องหมายเปรียบเทียบที่ใช้บ่อย: == (เท่ากับ), != (ไม่เท่ากับ), > (มากกว่า), < (น้อยกว่า), >= (มากกว่าหรือเท่ากับ) สังเกตว่าเครื่องหมาย "เท่ากับ" ในการเปรียบเทียบต้องใช้ == สองตัว ไม่ใช่ = ตัวเดียว (ตัวเดียวใช้สำหรับ "กำหนดค่า" อย่างที่เจอในหัวข้อ 4)
ลองทำ: เขียนโปรแกรมเช็คว่าตัวเลขที่กำหนดเป็นเลขคู่หรือเลขคี่ (ใบ้: ใช้ number % 2 == 0 เช็คว่าหารด้วย 2 ลงตัวไหม เครื่องหมาย % คือหาเศษที่เหลือจากการหาร)
07การทำซ้ำ (Loop)

ถ้าต้องการให้คอมพิวเตอร์ทำอะไรซ้ำๆ กันหลายรอบ เช่น print ข้อความ 5 ครั้ง แทนที่จะเขียน Console.WriteLine ซ้ำ 5 บรรทัด เราใช้ loop (การวนซ้ำ) แทน

for (int i = 1; i <= 5; i++)
{
    Console.WriteLine("รอบที่ " + i);
}

อ่านว่า "เริ่มจาก i เท่ากับ 1 ทำซ้ำไปเรื่อยๆ ตราบใดที่ i ยังน้อยกว่าหรือเท่ากับ 5 แล้วเพิ่มค่า i ทีละ 1 ในแต่ละรอบ" ผลลัพธ์คือจะ print คำว่า "รอบที่ 1" ถึง "รอบที่ 5" ออกมาทั้งหมด 5 บรรทัด

เปรียบเทียบ: เหมือนบอกให้ใครทำ squat 5 ครั้ง แทนที่จะบอกทีละครั้งว่า "squat 1 ครั้ง" ซ้ำ 5 รอบ เราแค่บอกครั้งเดียวว่า "ทำ squat 5 ครั้ง" loop ก็ทำหน้าที่แบบนั้น
ลองทำ: เขียน loop ที่ print ตัวเลข 1 ถึง 10 แต่ให้ print เฉพาะเลขคู่เท่านั้น (รวมความรู้จากหัวข้อ 6 กับ 7 เข้าด้วยกัน)
08Method — การตั้งชื่อ "งาน" ที่ทำซ้ำได้

ถ้ามีชุดคำสั่งที่ต้องใช้ซ้ำๆ หลายที่ในโปรแกรม แทนที่จะเขียนซ้ำทุกครั้ง เราตั้งชื่อชุดคำสั่งนั้นไว้ครั้งเดียว แล้วเรียกใช้ชื่อนั้นซ้ำได้เรื่อยๆ ชุดคำสั่งที่ตั้งชื่อไว้แบบนี้เรียกว่า method

// สร้าง method ชื่อ Greet
static void Greet(string name)
{
    Console.WriteLine("สวัสดี " + name);
}

// เรียกใช้ method
Greet("Somchai");
Greet("Somying");

method Greet รับค่าเข้ามา 1 ค่า (เรียกว่า parameter) ชื่อ name แล้ว print คำทักทายออกมา พอเรียก Greet("Somchai") ก็เหมือนบอกว่า "ทำงาน Greet โดยใช้ค่า Somchai แทน name"

method ที่ return ค่ากลับมา: บาง method ไม่ได้แค่ print แต่ "คำนวณแล้วส่งผลลัพธ์กลับมา" ด้วย return เช่น 
static int Add(int a, int b)
{
    return a + b;
}

int result = Add(3, 5);   // result จะเก็บค่า 8
ลองทำ: เขียน method ชื่อ IsEven ที่รับตัวเลข 1 ตัว แล้ว return ค่า true/false ว่าเป็นเลขคู่ไหม (เอาความรู้จากหัวข้อ 6 มาใช้)
09Class — การจัดกลุ่มข้อมูลที่เกี่ยวกัน

ลองนึกภาพว่าต้องเก็บข้อมูลลูกค้า 1 คน ซึ่งมีทั้งชื่อ อายุ และเบอร์โทร ถ้าใช้ตัวแปรแยกกัน 3 ตัว (ตามหัวข้อ 4) จะดูแลยากขึ้นเรื่อยๆ เมื่อมีลูกค้าหลายคน class คือวิธี "รวมข้อมูลที่เกี่ยวข้องกัน" ไว้เป็นก้อนเดียว

class Customer
{
    public string Name;
    public int Age;
    public string Phone;
}

นี่คือการ "นิยาม" ว่า Customer 1 คนมีข้อมูลอะไรบ้าง ยังไม่ได้สร้างลูกค้าจริง ต้องสร้างแบบนี้:

Customer customer1 = new Customer();
customer1.Name = "Somchai";
customer1.Age = 30;
customer1.Phone = "0812345678";

Console.WriteLine(customer1.Name);
เปรียบเทียบ: class เหมือน "แบบฟอร์ม" เปล่าที่กำหนดว่ามีช่องอะไรบ้าง (ชื่อ, อายุ, เบอร์โทร) ส่วนการสร้าง new Customer() คือการ "กรอกแบบฟอร์มจริง" ทีละใบ แต่ละใบคือลูกค้าคนละคนกัน
ลองทำ: สร้าง class ชื่อ Product มี field ชื่อ Name และ Price แล้วสร้างสินค้า 2 ชิ้นขึ้นมาจริง print ราคาทั้งสองออกมา
10List — เก็บของหลายชิ้นไว้ด้วยกัน

จากหัวข้อ 9 ถ้ามีลูกค้า 100 คน จะสร้างตัวแปร customer1, customer2... ไปจนถึง customer100 คงไม่ไหว List คือกล่องใหญ่ที่เก็บของหลายชิ้นไว้ด้วยกันในที่เดียว

List<string> fruits = new List<string>();
fruits.Add("แอปเปิ้ล");
fruits.Add("กล้วย");
fruits.Add("ส้ม");

foreach (var fruit in fruits)
{
    Console.WriteLine(fruit);
}

List<string> หมายถึง "List ที่เก็บข้อความ" (ในเครื่องหมาย < > คือบอกว่า ของข้างในเป็นชนิดอะไร) ส่วน foreach คือ loop แบบพิเศษที่ใช้ "วนดูของทุกชิ้นใน List ทีละชิ้น" ต่างจาก for ในหัวข้อ 7 ตรงที่ไม่ต้องนับจำนวนรอบเอง

List ของ class ก็ทำได้: รวมความรู้หัวข้อ 9 กับ 10 เข้าด้วยกัน เก็บลูกค้าหลายคนไว้ใน List เดียว 
List<Customer> customers = new List<Customer>();
customers.Add(customer1);
customers.Add(customer2);
ลองทำ: สร้าง List ของ Product จากหัวข้อ 9 ใส่สินค้า 3 ชิ้น แล้วใช้ foreach print ชื่อและราคาของทุกชิ้นออกมา — ถือว่าจบ Part B แล้ว!
PART C
เว็บแอปคืออะไร (ก่อนแตะ ASP.NET Core)
11เว็บทำงานยังไง

ก่อนเขียนเว็บแอป ต้องเข้าใจภาพรวมก่อนว่าเว็บทำงานยังไง (ยังไม่มีโค้ดในหัวข้อนี้)

เปรียบเทียบ: ลองนึกภาพร้านอาหาร มี "ลูกค้า" (browser ที่เราใช้เปิดเว็บ) กับ "ครัว" (server เครื่องที่เก็บโปรแกรมและข้อมูลไว้) ลูกค้าสั่งอาหารผ่านบริกร (ส่ง "คำขอ" หรือ request ไปหา server) ครัวทำอาหารเสร็จแล้วส่งกลับมาผ่านบริกร (server ส่ง "คำตอบ" หรือ response กลับมา) ลูกค้าไม่เห็นว่าครัว ทำงานยังไงข้างใน เห็นแค่จานอาหารที่ได้รับ

เวลาเราเปิดเว็บไซต์ browser จะส่ง request ไปหา server ว่า "ขอหน้านี้หน่อย" server ประมวลผล (อาจไปดึงข้อมูลจากฐานข้อมูล คำนวณอะไรบางอย่าง) แล้วส่ง response กลับมาเป็นหน้าเว็บ ให้ browser แสดงผล

ขั้นตอน request → server ประมวลผล → response แบบนี้เกิดขึ้นทุกครั้งที่เราคลิกลิงก์หรือกดปุ่มบนเว็บ

12ASP.NET Core คืออะไรในภาพนั้น

จากหัวข้อ 11 ฝั่ง "ครัว" (server) ต้องมีคนเขียนโปรแกรมกำหนดไว้ว่า พอมี request ประเภทไหนเข้ามา จะต้องทำอะไรตอบกลับไป ASP.NET Core คือเครื่องมือ (framework) ที่ช่วยให้เราเขียนโปรแกรมฝั่งครัวนี้ได้ ด้วยภาษา C# ที่เพิ่งฝึกมาใน Part B

ทำไมต้องมี framework: ถ้าไม่มี ASP.NET Core เราต้องเขียนโค้ดจัดการเรื่องพื้นฐานทุกอย่างเอง ทั้งการรับ request, แปลงข้อมูล, ส่ง response กลับให้ถูกรูปแบบ ASP.NET Core จัดการเรื่องพื้นฐานเหล่านี้ให้แล้ว เราแค่โฟกัสที่ "พอมี request แบบนี้เข้ามา ให้ทำอะไร" พอ

ทุกความรู้จาก Part B (ตัวแปร, if/else, loop, method, class, List) จะถูกใช้จริงตอนเขียน ASP.NET Core เพราะข้างในก็คือโค้ด C# ธรรมดา แค่ทำงานอยู่ในกรอบของ framework ที่คอยรับ-ส่ง request/response ให้เรา

ลองทำ: เปิดดูไฟล์ในโฟลเดอร์ Pages/ มีกี่หน้า แต่ละหน้าชื่ออะไรบ้าง ไม่ต้องเข้าใจเนื้อหาข้างใน แค่สำรวจโครงสร้างก่อน

@page

<h1>สวัสดีจากหน้าเว็บแรกของฉัน</h1>

@page คือบรรทัดที่บอก ASP.NET Core ว่า "ไฟล์นี้คือหน้าเว็บ 1 หน้า เข้าถึงได้ผ่าน URL" ต้องมีบรรทัดนี้อยู่บนสุดของทุกไฟล์หน้าเว็บเสมอ ส่วนที่เหลือคือ HTML ธรรมดา

รัน dotnet run แล้วเปิด http://localhost:5000/Greeting (ชื่อไฟล์ กลายเป็นส่วนหนึ่งของ URL โดยอัตโนมัติ) จะเห็นข้อความที่เขียนไว้ปรากฏขึ้นมา

ทำไมยังไม่มีไฟล์คู่ .cshtml.cs: หน้านี้ยังไม่มี logic อะไรที่ต้องใช้ C# เลย (แค่แสดงข้อความคงที่) เลยยังไม่จำเป็นต้องมีไฟล์คู่ จะเริ่มใช้ไฟล์คู่ในหัวขัดถัดไปที่ต้องมีข้อมูลจาก C# มาแสดง
ลองทำ: แก้ข้อความในไฟล์ Greeting.cshtml เป็นชื่อตัวเอง แล้วรีเฟรชหน้าเว็บดูผล

ตอนนี้จะเอาความรู้เรื่อง class และ List จาก Part B มาแสดงบนหน้าเว็บจริง สร้างไฟล์คู่ 2 ไฟล์ในโฟลเดอร์ Pages/:

@* Products.cshtml — ส่วนหน้าตา *@
@page
@model ProductsModel

<h1>รายการสินค้า</h1>
<ul>
@foreach (var product in Model.Products)

สังเกตว่าทุกอย่างในไฟล์ .cshtml.cs คือ C# ที่รู้จักมาแล้วจาก Part B ทั้งหมด (class, List, foreach) ส่วนใหม่มีแค่ 2 อย่าง:

@model ProductsModel — บอกว่าไฟล์ .cshtml นี้ผูกกับไฟล์ C# ชื่อ ProductsModel ทำให้เรียก Model.Products ในหน้า HTML ได้

OnGet() — method พิเศษที่ ASP.NET Core เรียกให้อัตโนมัติทุกครั้งที่มีคนเปิดหน้านี้

ลองทำ: เพิ่มสินค้าชิ้นที่ 3 ใน OnGet() แล้วรีเฟรชหน้าเว็บ ดูว่า list ที่แสดงมีครบ 3 ชิ้นไหม (ต้องสร้าง class Product ไว้ก่อนตามหัวข้อ 9 ด้วย)
16รับข้อมูลจากผู้ใช้ (ฟอร์ม)

ตอนนี้ข้อมูลสินค้ายัง hardcode ไว้ในโค้ด ขั้นถัดไปคือให้ผู้ใช้กรอกข้อมูลผ่านฟอร์มแล้วส่งเข้ามาได้จริง

@* Create.cshtml *@
@page
@model CreateModel

<form method="post">
    <label>ชื่อสินค้า</label>
    <input asp-for="NewProduct.Name" />

    <label>ราคา</label>
    <input asp-for="NewProduct.Price" />

    <button type="submit">บันทึก</button>
</form>
// Create.cshtml.cs
public class CreateModel : PageModel
{
    [BindProperty]
    public Product NewProduct { get; set; } = new();

    public void OnPost()
    {
        // ตอนนี้ NewProduct.Name และ NewProduct.Price
        // มีค่าที่ผู้ใช้กรอกมาแล้วโดยอัตโนมัติ
        Console.WriteLine("ได้รับสินค้า: " + NewProduct.Name);
    }
}

asp-for="NewProduct.Name" คือการบอกว่า input ช่องนี้ผูกกับ property ชื่อ Name ของ NewProduct โดยอัตโนมัติ ไม่ต้องเขียนโค้ดดึงค่าจากฟอร์มเอง ส่วน [BindProperty] บอกว่า property นี้จะรับค่าจากฟอร์มที่ submit เข้ามาให้เองอัตโนมัติเช่นกัน

OnPost() ต่างจาก OnGet() ในหัวข้อ 15 ตรงที่ OnGet ทำงานตอน "เปิดหน้า" ส่วน OnPost ทำงานตอน "กดปุ่ม submit ฟอร์ม"

ลองทำ: ลองกรอกฟอร์มแล้วกด submit เปิด terminal ดูว่าข้อความ "ได้รับสินค้า: ..." ปรากฏขึ้นมาพร้อมชื่อที่กรอกไปจริงไหม
17เก็บข้อมูลจริงด้วยฐานข้อมูล

ตอนนี้ข้อมูลที่กรอกในหัวข้อ 16 ยังหายไปทันทีที่ปิดโปรแกรม เพราะเก็บไว้แค่ในหน่วยความจำชั่วคราว ถ้าอยากให้ข้อมูลอยู่ถาวร ต้องเก็บลงฐานข้อมูล เครื่องมือที่ช่วยให้ C# คุยกับฐานข้อมูลได้ง่ายขึ้นเรียกว่า Entity Framework Core (EF Core)

ติดตั้ง EF Core เพิ่ม (ใช้ SQLite ก่อนเพราะติดตั้งง่ายที่สุดสำหรับฝึก):

dotnet add package Microsoft.EntityFrameworkCore.Sqlite
dotnet add package Microsoft.EntityFrameworkCore.Design

สร้างไฟล์ตัวแทนการเชื่อมต่อฐานข้อมูล:

public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }
    public DbSet<Product> Products => Set<Product>();
}

DbSet<Product> Products คือการบอกว่า "มี table ชื่อ Products เก็บข้อมูลตาม class Product ที่สร้างไว้แล้วในหัวข้อ 9" AppDbContext คือจุดเดียวที่ใช้คุยกับฐานข้อมูลทั้งหมด

ทำไมยังไม่ลงรายละเอียดการตั้งค่าเต็มรูปแบบ: การตั้งค่าเชื่อมต่อฐานข้อมูลมีรายละเอียดปลีกย่อยเยอะ (connection string, migration) หัวข้อนี้แค่ให้เห็นภาพว่า AppDbContext ทำหน้าที่อะไร ส่วนขั้นตอนเชื่อมต่อ และสร้าง table จริงจะฝึกละเอียดในหัวข้อ 18 ที่รวมทุกอย่างเป็นโปรเจกต์เดียว
18CRUD ครบวงจร — รวมทุกอย่างเข้าด้วยกัน

หัวข้อนี้คือการเอาความรู้ทั้งหมดจากหัวข้อ 13-17 มาประกอบเป็นเว็บแอปที่ใช้งานได้จริง มีฟังก์ชันครบ 4 อย่าง เรียกรวมกันว่า CRUD:

Create — สร้างข้อมูลใหม่ (ฟอร์มจากหัวข้อ 16)

Read — อ่าน/แสดงข้อมูล (list จากหัวข้อ 15)

Update — แก้ไขข้อมูลเดิม (คล้ายฟอร์ม Create แต่โหลดค่าเดิมมาแสดงก่อน)

Delete — ลบข้อมูล

สร้าง migration เพื่อให้ EF Core สร้าง table จริงในฐานข้อมูลตามที่นิยามไว้ในหัวข้อ 17:

dotnet tool install --global dotnet-ef
dotnet ef migrations add InitialCreate
dotnet ef database update

ตัวอย่างปุ่มลบใน list (Read) ที่เชื่อมกับฐานข้อมูลจริง:

public class ProductsModel : PageModel
{
    private readonly AppDbContext _db;
    public ProductsModel(AppDbContext db) { _db = db; }

    public List<Product> Products { get; set; } = new();

    public async Task OnGetAsync()
    {
        Products = await _db.Products.ToListAsync();
    }

    public async Task OnPostDeleteAsync(int id)
    {
        var product = await _db.Products.FindAsync(id);
        if (product is not null)
        {
            _db.Products.Remove(product);
            await _db.SaveChangesAsync();
        }
    }
}
คำว่า async/await ที่เพิ่งเห็น: เป็นวิธีบอกว่า "ระหว่างรอฐานข้อมูลตอบกลับ ให้เว็บแอปไปรับ request อื่นก่อนได้ ไม่ต้องหยุดรอเฉยๆ" เป็น pattern มาตรฐานที่ใช้ทุกครั้งที่คุยกับฐานข้อมูลใน ASP.NET Core แค่จำไว้ก่อนว่าต้องมีคำนี้คู่กับ method ที่เกี่ยวกับฐานข้อมูลเสมอ
ลองทำ: ทำให้โปรเจกต์ฝึกมีครบ 4 อย่าง (Create, Read, Update, Delete) ผ่านหน้าเว็บจริง ต่อกับฐานข้อมูล SQLite ที่ตั้งไว้ ใช้เวลาหัวข้อนี้นานกว่าหัวข้ออื่น เพราะเป็นการรวมทุกอย่างเข้าด้วยกัน
19Blazor เบื้องต้น (ถ้าอยากได้ UI โต้ตอบเร็วขึ้น)

เว็บแอปที่ทำมาถึงตอนนี้ ทุกครั้งที่กดปุ่มหรือ submit ฟอร์ม หน้าเว็บจะ reload ใหม่ทั้งหน้า ถ้าอยากได้ UI ที่อัพเดททันทีโดยไม่ reload (เช่น พิมพ์ค้นหาแล้ว list กรองทันที) ใช้ Blazor แทน ยังเป็น C# เหมือนเดิมทุกอย่าง แค่เขียนในไฟล์รูปแบบใหม่ (.razor)

@* ProductSearch.razor *@
<input @bind="keyword" @bind:event="oninput" />

<ul>
@foreach (var p in FilteredProducts)
{
    <li>@p.Name</li>
}
</ul>

@code {
    private string keyword = "";
    private List<Product> products = new()
    {
        new Product { Name = "แอปเปิ้ล" },
        new Product { Name = "กล้วย" },
    };

    private List<Product> FilteredProducts =>
        products.Where(p => p.Name.Contains(keyword)).ToList();
}

@bind="keyword" คือการผูกค่าในช่อง input เข้ากับตัวแปร keyword โดยอัตโนมัติ พิมพ์อะไรลงไป ตัวแปรก็เปลี่ยนทันที ทำให้ FilteredProducts คำนวณใหม่และหน้าจอกรองผลลัพธ์ให้เอง โดยไม่ต้อง reload หน้าเลย

ถือว่าครบพื้นฐานแล้ว: ถ้าทำมาถึงหัวข้อนี้ได้ แปลว่าเข้าใจตั้งแต่ "โปรแกรมคืออะไร" ไปจนถึง สร้างเว็บแอปเต็มรูปแบบด้วย ASP.NET Core แล้ว ขั้นต่อไปคือลองทำโปรเจกต์ฝึกของตัวเองที่ไม่ใช่ตัวอย่างในเอกสารนี้ เพื่อดูว่าจำและประยุกต์ใช้ได้จริงแค่ไหน
ทุกหัวข้อควรลงมือทำ "ลองทำ" ที่ท้ายหัวข้อก่อนไปหัวข้อถัดไปเสมอ แทนที่จะอ่านผ่านอย่างเดียว ถ้าติดขัดตรงไหน กลับไปอ่านหัวข้อก่อนหน้าซ้ำได้ ไม่ต้องรีบ เพราะแต่ละหัวข้อต่อยอดจากหัวข้อก่อนหน้าเสมอ
