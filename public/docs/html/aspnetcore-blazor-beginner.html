01Blazor คืออะไร

ถ้าเคยเรียน Razor Pages มาก่อน (หน้าเว็บที่กด submit แล้ว reload ทั้งหน้าใหม่ทุกครั้ง) Blazor คือ อีกวิธีสร้างหน้าเว็บด้วย C# เหมือนกัน แต่ทำให้หน้าเว็บ "อัพเดทเฉพาะจุด" ได้โดยไม่ต้อง reload ทั้งหน้า

เปรียบเทียบ: Razor Pages เหมือนถ่ายรูปหน้าจอใหม่ทุกครั้งที่มีอะไรเปลี่ยน (ถ่ายรูปทั้งห้องใหม่ แม้แค่ย้ายแจกันดอกไม้) ส่วน Blazor เหมือนมีคนคอยเดินเข้าไปขยับแค่แจกันดอกไม้อันเดียวในห้องจริง โดยไม่ต้องรื้อทั้งห้องใหม่ ผลลัพธ์ที่เห็นเหมือนกัน แต่ Blazor เร็วกว่าและรู้สึกลื่นไหลกว่า

ถ้าไม่เคยเรียน Razor Pages มาก่อนเลยก็ไม่เป็นไร ไฟล์นี้อธิบาย Blazor แบบไม่อิงกับ Razor Pages อยู่แล้ว แค่รู้ไว้เฉยๆ ว่าทั้งสองแบบใช้ C# เหมือนกัน ต่างกันแค่วิธีอัพเดทหน้าจอ

02Component คืออะไร

Blazor สร้างหน้าเว็บจากชิ้นส่วนเล็กๆ เรียกว่า component แต่ละ component คือ 1 ไฟล์นามสกุล .razor ที่รวม "หน้าตา" (HTML) กับ "พฤติกรรม" (C#) ไว้ในไฟล์เดียวกัน

เปรียบเทียบ: เหมือนตัวต่อเลโก้ แต่ละชิ้น (component) มีรูปร่างและหน้าที่ของตัวเอง เอามาประกอบกันเป็นหน้าเว็บทั้งหน้าได้ เช่น หน้าเดียวอาจประกอบด้วย component เมนู + component การ์ดสินค้า + component ปุ่มกด ซึ่งแต่ละอันแยกไฟล์กันชัดเจน

ตัวอย่างหน้าตาไฟล์ .razor (ยังไม่ต้องเข้าใจทุกบรรทัดตอนนี้ แค่ดูภาพรวม):

<h1>สวัสดี</h1>
<p>วันนี้คือ @DateTime.Now</p>

@code {
    // ส่วนนี้คือ C# ธรรมดา
}

ส่วนบน (HTML) เรียกว่า "markup" ส่วนล่างในวงเล็บ @code { } คือ C# ล้วนๆ ที่เคยเรียนมาแล้ว เครื่องหมาย @ คือตัวบอกว่า "ต่อไปนี้คือ C# ไม่ใช่ข้อความธรรมดา"

03สร้างโปรเจกต์แรก

เปิด terminal ใน VS Code (Ctrl+`) แล้วพิมพ์ทีละบรรทัด:

dotnet new blazor -o MyFirstBlazor
cd MyFirstBlazor
code .

dotnet new blazor -o MyFirstBlazor คือคำสั่งสร้างโปรเจกต์ Blazor เปล่าๆ (มีตัวอย่างมาให้) ใส่ไว้ในโฟลเดอร์ชื่อ MyFirstBlazor ส่วน code . คือเปิดโฟลเดอร์นั้นด้วย VS Code

ลองรันดู:

dotnet watch run

เปิด URL ที่ terminal แสดง ควรเห็นหน้าเว็บตัวอย่างขึ้นมา (มีเมนู Home, Counter, Weather) นี่คือ Blazor app แรกของคุณที่รันสำเร็จแล้ว

ลองทำ: คลิกเมนู "Counter" ในหน้าเว็บที่เปิดอยู่ ลองกดปุ่ม "Click me" สังเกตว่าตัวเลขเพิ่มขึ้นโดยหน้าเว็บไม่กระพริบหรือโหลดใหม่เลย — นี่คือสิ่งที่ analogy ในหัวข้อ 1 พูดถึง (อัพเดทเฉพาะจุด)
04แก้ไฟล์แรก เห็นผลจริง

เปิดไฟล์ Components/Pages/Home.razor (อยู่ในโฟลเดอร์ Components/Pages/) จะเห็นโค้ดสั้นๆ ประมาณนี้:

@page "/"

<PageTitle>Home</PageTitle>

<h1>Hello, world!</h1>

Welcome to your new app.

@page "/" คือการบอกว่า component นี้เข้าถึงได้ผ่าน URL หน้าแรก (เทียบเท่า @page ของ Razor Pages ที่อาจเคยเห็นมาก่อน)

ลองทำ: แก้ข้อความ "Hello, world!" เป็นชื่อตัวเอง บันทึกไฟล์ (Ctrl+S) แล้วดูหน้าเว็บที่เปิดค้างไว้ ควรเปลี่ยนให้อัตโนมัติภายใน 1-2 วินาที (เพราะรันด้วย dotnet watch)
05ตัวแปรใน Component (State)

component เก็บ "ค่าที่จำไว้" ของตัวเองได้ เรียกว่า state ก็คือตัวแปร C# ธรรมดาที่ประกาศไว้ใน @code { } นั่นเอง

<h1>สวัสดี @name</h1>

@code {
    private string name = "Somchai";
}
เปรียบเทียบ: state เหมือนกระดานไวท์บอร์ดเล็กๆ ที่ component แต่ละอันมีของตัวเอง เขียนอะไรไว้บนกระดานนี้ ก็แสดงผลบนหน้าจอตามนั้น พอลบแล้วเขียนใหม่ หน้าจอก็เปลี่ยนตาม

สังเกตว่า @name ในส่วน HTML คือการ "อ่านค่า" ตัวแปร name มาแสดง ใช้เครื่องหมาย @ นำหน้าเสมอเวลาจะแทรกค่า C# ลงในส่วน HTML

ลองทำ: เพิ่มตัวแปร age (ชนิด int) ใน @code แล้วแสดงผลว่า "อายุ X ปี" ต่อจากชื่อในหัวข้อนี้
ดูเฉลย
<h1>สวัสดี @name อายุ @age ปี</h1>

@code {
    private string name = "Somchai";
    private int age = 25;
}
06รับคลิกจากผู้ใช้ (Event)

ให้ component ตอบสนองเมื่อผู้ใช้คลิกปุ่ม ใช้ @onclick ผูกกับ method ที่เขียนไว้

<p>กดแล้ว @count ครั้ง</p>
<button @onclick="IncreaseCount">กดที่นี่</button>

@code {
    private int count = 0;

    private void IncreaseCount()
    {
        count++;
    }
}

พอกดปุ่ม Blazor จะเรียก IncreaseCount() ให้อัตโนมัติ แล้ว "วาดหน้าจอใหม่เอง" ทันทีที่ state เปลี่ยน ไม่ต้องเขียนโค้ดสั่งวาดใหม่เอง — เป็นเสน่ห์หลักของ Blazor ที่ต่างจากการเขียน JavaScript ธรรมดาที่ต้องสั่งอัพเดท HTML เองทุกจุด

ลองทำ: เพิ่มปุ่มที่สองชื่อ "รีเซ็ต" กดแล้วให้ count กลับเป็น 0
ดูเฉลย
<button @onclick="ResetCount">รีเซ็ต</button>

@code {
    private void ResetCount()
    {
        count = 0;
    }
}
07ผูกค่าสองทาง (@bind)

ถ้าอยากให้ผู้ใช้พิมพ์ข้อความแล้วตัวแปรเปลี่ยนตามทันที (ไม่ต้องกดปุ่ม) ใช้ @bind

<input @bind="username" @bind:event="oninput" />
<p>คุณพิมพ์ว่า: @username</p>

@code {
    private string username = "";
}
เปรียบเทียบ: ปกติ (หัวข้อ 6) เหมือนกดปุ่มส่งจดหมายถึงจะรู้ผล แต่ @bind เหมือนคุยโทรศัพท์สด พิมพ์อะไรในช่อง input ตัวแปร username ก็เปลี่ยนตามทันที ไม่ต้องรอกดอะไรเลย

@bind:event="oninput" คือการบอกว่า "อัพเดททันทีที่พิมพ์" ถ้าไม่ใส่ส่วนนี้ ค่าเริ่มต้น ของ @bind จะอัพเดทตอน "คลิกออกจากช่อง input" แทน (คือพิมพ์เสร็จแล้วกดที่อื่นถึงจะอัพเดท)

ลองทำ: ลองเอา @bind:event="oninput" ออก แล้วสังเกตความต่าง ว่าข้อความด้านล่างอัพเดทช้าลงยังไง (ต้องคลิกออกจากช่องก่อนถึงจะเห็นค่าใหม่)
08ทำไมต้อง @rendermode

ถ้าลองสร้างหน้าใหม่เอง (ไม่ใช่ Home.razor ที่มีมาให้ตั้งแต่ต้น) แล้วโค้ดจากหัวข้อ 5-7 ไม่ทำงานเลย (กดปุ่มไม่ตอบสนอง พิมพ์อะไรก็ไม่อัพเดท) ไม่ใช่เพราะเขียนผิด แต่เพราะยังไม่ได้เปิด "interactivity"

เปรียบเทียบ: ค่าเริ่มต้นของหน้าใหม่เหมือนรูปถ่ายหน้าเว็บ (ดูได้ แต่กดอะไรไม่ได้เลย) ต้องบอก Blazor ชัดเจนว่า "หน้านี้ขอเป็นแบบโต้ตอบได้จริง" ก่อน ถึงจะกดปุ่มหรือพิมพ์อะไรแล้วเห็นผล

วิธีเปิด ใส่บรรทัดนี้ไว้ใกล้บนสุดของไฟล์ .razor ต่อจาก @page:

@page "/my-new-page"
@rendermode InteractiveServer

ทำไม Home.razor เดิมถึงทำงานได้โดยไม่ต้องใส่เอง เพราะ template ตั้งค่าไว้ให้ "ทั้งแอป" interactive อัตโนมัติตั้งแต่สร้างโปรเจกต์แล้ว (ผ่านไฟล์ App.razor) แต่ถ้าสร้างหน้าเองใหม่ๆ บางครั้งต้องประกาศ ซ้ำเฉพาะไฟล์ ถ้าเจอปัญหา "กดอะไรไม่ได้เลย" ให้นึกถึงหัวข้อนี้เป็นอันดับแรก

09ส่งค่าจากแม่สู่ลูก (Parameter)

ถ้าอยากใช้ component เดิมซ้ำหลายครั้ง แต่ใส่ข้อมูลต่างกันแต่ละครั้ง ใช้ Parameter

เปรียบเทียบ: เหมือนแม่พิมพ์ขนม พิมพ์เดียวใช้ซ้ำได้หลายชิ้น แต่ใส่แป้งคนละสีคนละรสได้ แม่พิมพ์คือ component ส่วนแป้งที่ใส่แต่ละครั้งคือ Parameter

สร้างไฟล์ใหม่: Components/Greeting.razor (component ลูก)

<h3>สวัสดี @Name</h3>

@code {
    [Parameter] public string Name { get; set; } = "";
}

เรียกใช้จาก Home.razor (component แม่):

<Greeting Name="Somchai" />
<Greeting Name="Somying" />

ผลลัพธ์คือได้ข้อความทักทาย 2 อัน ชื่อต่างกัน จาก component เดียวกัน [Parameter] คือคำที่บอกว่า "property นี้รับค่าจากข้างนอกได้" ชื่อ attribute ตอนเรียกใช้ (Name="...") ต้องตรงกับชื่อ property เป๊ะ

ลองทำ: เพิ่ม Parameter อีกตัวชื่อ Age (int) ใน Greeting.razor แล้วเรียกใช้พร้อมส่งอายุมาด้วย
ดูเฉลย
<h3>สวัสดี @Name อายุ @Age ปี</h3>

@code {
    [Parameter] public string Name { get; set; } = "";
    [Parameter] public int Age { get; set; }
}
เรียกใช้: <Greeting Name="Somchai" Age="25" />
10ส่งค่าจากลูกกลับแม่ (EventCallback)

หัวข้อ 9 คือส่งค่า "ลงไป" จากแม่สู่ลูก ตอนนี้จะทำกลับกัน — ให้ลูก "แจ้งข่าว" กลับไปหาแม่ เช่น ตอนมีคนกดปุ่มในลูก แล้วแม่อยากรู้

เปรียบเทียบ: เหมือนลูกโทรบอกแม่ว่า "หนูกดปุ่มแล้วนะ" แม่ฟังแล้วจะทำอะไรต่อก็ได้ ลูกแค่แจ้ง ไม่ได้สั่งว่าแม่ต้องทำอะไร

แก้ไฟล์: Components/Greeting.razor (เพิ่มปุ่มและ EventCallback)

<h3>สวัสดี @Name</h3>
<button @onclick="HandleClick">กดทักทายกลับ</button>

@code {
    [Parameter] public string Name { get; set; } = "";
    [Parameter] public EventCallback<string> OnGreet { get; set; }

    private async Task HandleClick()
    {
        await OnGreet.InvokeAsync(Name);
    }
}

แก้ไฟล์: Components/Pages/Home.razor (ฟังข่าวจากลูก)

<Greeting Name="Somchai" OnGreet="HandleGreeting" />
<p>@lastMessage</p>

@code {
    private string lastMessage = "";

    private void HandleGreeting(string name)
    {
        lastMessage = $"{name} กดทักทายกลับมาแล้ว!";
    }
}

EventCallback<string> คือ "ช่องทางแจ้งข่าว" ที่ส่งค่าเป็น string กลับไปได้ ส่วน OnGreet.InvokeAsync(Name) คือการ "โทรแจ้ง" จริงๆ พอแม่ (Home.razor) ผูก OnGreet="HandleGreeting" ไว้ ก็จะมี method นั้นถูกเรียกทุกครั้งที่ลูกแจ้งข่าวมา

11เชื่อมฐานข้อมูล

ทุกอย่างที่เรียนมาเก็บข้อมูลแค่ชั่วคราว (ปิดเบราว์เซอร์แล้วหาย) ถ้าอยากเก็บถาวรต้องต่อฐานข้อมูล ด้วย EF Core (เครื่องมือเดียวกับที่ Razor Pages ใช้)

dotnet add package Microsoft.EntityFrameworkCore.Sqlite
dotnet add package Microsoft.EntityFrameworkCore.Design

สร้างไฟล์ใหม่: Models/Product.cs

namespace MyFirstBlazor.Models;

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public decimal Price { get; set; }
}

สร้างไฟล์ใหม่: Data/AppDbContext.cs

using Microsoft.EntityFrameworkCore;
using MyFirstBlazor.Models;

namespace MyFirstBlazor.Data;

public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }
    public DbSet<Product> Products => Set<Product>();
}

แก้ไฟล์: Program.cs (เพิ่ม 2 บรรทัดก่อน builder.Build())

using MyFirstBlazor.Data;

builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlite("Data Source=app.db"));
dotnet tool install --global dotnet-ef
dotnet ef migrations add InitialCreate
dotnet ef database update

ตอนนี้ในหน้า .razor ไหนก็ตาม เรียกใช้ฐานข้อมูลได้ด้วย @inject AppDbContext Db ไว้บนสุดของไฟล์ แล้วเรียก Db.Products.ToListAsync() ได้เลย

12ฟอร์มด้วย EditForm

Blazor มี component ฟอร์มพิเศษชื่อ EditForm ที่ตรวจสอบข้อมูลให้อัตโนมัติ

@page "/add-product"
@rendermode InteractiveServer
@inject AppDbContext Db
@inject NavigationManager Nav

<EditForm Model="newProduct" OnValidSubmit="SaveAsync">
    <InputText @bind-Value="newProduct.Name" />
    <InputNumber @bind-Value="newProduct.Price" />
    <button type="submit">บันทึก</button>
</EditForm>

@code {
    private Product newProduct = new();

    private async Task SaveAsync()
    {
        Db.Products.Add(newProduct);
        await Db.SaveChangesAsync();
        Nav.NavigateTo("/");
    }
}

OnValidSubmit ทำงานก็ต่อเมื่อข้อมูลในฟอร์มถูกต้องเท่านั้น (ยังไม่ได้ใส่กฎ validation ในตัวอย่างนี้ แต่ EditForm รองรับ [Required]/[Range] แบบเดียวกับที่เคยเรียนได้ทันทีถ้าเพิ่มเข้าไปใน class Product)

NavigationManager คือตัวเปลี่ยนหน้าของ Blazor Nav.NavigateTo("/") คือ "พาไปหน้าแรก" หลังบันทึกเสร็จ

13รวมเป็น CRUD เล็กๆ

ตอนนี้รวมทุกอย่างจากหัวข้อ 11-12 เข้าด้วยกัน แก้ Home.razor ให้แสดงรายการสินค้าจริง พร้อมปุ่มลบ:

@page "/"
@rendermode InteractiveServer
@inject AppDbContext Db

<h1>สินค้าทั้งหมด</h1>
<a href="/add-product">+ เพิ่มสินค้า</a>

<ul>
@foreach (var p in products)
{
    <li>
        @p.Name — @p.Price บาท
        <button @onclick="() => DeleteAsync(p.Id)">ลบ</button>
    </li>
}
</ul>

@code {
    private List<Product> products = new();

    protected override async Task OnInitializedAsync()
    {
        products = await Db.Products.ToListAsync();
    }

    private async Task DeleteAsync(int id)
    {
        var product = await Db.Products.FindAsync(id);
        if (product is not null)
        {
            Db.Products.Remove(product);
            await Db.SaveChangesAsync();
            products = await Db.Products.ToListAsync();
        }
    }
}

OnInitializedAsync คือ method พิเศษที่ Blazor เรียกให้อัตโนมัติตอน component เพิ่งถูกสร้างขึ้นมาครั้งแรก (เหมือน "ทำสิ่งนี้ทันทีที่หน้าเปิด")

ลองทำ: ทดสอบเพิ่มสินค้าผ่าน /add-product แล้วกลับมาหน้าแรก ดูว่าแสดงครบไหม ลองกดปุ่มลบดูว่าหายไปจากหน้าจอทันทีโดยไม่ reload หน้าเลยหรือเปล่า
เช็คลิสต์
ถ้าเพิ่มสินค้าแล้วไม่เห็นในหน้าแรก เช็คว่า Nav.NavigateTo("/") ทำงานจริงไหม (URL เปลี่ยนกลับมาหน้าแรกไหม) ถ้ากดลบแล้วไม่มีอะไรเกิดขึ้นเลย ให้เช็คว่าใส่ @rendermode InteractiveServer ไว้ที่ Home.razor แล้วหรือยัง (ตามหัวข้อ 8) เป็นสาเหตุอันดับหนึ่งที่ทำให้ปุ่มกดไม่ได้ผล
