งานของ session นี้คือ PLAN.md Phase 2 ข้อ 1 เท่านั้น: "แทน LINE
Notify ด้วย Apps Script pushMessage()"

อ่าน CLAUDE.md, PLAN.md, DESIGN.md ก่อนเริ่ม โดยเฉพาะ Decision Log
ข้อ 2 ใน DESIGN.md

1. เพิ่มฟังก์ชัน pushMessage(userId, text) ใน
   backend/apps-script/Code.gs ยิงไปที่
   https://api.line.me/v2/bot/message/push ใช้ Channel Access Token
   จาก Script Properties (ตัวเดียวกับที่ replyMessage() ใช้อยู่แล้ว
   จาก Phase 1)

2. เก็บ line_user_id ของผู้ทักบอทครั้งแรก ไว้ใน Script Properties —
   ดักจาก requestObj.source.userId ใน doPost() ตอนมี event เข้ามา
   ถ้ายังไม่เคยเก็บไว้ก็บันทึกทันที

3. ยังไม่ต้องเรียก pushMessage() จากที่ไหน แค่เตรียมฟังก์ชันให้พร้อม
   ใช้ก่อน (เป็นข้อถัดไป)

ห้ามแก้ logic อื่นใน Code.gs นอกจากนี้

เมื่อเสร็จ: ติ๊ก PLAN.md ข้อนี้ ทดสอบเรียก pushMessage() ตรง ๆ ครั้ง
เดียวว่าข้อความไปถึงจริง แล้วรอผมยืนยันก่อนไปข้อถัดไป
คิวถัดไป2.2 — ต่อ pushMessage() เข้ากล้อง/แจ้งเตือน 
งานของ session นี้คือ PLAN.md Phase 2 ข้อ 2 เท่านั้น: "เอา
pushMessage() มาต่อกับส่วนกล้อง/แจ้งเตือนที่ถูก stub ไว้"

1. เปิด firmware/src/camera.cpp และ control.cpp หาจุดที่เคย
   Serial.println() แทน LINE.notify() ไว้ตอน Phase 0

2. ฝั่งเฟิร์มแวร์: จุดที่ต้องแจ้งเตือน (เช่น น้ำในถังหมด) ให้ยิง
   HTTP ไปหา Apps Script endpoint ใหม่ (เพิ่ม status=notify ใน
   doGet/doPost) ส่ง event type ไป แทนที่จะยิง LINE โดยตรงจากเฟิร์มแวร์
   เอง (เฟิร์มแวร์ไม่ควรถือ LINE token)

3. ฝั่ง Code.gs: รับ status=notify แล้วเรียก pushMessage() ที่ทำไว้
   ข้อ 2.1 ส่งข้อความไปหา line_user_id ที่เก็บไว้ — เฉพาะ event สำคัญ
   เท่านั้น (น้ำหมด/ค่าผิดปกติ) ไม่ใช่ทุกรอบ poll เพื่อไม่ให้เกิน
   โควตาฟรี ~500 ข้อความ/เดือน

ห้ามเรียก LINE.notify()/TridentTD กลับมาใช้เด็ดขาด

เมื่อเสร็จ: ติ๊ก PLAN.md ข้อนี้ ทดสอบผ่าน Wokwi จำลอง event น้ำหมด
เช็คว่าได้ข้อความ LINE จริง สรุปผลแล้วรอผมยืนยันก่อนไปข้อถัดไป
รอคิว2.3 — Mobile App ด้วย Flutter

เปลี่ยนจากแผนเดิม (PWA/React Native) เป็นแอป Flutter จริง — cross-platform iOS + Android

งานของ session นี้คือ PLAN.md Phase 2 ข้อ 3 เท่านั้น: "ทำแอปมือถือ
ด้วย Flutter"

อ่าน DESIGN.md หัวข้อ "Mobile App — Flutter" ก่อนเริ่ม โดยเฉพาะ
Decision Log ข้อ 5

1. สร้างโปรเจ็ค Flutter ใหม่ในโฟลเดอร์ mobile-app/ ที่ root repo
   (แยกจาก firmware/ backend/) ด้วย `flutter create`

2. ออกแบบโครงแอปแบบ 3 แท็บ ใช้ BottomNavigationBar:
   - แท็บสถานะ: การ์ดแสดงค่าเซนเซอร์ล่าสุด + ปุ่มควบคุม manual
     (เรียก doGet(status=get) ของ Apps Script Web App เดิม)
   - แท็บกราฟ: ใช้ package fl_chart แสดงความชื้นดิน/อุณหภูมิย้อนหลัง
     (ถ้ายังไม่มี endpoint status=log ใน Code.gs ให้บอกผมก่อน เป็น
     คนละงานที่ต้องแก้ backend)
   - แท็บตั้งค่า: เลือกโหมดปลูก (เขียนกลับไปที่ชีต control ผ่าน
     Apps Script)

3. ใช้ package http เรียก Apps Script Web App เป็น JSON API ตรง ๆ
   (GET ธรรมดา ไม่ติดปัญหา CORS แบบเว็บ browser)

4. ยังไม่ต้องทำ push notification (Firebase Cloud Messaging) ในขั้นนี้
   — เป็นข้อถัดไปถ้าต้องการ เน้นให้แอปอ่าน/เขียนสถานะได้ถูกต้องก่อน

5. ทดสอบบน Android emulator หรือมือถือจริงผ่าน USB debugging (ไม่มี
   iOS ให้ทดสอบก็ไม่เป็นไร โฟกัส Android ก่อน)

ห้ามใช้ Firebase Realtime Database ในขั้นนี้ (ตัดสินใจไม่ใช้แล้ว ดู
Decision Log ข้อ 1) — เรียก Apps Script เป็น backend เดียวเท่านั้น

เมื่อเสร็จ: ติ๊ก PLAN.md ข้อนี้ ส่งสกรีนช็อตหรือวิดีโอสั้น ๆ มาให้ผมดู
