GETTING-STARTED / aspnetcore-setup-to-run / rev.1

ASP.NET Core — ตั้งแต่เริ่มจนรันสำเร็จ

ไล่ทีละขั้นตั้งแต่เช็คเครื่องมือที่ต้องมี ไปจนถึงเห็นเว็บแอปแรกทำงานจริงในเบราว์เซอร์ ทุกขั้นบอกคำสั่งที่ต้องพิมพ์ และผลลัพธ์ที่ควรเห็น เพื่อให้รู้ทันทีว่าทำถูกหรือทำพลาดตรงไหน

ขอบเขตเอกสารนี้
เฉพาะ setup และรันโปรเจกต์แรกให้สำเร็จเท่านั้น ยังไม่สอนเขียนหน้าเว็บหรือ logic ใดๆ
ใช้เวลา
ประมาณ 20-30 นาที (ถ้าเครื่องมือยังไม่เคยติดตั้งมาก่อนเลย)
สิ่งที่ต้องมี
เครื่องคอมพิวเตอร์ที่ต่ออินเทอร์เน็ตได้ และ VS Code ติดตั้งไว้แล้ว
ขั้น 1 — เช็ค SDK ขั้น 2 — ติดตั้ง extension ขั้น 3 — สร้างโปรเจกต์ ขั้น 4 — สำรวจไฟล์ ขั้น 5 — รันจริง ขั้น 6 — ดูผลใน browser ขั้น 7 — แก้โค้ดแล้วเห็นผลทันที ขั้น 8 — หยุดการรัน แก้ปัญหาที่เจอบ่อย
1เช็คว่า .NET SDK ติดตั้งอยู่หรือยัง

เปิด VS Code แล้วเปิด terminal ข้างในโปรแกรม (กด Ctrl+` — ปุ่มเครื่องหมายเน้นเสียงข้างเลข 1 บนคีย์บอร์ด ไม่ใช่เครื่องหมายคำพูด) พิมพ์คำสั่งนี้แล้วกด Enter:

dotnet --version
ควรเห็น
ตัวเลขเวอร์ชัน เช่น 8.0.100 หรือ 9.0.200 (ขึ้นต้นด้วย 8 หรือมากกว่า)
ถ้าเจอแบบนี้แทน
ข้อความ 'dotnet' is not recognized หรือ command not found แปลว่ายังไม่ได้ติดตั้ง .NET SDK ให้ไปที่ https://dotnet.microsoft.com/download เลือกเวอร์ชัน LTS (ตัวที่แนะนำสำหรับใช้งานทั่วไป) ดาวน์โหลดแล้วติดตั้งตามขั้นตอนของโปรแกรมติดตั้งปกติ (กด Next ไปเรื่อยๆ) เสร็จแล้ว ปิด terminal เดิมแล้วเปิดใหม่ ก่อนลองพิมพ์คำสั่งนี้อีกครั้ง
2ติดตั้ง extension สำหรับเขียน C#

คลิกไอคอน Extensions ทางแถบซ้ายของ VS Code (รูปสี่เหลี่ยมต่อกัน 4 ชิ้น) หรือกด Ctrl+Shift+X แล้วพิมพ์ค้นหา:

C# Dev Kit

เลือกตัวที่ publisher เป็น Microsoft (มักจะขึ้นเป็นอันดับแรก) กด Install แล้วรอจนติดตั้งเสร็จ extension นี้จะติดตั้ง C# ตัวพื้นฐานและ .NET Install Tool มาให้อัตโนมัติด้วย

ควรเห็น
ปุ่ม Install เปลี่ยนเป็นไอคอนฟันเฟือง (แปลว่าติดตั้งเสร็จแล้ว) และถ้าเปิดไฟล์ .cs ใดๆ จะมีสีไฮไลต์ของโค้ดขึ้นมา

ติดตั้งเสร็จแล้ว ปิด VS Code แล้วเปิดใหม่ 1 ครั้ง เพื่อให้ extension โหลดค่าทั้งหมดสมบูรณ์

3สร้างโปรเจกต์เว็บแอปแรก

เลือกตำแหน่งที่จะเก็บงานฝึก (เช่น Desktop หรือ Documents) เปิด terminal ใน VS Code แล้วพิมพ์ทีละบรรทัด:

cd Desktop
mkdir learn-aspnetcore
cd learn-aspnetcore
dotnet new webapp -o FirstWebApp

อธิบายทีละคำสั่ง:

cd Desktop — เข้าไปในโฟลเดอร์ Desktop (เปลี่ยนเป็นโฟลเดอร์อื่นที่ต้องการได้)

mkdir learn-aspnetcore — สร้างโฟลเดอร์ใหม่ชื่อ learn-aspnetcore สำหรับเก็บงานฝึกทั้งหมด

cd learn-aspnetcore — เข้าไปในโฟลเดอร์ที่เพิ่งสร้าง

dotnet new webapp -o FirstWebApp — สั่งให้ .NET สร้างโปรเจกต์เว็บแอปเปล่าๆ (มีตัวอย่างมาให้พร้อม) ใส่ไว้ในโฟลเดอร์ชื่อ FirstWebApp

ควรเห็น
ข้อความประมาณ The template "ASP.NET Core Web App" was created successfully. และมีโฟลเดอร์ชื่อ FirstWebApp เกิดขึ้นมา
ถ้าเจอ error
ถ้าขึ้น error เกี่ยวกับ template ไม่รู้จัก มักเกิดจาก SDK ที่ติดตั้งเป็นเวอร์ชันเก่ามากหรือมีปัญหาตอนติดตั้ง ลองรัน dotnet --version ซ้ำตามขั้น 1 อีกครั้งเพื่อยืนยันว่า SDK ยังใช้งานได้ปกติ
4เปิดโปรเจกต์และสำรวจไฟล์คร่าวๆ

เข้าไปในโฟลเดอร์โปรเจกต์แล้วเปิดด้วย VS Code:

cd FirstWebApp
code .

VS Code จะเปิดหน้าต่างใหม่ขึ้นมา (หรือเปลี่ยนโฟลเดอร์ในหน้าต่างเดิม) แสดง sidebar ทางซ้ายมีไฟล์และโฟลเดอร์ หลายอย่าง ตอนนี้ยังไม่ต้องเข้าใจทุกไฟล์ ให้รู้จักแค่ 3 อย่างที่จะเจอบ่อยที่สุด:

โฟลเดอร์ Pages/ — เก็บหน้าเว็บทั้งหมด

ไฟล์ Program.cs — จุดเริ่มต้นของโปรแกรม

ไฟล์ FirstWebApp.csproj — ไฟล์ตั้งค่าโปรเจกต์ (บอกว่าใช้ .NET เวอร์ชันไหน)

ลองทำ: คลิกเปิดโฟลเดอร์ Pages/ ดูว่ามีไฟล์อะไรอยู่ข้างในบ้าง ไม่ต้องเปิดอ่านเนื้อหา แค่ดูชื่อไฟล์ผ่านๆ ก็พอสำหรับตอนนี้
5รันเว็บแอปจริง

กลับไปที่ terminal (ต้องอยู่ในโฟลเดอร์ FirstWebApp ถ้า path ใน terminal ไม่ตรง ให้พิมพ์ cd FirstWebApp ก่อน) แล้วพิมพ์:

dotnet run
ควรเห็น
ข้อความหลายบรรทัด บรรทัดสำคัญที่ต้องมองหาคือแบบนี้: 
Now listening on: http://localhost:5000
Now listening on: https://localhost:5001
ตัวเลข port (5000, 5001) อาจไม่ตรงเป๊ะทุกเครื่อง ให้จำ URL ที่ terminal แสดงไว้ในขั้นถัดไป

ตอนนี้ terminal จะ "ค้าง" อยู่แบบนั้น ไม่ขึ้น prompt ให้พิมพ์คำสั่งต่อ — นั่นคือพฤติกรรมปกติ แปลว่าเว็บแอปกำลังรันอยู่และรอรับ request ตลอดเวลา ไม่ใช่ error

6เปิดดูผลใน browser

เปิด browser (Chrome, Edge, อะไรก็ได้) แล้วพิมพ์ URL ที่เห็นจาก terminal ในขั้นก่อนหน้า เช่น:

http://localhost:5000
ควรเห็น
หน้าเว็บตัวอย่างที่มีข้อความต้อนรับประมาณ "Welcome" พร้อมเมนูด้านบน (Home, Privacy) — นี่คือเว็บแอป ASP.NET Core ตัวแรกที่รันสำเร็จจริงบนเครื่องคุณ
ถ้าเปิดแล้วขึ้น "This site can't be reached"
เช็คว่าพิมพ์ URL ตรงกับที่ terminal แสดงจริงไหม (บาง port อาจไม่ใช่ 5000) และเช็คว่า terminal ยังรันอยู่ (ยังไม่ได้กด Ctrl+C ปิดไปก่อน)
7ลองแก้โค้ดแล้วดูผลแบบสด

กลับไปที่ terminal กด Ctrl+C เพื่อหยุดการรันชั่วคราวก่อน แล้วพิมพ์คำสั่งใหม่แทน dotnet run:

dotnet watch run

คำสั่งนี้ทำงานเหมือน dotnet run ทุกอย่าง แต่เพิ่มความสามารถพิเศษคือ รีเฟรชหน้าเว็บให้อัตโนมัติทุกครั้งที่มีการแก้ไขไฟล์และบันทึก สะดวกมากตอนพัฒนาจริง ไม่ต้องกด Ctrl+C แล้วรันใหม่เองทุกครั้งที่แก้โค้ด

ลองเปิดไฟล์ Pages/Index.cshtml ใน VS Code หาข้อความที่แสดงอยู่บนหน้าเว็บ (เช่นคำว่า "Welcome") แก้เป็นข้อความอื่น แล้วกด Ctrl+S เพื่อบันทึก

ควรเห็น
กลับไปที่ browser ที่เปิดค้างไว้ หน้าเว็บจะรีเฟรชและแสดงข้อความใหม่ให้อัตโนมัติ โดยไม่ต้องกดรีเฟรชเอง (อาจใช้เวลา 1-2 วินาที)
ลองทำ: แก้ข้อความอีก 2-3 รอบ สังเกตว่าทุกครั้งที่บันทึกไฟล์ browser อัพเดทให้เองโดยไม่ต้องสลับกลับไปที่ terminal เลย
8หยุดการรันเมื่อเลิกใช้งาน

เมื่อเลิกฝึกในแต่ละครั้ง กลับไปที่ terminal ที่ยังรันค้างอยู่ แล้วกด:

Ctrl+C

terminal จะกลับมาพร้อมพิมพ์คำสั่งใหม่ได้ตามปกติ (สังเกตว่า prompt กลับมาแสดง) เว็บแอปจะหยุดทำงาน ถ้าเปิด browser ที่ URL เดิมอีกครั้งจะขึ้นว่าเชื่อมต่อไม่ได้ ซึ่งเป็นเรื่องปกติเพราะไม่มีอะไรรันอยู่แล้ว

ครั้งถัดไปที่อยากรันใหม่ แค่เปิด terminal ใน VS Code ที่โฟลเดอร์ FirstWebApp แล้วพิมพ์ dotnet watch run อีกครั้งได้เลย

!แก้ปัญหาที่เจอบ่อย
อาการวิธีแก้
dotnet: command not foundSDK ยังไม่ได้ติดตั้ง หรือติดตั้งแล้วแต่ยังไม่ได้ปิด-เปิด terminal ใหม่ ย้อนไปทำขั้น 1
รัน dotnet run แล้วค้างไม่ขึ้นอะไรเลยนานผิดปกติรอบแรกที่รันโปรเจกต์ ระบบต้อง restore package ก่อน อาจใช้เวลา 30 วินาที-1 นาที ถ้านานเกิน 3 นาทีค่อยลองตรวจสอบการเชื่อมต่ออินเทอร์เน็ต
เปิด URL แล้วเจอ "Your connection is not private" (https)เป็นเพราะ certificate สำหรับพัฒนา (development certificate) ยังไม่ได้รับความเชื่อถือจากเครื่อง ลองใช้ URL แบบ http (port 5000) แทน https (port 5001) ไปก่อนสำหรับการฝึก
แก้โค้ดแล้ว browser ไม่อัพเดทให้เองเช็คว่ารันด้วย dotnet watch run ไม่ใช่ dotnet run เฉยๆ (watch เท่านั้นที่มีระบบรีเฟรชอัตโนมัติ)
Port 5000 ถูกใช้งานอยู่แล้ว (address already in use)มักเกิดจากลืมปิด terminal ที่รันค้างไว้จากรอบก่อน ลองหา terminal เก่าแล้วกด Ctrl+C หรือปิดหน้าต่าง terminal นั้นทิ้งไปเลย
ถึงตรงนี้แปลว่าพร้อมแล้ว

เครื่องมือครบ โปรเจกต์รันได้จริง เห็นผลลัพธ์ใน browser และแก้โค้ดแล้วเห็นผลแบบสดได้แล้ว ขั้นต่อไปคือเริ่มเรียนเขียนหน้าเว็บจริงตามแผนการเรียนรู้ที่วางไว้

เอกสารนี้ครอบคลุมเฉพาะการเตรียมเครื่องมือและรันโปรเจกต์เปล่าให้สำเร็จ ยังไม่มีการเขียนโค้ดเนื้อหาใดๆ
