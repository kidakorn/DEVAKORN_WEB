.NET Desktop (WPF / MAUI) · Claude Code Subagents · Full Lifecycle

Phase Workflow สำหรับพัฒนา Solution ตั้งแต่ต้นจนจบ

แบ่งงานเป็น 10 phase ตามลำดับ ตั้งแต่ discovery จนถึง deploy/maintain ควบคุมด้วยไฟล์ PLAN.md เดียว และมอบหมายแต่ละช่วงให้ subagent 3 บทบาท: architect / implementer / reviewer

กติกาบังคับ

  1. ทุก task ใหม่ต้องเริ่มที่ PLAN.md — ถ้ายังไม่มี copy จาก PLAN.template.md
  2. ห้าม implementer เริ่มเขียนโค้ดจนกว่า Phase 1–2 จะถูก mark ว่า “อนุมัติแล้ว”
  3. จบแต่ละ phase ต้องอัปเดต checklist ใน PLAN.md ก่อนไป phase ถัดไป
  4. Phase 5 (Feature Implementation) เป็น loop — ทำทีละ feature จนครบ backlog ก่อนไป phase 6
  5. ยกเว้นได้เมื่อผู้ใช้พิมพ์ “ข้าม plan” ชัดเจน หรือเป็นงานอ่าน/อธิบายโค้ดอย่างเดียว

# มอบหมาย phase 1-2 ให้ architect
> ใช้ agent architect วางแผน phase 1 และ 2 สำหรับ solution "ระบบจัดการสต็อกสินค้า"

# มอบหมาย phase 3-5 ให้ implementer (ต้องมี plan อนุมัติแล้วก่อน)
> ใช้ agent implementer เริ่ม phase 3 แล้วตามด้วย feature backlog ข้อ 1 ใน PLAN.md

# มอบหมาย phase 6-7 ให้ reviewer
> ใช้ agent reviewer ตรวจ code ที่เพิ่ง merge, เขียน test และทำ hardening review

# มอบหมาย phase 9 ให้ implementer
> ใช้ agent implementer ทำ packaging phase 9 พร้อม release notes

implementer

ทำไมแยก Core / Data / UI

  • Core ไม่ reference WPF/MAUI เลย → เขียน unit test ได้เร็ว ไม่ต้อง mock UI
  • ถ้าอยากเพิ่มเวอร์ชัน MAUI จาก WPF เดิม แค่เพิ่ม MyApp.UI.Maui โดย Core/Data ใช้ซ้ำได้ทั้งหมด
  • Data แยกออกมาเผื่อเปลี่ยน ORM หรือ database ในอนาคตโดยไม่กระทบ business logic

โปรเจ็คเล็กมาก (tool ใช้ในทีมเดียว ไม่ซับซ้อน) ไม่ต้อง over-engineer — ยุบเหลือ single-project แบบ Models/ViewModels/Views/Services ในโปรเจ็คเดียวพอ

ใช้กับ IDE ไหนได้บ้าง

VS Code

รองรับผ่าน CLIextension panel มี bug

มี extension “Claude Code” อย่างเป็นทางการ ใช้ config เดียวกับ CLI (~/.claude/) แต่ตอนนี้ปุ่ม/panel เรียก subagent โดยตรงยังไม่รู้จัก custom agent ใน .claude/agents/ — ให้เปิด integrated terminal แล้วรัน claude ผ่าน CLI ซึ่งอ่านไฟล์ agent ได้ถูกต้องครบ

Antigravity (Google, VS Code fork)

รองรับผ่าน CLI

ติดตั้ง Claude Code extension ในนั้นได้เหมือน VS Code เพราะเป็น fork เดียวกัน และ ~/.claude/ config แชร์ข้ามสภาพแวดล้อม workflow ที่นิยม: ใช้ Gemini วางแผนคร่าวๆ แล้วสลับมา Claude Code (ผ่าน terminal) รัน subagent ตาม PLAN.md

สรุป: เปิด repo ใน editor ไหนก็ได้ตามถนัด แต่รัน Claude Code ผ่าน terminal/CLI เสมอ เพื่อให้ subagent ทำงานถูกต้องเต็มรูปแบบ
