ASP.NET Core — ตั้งแต่เริ่มจนรันสำเร็จ

ไล่ทีละขั้นตั้งแต่เช็คเครื่องมือที่ต้องมี ไปจนถึงเห็นเว็บแอปแรกทำงานจริงในเบราว์เซอร์ ทุกขั้นบอกคำสั่งที่ต้องพิมพ์ และผลลัพธ์ที่ควรเห็น เพื่อให้รู้ทันทีว่าทำถูกหรือทำพลาดตรงไหน

ขอบเขตเอกสารนี้
เฉพาะ setup และรันโปรเจกต์แรกให้สำเร็จเท่านั้น ยังไม่สอนเขียนหน้าเว็บหรือ logic ใดๆ
ใช้เวลา
ประมาณ 20-30 นาที (ถ้าเครื่องมือยังไม่เคยติดตั้งมาก่อนเลย)
สิ่งที่ต้องมี
เครื่องคอมพิวเตอร์ที่ต่ออินเทอร์เน็ตได้ และ VS Code ติดตั้งไว้แล้ว
ขั้น 1 — เช็ค SDK ขั้น 2 — ติดตั้ง extension ขั้น 3 — สร้างโปรเจกต์ ขั้น 4 — สำรวจไฟล์ ขั้น 5 — รันจริง ขั้น 6 — ดูผลใน browser ขั้น 7 — แก้โค้ดแล้วเห็นผลทันที ขั้น 8 — หยุดการรัน แก้ปัญหาที่เจอบ่อย
1เช็คว่า .NET SDK ติดตั้งอยู่หรือยัง

เปิด VS Code แล้วเปิด terminal ข้างในโปรแกรม (กด Ctrl+` — ปุ่มเครื่องหมายเน้นเสียงข้างเลข 1 บนคีย์บอร์ด ไม่ใช่เครื่องหมายคำพูด) พิมพ์คำสั่งนี้แล้วกด Enter:

dotnet --version
ควรเห็น
ตัวเลขเวอร์ชัน เช่น 8.0.100 หรือ 9.0.200 (ขึ้นต้นด้วย 8 หรือมากกว่า)
ถ้าเจอแบบนี้แทน
ข้อความ 'dotnet' is not recognized หรือ command not found แปลว่ายังไม่ได้ติดตั้ง .NET SDK ให้ไปที่ https://dotnet.microsoft.com/download เลือกเวอร์ชัน LTS (ตัวที่แนะนำสำหรับใช้งานทั่วไป) ดาวน์โหลดแล้วติดตั้งตามขั้นตอนของโปรแกรมติดตั้งปกติ (กด Next ไปเรื่อยๆ) เสร็จแล้ว ปิด terminal เดิมแล้วเปิดใหม่ ก่อนลองพิมพ์คำสั่งนี้อีกครั้ง
2ติดตั้ง extension สำหรับเขียน C#

คลิกไอคอน Extensions ทางแถบซ้ายของ VS Code (รูปสี่เหลี่ยมต่อกัน 4 ชิ้น) หรือกด Ctrl+Shift+X แล้วพิมพ์ค้นหา:

C# Dev Kit

เลือกตัวที่ publisher เป็น Microsoft (มักจะขึ้นเป็นอันดับแรก) กด Install แล้วรอจนติดตั้งเสร็จ extension นี้จะติดตั้ง C# ตัวพื้นฐานและ .NET Install Tool มาให้อัตโนมัติด้วย

ควรเห็น
ปุ่ม Install เปลี่ยนเป็นไอคอนฟันเฟือง (แปลว่าติดตั้งเสร็จแล้ว) และถ้าเปิดไฟล์ .cs ใดๆ จะมีสีไฮไลต์ของโค้ดขึ้นมา

ติดตั้งเสร็จแล้ว ปิด VS Code แล้วเปิดใหม่ 1 ครั้ง เพื่อให้ extension โหลดค่าทั้งหมดสมบูรณ์

3สร้างโปรเจกต์เว็บแอปแรก

เลือกตำแหน่งที่จะเก็บงานฝึก (เช่น Desktop หรือ Documents) เปิด terminal ใน VS Code แล้วพิมพ์ทีละบรรทัด:

cd Desktop
mkdir learn-aspnetcore
cd learn-aspnetcore
dotnet new webapp -o FirstWebApp

อธิบายทีละคำสั่ง:

cd Desktop — เข้าไปในโฟลเดอร์ Desktop (เปลี่ยนเป็นโฟลเดอร์อื่นที่ต้องการได้)

mkdir learn-aspnetcore — สร้างโฟลเดอร์ใหม่ชื่อ learn-aspnetcore สำหรับเก็บงานฝึกทั้งหมด

cd learn-aspnetcore — เข้าไปในโฟลเดอร์ที่เพิ่งสร้าง

dotnet new webapp -o FirstWebApp — สั่งให้ .NET สร้างโปรเจกต์เว็บแอปเปล่าๆ (มีตัวอย่างมาให้พร้อม) ใส่ไว้ในโฟลเดอร์ชื่อ FirstWebApp

ควรเห็น
ข้อความประมาณ The template "ASP.NET Core Web App" was created successfully. และมีโฟลเดอร์ชื่อ FirstWebApp เกิดขึ้นมา
ถ้าเจอ error
ถ้าขึ้น error เกี่ยวกับ template ไม่รู้จัก มักเกิดจาก SDK ที่ติดตั้งเป็นเวอร์ชันเก่ามากหรือมีปัญหาตอนติดตั้ง ลองรัน dotnet --version ซ้ำตามขั้น 1 อีกครั้งเพื่อยืนยันว่า SDK ยังใช้งานได้ปกติ
4เปิดโปรเจกต์และสำรวจไฟล์คร่าวๆ

เข้าไปในโฟลเดอร์โปรเจกต์แล้วเปิดด้วย VS Code:

cd FirstWebApp
code .

VS Code จะเปิดหน้าต่างใหม่ขึ้นมา (หรือเปลี่ยนโฟลเดอร์ในหน้าต่างเดิม) แสดง sidebar ทางซ้ายมีไฟล์และโฟลเดอร์ หลายอย่าง ตอนนี้ยังไม่ต้องเข้าใจทุกไฟล์ ให้รู้จักแค่ 3 อย่างที่จะเจอบ่อยที่สุด:

โฟลเดอร์ Pages/ — เก็บหน้าเว็บทั้งหมด

ไฟล์ Program.cs — จุดเริ่มต้นของโปรแกรม

ไฟล์ FirstWebApp.csproj — ไฟล์ตั้งค่าโปรเจกต์ (บอกว่าใช้ .NET เวอร์ชันไหน)

ลองทำ: คลิกเปิดโฟลเดอร์ Pages/ ดูว่ามีไฟล์อะไรอยู่ข้างในบ้าง ไม่ต้องเปิดอ่านเนื้อหา แค่ดูชื่อไฟล์ผ่านๆ ก็พอสำหรับตอนนี้
5รันเว็บแอปจริง

กลับไปที่ terminal (ต้องอยู่ในโฟลเดอร์ FirstWebApp ถ้า path ใน terminal ไม่ตรง ให้พิมพ์ cd FirstWebApp ก่อน) แล้วพิมพ์:

dotnet run
ควรเห็น
ข้อความหลายบรรทัด บรรทัดสำคัญที่ต้องมองหาคือแบบนี้: 
Now listening on: http://localhost:5000
Now listening on: https://localhost:5001
ตัวเลข port (5000, 5001) อาจไม่ตรงเป๊ะทุกเครื่อง ให้จำ URL ที่ terminal แสดงไว้ในขั้นถัดไป

ตอนนี้ terminal จะ "ค้าง" อยู่แบบนั้น ไม่ขึ้น prompt ให้พิมพ์คำสั่งต่อ — นั่นคือพฤติกรรมปกติ แปลว่าเว็บแอปกำลังรันอยู่และรอรับ request ตลอดเวลา ไม่ใช่ error

6เปิดดูผลใน browser

เปิด browser (Chrome, Edge, อะไรก็ได้) แล้วพิมพ์ URL ที่เห็นจาก terminal ในขั้นก่อนหน้า เช่น:

http://localhost:5000
ควรเห็น
หน้าเว็บตัวอย่างที่มีข้อความต้อนรับประมาณ "Welcome" พร้อมเมนูด้านบน (Home, Privacy) — นี่คือเว็บแอป ASP.NET Core ตัวแรกที่รันสำเร็จจริงบนเครื่องคุณ
ถ้าเปิดแล้วขึ้น "This site can't be reached"
เช็คว่าพิมพ์ URL ตรงกับที่ terminal แสดงจริงไหม (บาง port อาจไม่ใช่ 5000) และเช็คว่า terminal ยังรันอยู่ (ยังไม่ได้กด Ctrl+C ปิดไปก่อน)
7ลองแก้โค้ดแล้วดูผลแบบสด

กลับไปที่ terminal กด Ctrl+C เพื่อหยุดการรันชั่วคราวก่อน แล้วพิมพ์คำสั่งใหม่แทน dotnet run:

dotnet watch run

คำสั่งนี้ทำงานเหมือน dotnet run ทุกอย่าง แต่เพิ่มความสามารถพิเศษคือ รีเฟรชหน้าเว็บให้อัตโนมัติทุกครั้งที่มีการแก้ไขไฟล์และบันทึก สะดวกมากตอนพัฒนาจริง ไม่ต้องกด Ctrl+C แล้วรันใหม่เองทุกครั้งที่แก้โค้ด

ลองเปิดไฟล์ Pages/Index.cshtml ใน VS Code หาข้อความที่แสดงอยู่บนหน้าเว็บ (เช่นคำว่า "Welcome") แก้เป็นข้อความอื่น แล้วกด Ctrl+S เพื่อบันทึก

ควรเห็น
กลับไปที่ browser ที่เปิดค้างไว้ หน้าเว็บจะรีเฟรชและแสดงข้อความใหม่ให้อัตโนมัติ โดยไม่ต้องกดรีเฟรชเอง (อาจใช้เวลา 1-2 วินาที)
ลองทำ: แก้ข้อความอีก 2-3 รอบ สังเกตว่าทุกครั้งที่บันทึกไฟล์ browser อัพเดทให้เองโดยไม่ต้องสลับกลับไปที่ terminal เลย
8หยุดการรันเมื่อเลิกใช้งาน

เมื่อเลิกฝึกในแต่ละครั้ง กลับไปที่ terminal ที่ยังรันค้างอยู่ แล้วกด:

Ctrl+C

terminal จะกลับมาพร้อมพิมพ์คำสั่งใหม่ได้ตามปกติ (สังเกตว่า prompt กลับมาแสดง) เว็บแอปจะหยุดทำงาน ถ้าเปิด browser ที่ URL เดิมอีกครั้งจะขึ้นว่าเชื่อมต่อไม่ได้ ซึ่งเป็นเรื่องปกติเพราะไม่มีอะไรรันอยู่แล้ว

ครั้งถัดไปที่อยากรันใหม่ แค่เปิด terminal ใน VS Code ที่โฟลเดอร์ FirstWebApp แล้วพิมพ์ dotnet watch run อีกครั้งได้เลย

!แก้ปัญหาที่เจอบ่อย
อาการวิธีแก้
dotnet: command not foundSDK ยังไม่ได้ติดตั้ง หรือติดตั้งแล้วแต่ยังไม่ได้ปิด-เปิด terminal ใหม่ ย้อนไปทำขั้น 1
รัน dotnet run แล้วค้างไม่ขึ้นอะไรเลยนานผิดปกติรอบแรกที่รันโปรเจกต์ ระบบต้อง restore package ก่อน อาจใช้เวลา 30 วินาที-1 นาที ถ้านานเกิน 3 นาทีค่อยลองตรวจสอบการเชื่อมต่ออินเทอร์เน็ต
เปิด URL แล้วเจอ "Your connection is not private" (https)เป็นเพราะ certificate สำหรับพัฒนา (development certificate) ยังไม่ได้รับความเชื่อถือจากเครื่อง ลองใช้ URL แบบ http (port 5000) แทน https (port 5001) ไปก่อนสำหรับการฝึก
แก้โค้ดแล้ว browser ไม่อัพเดทให้เองเช็คว่ารันด้วย dotnet watch run ไม่ใช่ dotnet run เฉยๆ (watch เท่านั้นที่มีระบบรีเฟรชอัตโนมัติ)
Port 5000 ถูกใช้งานอยู่แล้ว (address already in use)มักเกิดจากลืมปิด terminal ที่รันค้างไว้จากรอบก่อน ลองหา terminal เก่าแล้วกด Ctrl+C หรือปิดหน้าต่าง terminal นั้นทิ้งไปเลย
ถึงตรงนี้แปลว่าพร้อมแล้ว

เครื่องมือครบ โปรเจกต์รันได้จริง เห็นผลลัพธ์ใน browser และแก้โค้ดแล้วเห็นผลแบบสดได้แล้ว ขั้นต่อไปคือเริ่มเรียนเขียนหน้าเว็บจริงตามแผนการเรียนรู้ที่วางไว้

01โปรแกรมคืออะไร

โปรแกรม คือ ชุดคำสั่งที่บอกให้คอมพิวเตอร์ทำอะไรบางอย่าง ทีละขั้น ทีละขั้น เหมือนสูตรอาหารที่บอกว่า "ทำขั้นที่ 1 ก่อน แล้วค่อยทำขั้นที่ 2" คอมพิวเตอร์เองไม่ได้ฉลาดหรือคิดเองได้ มันแค่ทำตามคำสั่งที่เราเขียนไว้ ทีละบรรทัดอย่างเคร่งครัด

เปรียบเทียบ: ถ้าเราสั่งให้เพื่อนชงกาแฟโดยบอกแค่ "ชงกาแฟให้หน่อย" เพื่อนอาจจะเข้าใจเองว่าต้องทำอะไรบ้าง แต่คอมพิวเตอร์ทำแบบนั้นไม่ได้ เราต้องบอกละเอียดทุกขั้น เช่น "ต้มน้ำ" → "ใส่กาแฟ 2 ช้อน" → "เทน้ำร้อนลงไป" → "คนให้เข้ากัน" การเขียนโปรแกรม คือการเขียนคำสั่งละเอียดขนาดนั้นให้คอมพิวเตอร์ทำตาม

ภาษาโปรแกรม (เช่น C# ที่เรากำลังจะเรียน) คือภาษาที่มนุษย์ใช้เขียนคำสั่งเหล่านั้น ให้คอมพิวเตอร์เข้าใจได้

02Source Code กับการรันโค้ด ต่างกันยังไง

Source code คือ ตัวหนังสือที่เราพิมพ์เขียนคำสั่งไว้ในไฟล์ (ยังไม่ได้ทำงานอะไร แค่เป็นตัวอักษรอยู่ในไฟล์)

การรันโค้ด (run) คือ การสั่งให้คอมพิวเตอร์อ่าน source code นั้น แล้วทำตามคำสั่งจริงๆ ทีละบรรทัด

เปรียบเทียบ: source code เหมือนสูตรอาหารที่เขียนไว้ในกระดาษ ส่วนการรันโค้ด คือตอนที่เรา "ลงมือทำตามสูตรนั้นจริงๆ" ในครัว สูตรอาหารเฉยๆ ไม่ทำให้เกิดอาหารขึ้นมา ต้องมีคนลงมือทำตามถึงจะได้อาหารจริง

สำหรับภาษา C# ตัวที่ทำหน้าที่ "อ่านแล้วรันตามคำสั่ง" เรียกว่า .NET (อ่านว่า ดอท-เน็ต) เราจะติดตั้งมันในหัวข้อถัดไป

สิ่งที่มักเกิดขึ้นตอนรัน — Error: ถ้าเราเขียนคำสั่งผิด (เช่น สะกดผิด ลืมใส่เครื่องหมาย) ตอนรันโค้ด .NET จะไม่ทำงานให้แล้วแจ้ง error (ข้อผิดพลาด) กลับมาบอกว่าพังตรงไหน error ไม่ใช่เรื่องน่ากลัว มันคือข้อความช่วยบอกว่าต้องแก้ตรงไหน โปรแกรมเมอร์ทุกคนเจอ error ทุกวันแม้จะเขียนมานานแล้วก็ตาม ส่วนการหาสาเหตุที่โค้ดพังแล้วแก้ไข เรียกว่า debug
Compile กับ Run ต่างกันยังไง: ก่อนที่ .NET จะรันโค้ด C# ได้จริง มันต้อง "แปล" source code (ที่มนุษย์อ่านเข้าใจ) ให้กลายเป็นภาษาที่คอมพิวเตอร์เข้าใจก่อน ขั้นตอนแปลนี้เรียกว่า compile ถ้า source code เขียนผิดหลักไวยากรณ์ (เช่น ลืมใส่ ;) จะ compile ไม่ผ่านและไม่ได้รันเลย ต่างจาก error บางแบบที่ compile ผ่านแต่พังตอนรันจริง (เช่น เอา 10 หารด้วย 0)
ทำไมบางทีรันไม่ได้: ก่อนรันจริง .NET จะ "ตรวจสอบ" source code ก่อนว่าเขียนถูกไวยากรณ์ไหม ขั้นตอนนี้เรียกว่า compile ถ้าเขียนผิด (เช่น ลืมใส่เครื่องหมาย ; ท้ายบรรทัด หรือสะกดคำสั่งผิด) จะเจอ "compile error" และโปรแกรมจะไม่รันเลยแม้แต่บรรทัดเดียว ต่างจากตอนรันแล้วเกิดปัญหาระหว่างทาง (เรียกว่า "runtime error") ที่อย่างน้อยโปรแกรมได้เริ่มทำงานไปบ้างแล้วก่อนจะพัง จุดนี้สำคัญเวลา debug เพราะบอกได้ทันทีว่าปัญหาอยู่ที่ "เขียนผิดไวยากรณ์" หรือ "ตรรกะผิดตอนรัน"
ลองนึกภาพ: เทียบกับสูตรอาหารที่เขียนขั้นตอนไม่ครบ (เช่น "ผัดจนสุก" แต่ไม่บอกว่าผัดอะไร) คนทำอาหารอาจงงตั้งแต่ยังไม่เริ่มทำ นั่นคล้ายกับ compile error ส่วนถ้าสูตรเขียนครบแต่ทำไปแล้วไฟไหม้กลางทาง (เช่น ลืมปิดเตา) นั่นคล้ายกับ runtime error — ยังไม่ต้องเขียนโค้ดในหัวข้อนี้ แค่จำภาพนี้ไว้ก่อน

03เขียนบรรทัดแรก (Hello World)

ก่อนเขียนโค้ด ต้องติดตั้งเครื่องมือ 2 อย่างก่อน:

อย่างแรก — ติดตั้ง .NET SDK จาก dotnet.microsoft.com/download เลือกเวอร์ชัน LTS (เวอร์ชันที่แนะนำ) แล้วติดตั้งตามขั้นตอนของโปรแกรมติดตั้งปกติ

อย่างที่สอง — เปิด VS Code แล้วติดตั้ง extension ชื่อ "C# Dev Kit" (กดที่ไอคอน Extensions ด้านซ้าย พิมพ์ค้นหา แล้วกด Install)

ตรวจสอบว่าติดตั้งสำเร็จ เปิด terminal ใน VS Code (กด Ctrl+`) แล้วพิมพ์:

dotnet --version

ถ้าเห็นตัวเลขเวอร์ชัน (เช่น 8.0.100) แปลว่าเรียบร้อย ถ้าขึ้น error ว่าไม่รู้จักคำสั่งนี้ แปลว่ายังติดตั้งไม่สำเร็จ ต้องกลับไปข้อแรกก่อน

ตอนนี้ลองสร้างโปรแกรมแรกในชีวิต ที่แค่ print ข้อความออกมา:

mkdir hello-world
cd hello-world
dotnet new console
dotnet run

คำสั่ง dotnet new console คือการสร้างโปรแกรมเปล่าๆ แบบง่ายที่สุดให้ ส่วน dotnet run คือการสั่งรันโปรแกรมนั้น ถ้าทำถูกต้อง จะเห็นคำว่า Hello, World! ปรากฏขึ้นมาในหน้าจอ terminal

ตอนพิมพ์ dotnet run เกิดอะไรขึ้นบ้าง: เบื้องหลังมี 2 ขั้นตอนซ้อนกันอยู่ ต่อเนื่องจากหัวข้อ 2 ขั้นแรก .NET จะ compile source code ในไฟล์ Program.cs ก่อน (ตรวจไวยากรณ์ให้) ถ้าผ่านแล้วถึงจะเข้าขั้นที่สอง คือรันจริง ถ้าเจอ compile error จะเห็นข้อความ error สีแดงแทนคำว่า Hello, World! และโปรแกรมจะไม่เริ่มทำงานเลย
ลองทำ: เปิดไฟล์ Program.cs ที่ถูกสร้างขึ้นมา (อยู่ในโฟลเดอร์ hello-world) จะเห็นบรรทัดเดียวที่เขียนว่า Console.WriteLine("Hello, World!"); ลองแก้ข้อความในเครื่องหมายคำพูด เป็นชื่อตัวเองแล้วรัน dotnet run ใหม่ ดูว่าข้อความเปลี่ยนไหม
ดูเฉลย
Console.WriteLine("Somchai");
เปลี่ยนแค่ข้อความในเครื่องหมายคำพูด ผลลัพธ์ตอนรัน dotnet run จะแสดงชื่อแทนคำว่า Hello, World!
Comment คืออะไร: บางครั้งอยากเขียนโน้ตไว้ในโค้ดเพื่อเตือนความจำตัวเองหรืออธิบายให้คนอื่นเข้าใจ โดยไม่ให้คอมพิวเตอร์เอาไปรันด้วย ใช้เครื่องหมาย // นำหน้าบรรทัดนั้น 
// บรรทัดนี้คือ comment คอมพิวเตอร์จะข้ามไปเลย ไม่รันอะไร
Console.WriteLine("Hello, World!");   // เขียนโน้ตต่อท้ายบรรทัดโค้ดก็ได้
comment มีประโยชน์มากตอนกลับมาอ่านโค้ดตัวเองหลังผ่านไปนานๆ หรือมีคนอื่นมาอ่านโค้ดของเรา
Console.WriteLine ทำอะไรกันแน่: Console คือชื่อของหน้าจอ terminal ที่กำลังใช้อยู่ WriteLine คือคำสั่ง "เขียนข้อความแล้วขึ้นบรรทัดใหม่" ส่วนข้อความในวงเล็บคือสิ่งที่จะให้แสดง ถ้าอยากเขียนโดยไม่ขึ้นบรรทัดใหม่ ใช้ Console.Write แทน (ไม่มี Line ต่อท้าย)
ลองทำอีกอย่าง: ลองลบเครื่องหมาย ; ท้ายบรรทัดออกไปก่อน 1 ตัว แล้วรัน dotnet run ดูว่าเจอ compile error แบบไหน (นี่คือตัวอย่าง compile error จริงที่เพิ่งพูดถึง) แก้กลับคืนเป็นเดิมก่อนไปหัวข้อถัดไป

ลบ ; ออกแล้วรัน จะเห็น compile error ประมาณ 
error CS1002: ; expected
นี่คือตัวอย่าง error ที่เกิดตอน compile (ก่อนรันจริง) เพราะ C# บังคับให้ทุกคำสั่งจบด้วย ; เสมอ อย่าลืมใส่ ; กลับคืนก่อนไปหัวข้อถัดไป
04ตัวแปรคืออะไร

ตัวแปร คือ ที่สำหรับเก็บค่าไว้ใช้ในภายหลัง เหมือนกล่องที่มีชื่อติดไว้ ใส่ของลงไปแล้วเรียกของนั้นออกมาใช้ทีหลังได้ โดยเรียกผ่านชื่อกล่อง

เปรียบเทียบ: เหมือนเขียนชื่อกำกับบนกล่องเก็บของ เช่น กล่องชื่อ "อายุ" ใส่เลข 25 ไว้ข้างใน ทีหลังพอเราพูดถึง "อายุ" คอมพิวเตอร์ก็รู้ว่าหมายถึง 25

ในภาษา C# การสร้างตัวแปรเขียนแบบนี้:

int age = 25;
string name = "Somchai";

อ่านว่า "สร้างตัวแปรชื่อ age เก็บค่าเป็นตัวเลข 25" และ "สร้างตัวแปรชื่อ name เก็บค่าเป็นข้อความ Somchai" คำว่า int และ string ด้านหน้า คือการบอกว่าของในกล่องนี้เป็น "ชนิด" ไหน ซึ่งจะอธิบายละเอียดในหัวข้อถัดไป

เปลี่ยนค่าในตัวแปรได้ตลอด: ตัวแปรเรียกว่า "แปร" เพราะเปลี่ยนค่าได้ ไม่ใช่กำหนดครั้งเดียวแล้วตายตัว 
int age = 25;
Console.WriteLine(age);   // แสดง 25

age = 26;                 // เปลี่ยนค่าในกล่องเดิม ไม่ต้องเขียน int ซ้ำ
Console.WriteLine(age);   // แสดง 26
สังเกตว่าบรรทัดที่สองไม่มีคำว่า int นำหน้าอีก เพราะกล่องชื่อ age ถูกสร้างไปแล้วตั้งแต่บรรทัดแรก บรรทัดนี้แค่ "เปลี่ยนของข้างใน" เท่านั้น
กฎการตั้งชื่อตัวแปร: ต้องขึ้นต้นด้วยตัวอักษรหรือ underscore (ห้ามขึ้นต้นด้วยตัวเลข) ห้ามมีช่องว่าง และห้ามซ้ำกับคำสั่งที่ภาษา C# ใช้เอง (เช่นห้ามตั้งชื่อตัวแปรว่า int) ธรรมเนียมที่นิยมใช้กันคือ ตั้งชื่อแบบ camelCase (ตัวแรกเล็ก คำถัดไปขึ้นต้นด้วยตัวใหญ่) เช่น customerName, totalAmount เพื่อให้อ่านง่ายเมื่อชื่อมีหลายคำ
ลองทำ: ในไฟล์ Program.cs เดิม เพิ่มบรรทัด int age = 25; ไว้ก่อนบรรทัด Console.WriteLine แล้วเปลี่ยนบรรทัดนั้นเป็น Console.WriteLine(age); รันดูว่าเห็นเลข 25 ปรากฏขึ้นมาไหม
ดูเฉลย
int age = 25;
Console.WriteLine(age);
รันแล้วจะเห็นเลข 25 ปรากฏในหน้าจอ terminal
เปลี่ยนค่าในตัวแปรได้ทีหลัง: ตัวแปรเรียกว่า "ตัวแปร" เพราะค่าข้างในเปลี่ยนได้ตลอดเวลา 
int age = 25;
Console.WriteLine(age);   // แสดง 25

age = 26;                 // เปลี่ยนค่าใหม่ (ไม่ต้องเขียน int ซ้ำ)
Console.WriteLine(age);   // แสดง 26
สังเกตว่าตอนเปลี่ยนค่าครั้งที่สอง ไม่ต้องเขียน int นำหน้าอีก เพราะกล่องชื่อ age ถูกสร้างไปแล้วตั้งแต่บรรทัดแรก แค่ใส่ของใหม่ลงไปแทนของเดิม
ค่าคงที่ (const): ถ้ามีค่าที่ไม่อยากให้ใครเผลอไปเปลี่ยนทีหลัง ใช้ const แทน int/string ปกติ 
const double TaxRate = 0.07;
// TaxRate = 0.08;   ถ้าเขียนบรรทัดนี้จะ error ทันที เพราะ const ห้ามเปลี่ยนค่า
วิธีตั้งชื่อตัวแปรที่นิยมใน C#: ตัวแปรทั่วไปมักตั้งชื่อแบบ camelCase (ขึ้นต้นตัวเล็ก คำถัดไปขึ้นตัวใหญ่) เช่น customerName, totalAmount ชื่อควรสื่อความหมายชัดเจน หลีกเลี่ยงชื่อสั้นๆ กำกวมอย่าง x, data1 เพราะทำให้กลับมาอ่านโค้ดทีหลังยากขึ้นมาก
ลองทำอีกอย่าง: เพิ่มบรรทัด age = 30; ต่อจากบรรทัดเดิม แล้ว Console.WriteLine(age) อีกครั้ง สังเกตว่าครั้งที่สองแสดงผลเป็น 30 ไม่ใช่ 25 แล้ว เพราะค่าถูกเปลี่ยนไปแล้ว
ดูเฉลย
int age = 25;
Console.WriteLine(age);   // แสดง 25

age = 30;
Console.WriteLine(age);   // แสดง 30
สังเกตว่าบรรทัดที่สองไม่ต้องเขียน int ซ้ำ เพราะ age ถูกสร้างไปแล้วตั้งแต่บรรทัดแรก
05ชนิดข้อมูล (Data Type)

ทำไมต้องบอกคอมพิวเตอร์ว่าของในกล่องเป็น "ตัวเลข" หรือ "ข้อความ" เพราะแต่ละชนิดทำงานต่างกัน เช่น ตัวเลขเอามาบวกลบคูณหารกันได้ แต่ข้อความบวกกันไม่ได้ในความหมายเดียวกัน (บวกข้อความคือการต่อกันแทน) การบอกชนิดไว้ล่วงหน้าช่วยให้คอมพิวเตอร์เตือนเราได้ทันทีถ้าทำอะไรผิดประเภท เช่น เอาข้อความไปหารตัวเลข

ชนิดข้อมูลพื้นฐานที่ใช้บ่อยที่สุด:

int quantity = 10;        // ตัวเลขจำนวนเต็ม
decimal price = 25.50m;   // ตัวเลขทศนิยม (ใช้กับเงินเสมอ)
string name = "Somchai";  // ข้อความ
bool isActive = true;     // ค่าจริง/เท็จ (true หรือ false เท่านั้น)
ทำไมต้อง decimal สำหรับเงิน: ตัวเลขทศนิยมแบบปกติ (เรียกว่า double หรือ float) อาจคำนวณเงินแล้วเพี้ยน เล็กน้อยจากการปัดเศษของคอมพิวเตอร์ ภาษา C# เลยมีชนิดพิเศษชื่อ decimal ที่แม่นยำกว่าสำหรับงานเงินโดยเฉพาะ
ชนิดข้อมูลอื่นที่จะเจอเพิ่มเติม: 
long bigNumber = 10000000000;   // ตัวเลขจำนวนเต็มที่ใหญ่กว่า int รับได้ (ใช้เมื่อ int ไม่พอ)
double score = 88.5;             // ตัวเลขทศนิยมทั่วไป (ไม่ใช่เงิน)
char grade = 'A';                // ตัวอักษรเดี่ยว 1 ตัว (ใช้เครื่องหมายคำพูดเดี่ยว ไม่ใช่คู่)
ส่วนใหญ่ในงานจริงจะใช้แค่ int, decimal, string, bool บ่อยที่สุด ที่เหลือเจอเป็นครั้งคราว
แปลงชนิดข้อมูล (type conversion): บางครั้งมีค่าชนิดหนึ่งแต่ต้องใช้อีกชนิด เช่น รับตัวเลขมาเป็น string แล้วอยากเอาไปคำนวณจริง ต้องแปลงก่อน 
string ageText = "25";
int age = int.Parse(ageText);     // แปลงข้อความเป็นตัวเลข
Console.WriteLine(age + 5);        // ได้ 30

int score = 90;
string scoreText = score.ToString();   // แปลงตัวเลขเป็นข้อความ
ถ้าลืมแปลงแล้วเอาชนิดที่เข้ากันไม่ได้มาบวกกันตรงๆ (เช่น string บวก int โดยไม่แปลง) จะเจอ compile error ตามที่พูดถึงในหัวข้อ 2-3
ลองทำ: เพิ่มตัวแปร 4 ชนิดข้างบนในโปรแกรมเดิม แล้วลอง Console.WriteLine แต่ละตัวดูทีละบรรทัด สังเกตว่าแสดงผลต่างกันยังไง
ดูเฉลย
int quantity = 10;
decimal price = 25.50m;
string name = "Somchai";
bool isActive = true;

Console.WriteLine(quantity);   // 10
Console.WriteLine(price);      // 25.50
Console.WriteLine(name);       // Somchai
Console.WriteLine(isActive);   // True
สังเกตว่า bool แสดงผลเป็น True/False (ขึ้นต้นด้วยตัวใหญ่) ต่างจาก true/false ตอนเขียนโค้ด
การแปลงชนิดข้อมูล (Type Conversion): บางครั้งข้อมูลมาเป็นข้อความ แต่เราอยากเอาไปคำนวณเป็นตัวเลข ต้อง "แปลงชนิด" ก่อน 
string ageText = "25";
int age = int.Parse(ageText);    // แปลงข้อความเป็นตัวเลข
Console.WriteLine(age + 5);      // ได้ 30

int number = 100;
string text = number.ToString(); // แปลงตัวเลขเป็นข้อความ
ถ้าเผลอเอาข้อความที่ไม่ใช่ตัวเลขไปแปลง เช่น int.Parse("abc") โปรแกรมจะ error ทันที เพราะ "abc" แปลงเป็นตัวเลขไม่ได้
คำว่า var — ให้คอมพิวเตอร์เดา type ให้: แทนที่จะพิมพ์ type เองทุกครั้ง ใช้ var แทนได้ คอมพิวเตอร์จะดูจากค่าที่ใส่แล้วเดา type ให้อัตโนมัติ 
var age = 25;              // C# เดาว่าเป็น int เอง
var name = "Somchai";      // C# เดาว่าเป็น string เอง
ผลลัพธ์เหมือนกับเขียน int age = 25; ทุกประการ แค่สั้นกว่า นิยมใช้เมื่อเห็นชัดอยู่แล้วว่า ค่าทางขวาเป็น type อะไร
ลองทำอีกอย่าง: สร้างตัวแปร string เก็บค่า "100" แล้วใช้ int.Parse แปลงเป็นตัวเลข บวกกับ 50 แล้ว Console.WriteLine ผลลัพธ์ ควรได้ 150
ดูเฉลย
string numberText = "100";
int number = int.Parse(numberText);
Console.WriteLine(number + 1);   // แสดง 101 (บวกกันได้จริงเพราะแปลงเป็น int แล้ว)
ถ้าลอง Console.WriteLine(numberText + 1) โดยไม่แปลงก่อน จะได้ผลเป็น "1001" (ต่อข้อความ) แทนการบวกจริง
06การตัดสินใจ (if/else)

ในชีวิตจริงเราตัดสินใจตลอดเวลา เช่น "ถ้าฝนตก ให้พกร่ม ถ้าไม่ตก ก็ไม่ต้องพก" โปรแกรมก็ต้องตัดสินใจแบบนี้ได้เหมือนกัน เรียกว่า if/else (ถ้า.../ไม่งั้น...)

int age = 25;

if (age >= 18)
{
    Console.WriteLine("เป็นผู้ใหญ่แล้ว");
}
else
{
    Console.WriteLine("ยังไม่บรรลุนิติภาวะ");
}

อ่านว่า "ถ้า age มากกว่าหรือเท่ากับ 18 ให้ print ว่าเป็นผู้ใหญ่ ไม่งั้นให้ print อีกอันแทน" สังเกตว่าคอมพิวเตอร์จะเลือกทำแค่ทางใดทางหนึ่งเท่านั้น ไม่ทำทั้งสองทาง

เครื่องหมายเปรียบเทียบที่ใช้บ่อย: == (เท่ากับ), != (ไม่เท่ากับ), > (มากกว่า), < (น้อยกว่า), >= (มากกว่าหรือเท่ากับ) สังเกตว่าเครื่องหมาย "เท่ากับ" ในการเปรียบเทียบต้องใช้ == สองตัว ไม่ใช่ = ตัวเดียว (ตัวเดียวใช้สำหรับ "กำหนดค่า" อย่างที่เจอในหัวข้อ 4)
ตัดสินใจมากกว่า 2 ทาง — else if: ถ้ามีเงื่อนไขมากกว่าแค่ "ใช่หรือไม่ใช่" ใช้ else if ต่อกันได้เรื่อยๆ 
int score = 75;

if (score >= 80)
{
    Console.WriteLine("เกรด A");
}
else if (score >= 60)
{
    Console.WriteLine("เกรด B");
}
else
{
    Console.WriteLine("เกรด C");
}
คอมพิวเตอร์เช็คจากบนลงล่างทีละเงื่อนไข พอเจอเงื่อนไขไหนที่เป็นจริงก่อน จะทำตามนั้นแล้วข้ามที่เหลือไปเลย (ในตัวอย่างนี้ score = 75 ไม่เข้าเงื่อนไขแรก แต่เข้าเงื่อนไขที่สอง เลยได้ "เกรด B")
รวมหลายเงื่อนไขในบรรทัดเดียว: ใช้ && (และ — ต้องจริงทั้งคู่) กับ || (หรือ — จริงแค่อันใดอันหนึ่งก็พอ) 
int age = 20;
bool hasId = true;

if (age >= 18 && hasId)
{
    Console.WriteLine("เข้าได้");   // ต้องอายุถึงและมีบัตร ถึงจะเข้าเงื่อนไขนี้
}
ลองทำ: เขียนโปรแกรมเช็คว่าตัวเลขที่กำหนดเป็นเลขคู่หรือเลขคี่ (ใบ้: ใช้ number % 2 == 0 เช็คว่าหารด้วย 2 ลงตัวไหม เครื่องหมาย % คือหาเศษที่เหลือจากการหาร)
ดูเฉลย
int number = 7;

if (number % 2 == 0)
{
    Console.WriteLine("เลขคู่");
}
else
{
    Console.WriteLine("เลขคี่");
}
% คือการหาเศษเหลือจากการหาร ถ้าหารด้วย 2 แล้วเศษเป็น 0 แปลว่าหารลงตัว คือเลขคู่
เลือกได้มากกว่า 2 ทางด้วย else if: ถ้ามีเงื่อนไขมากกว่า "ใช่/ไม่ใช่" ใช้ else if ต่อกันได้เรื่อยๆ 
int score = 75;

if (score >= 80)
{
    Console.WriteLine("เกรด A");
}
else if (score >= 70)
{
    Console.WriteLine("เกรด B");
}
else if (score >= 60)
{
    Console.WriteLine("เกรด C");
}
else
{
    Console.WriteLine("เกรด D");
}
คอมพิวเตอร์จะเช็คจากบนลงล่าง เจอเงื่อนไขไหนที่เป็นจริงก่อน ก็ทำตามนั้นแล้วหยุดเช็คอันที่เหลือทันที
รวมหลายเงื่อนไขด้วย && และ ||: && อ่านว่า "และ" (ต้องจริงทั้งคู่) ส่วน || อ่านว่า "หรือ" (จริงแค่อันใดอันหนึ่งก็พอ) 
int age = 25;
bool hasId = true;

if (age >= 18 && hasId)
{
    Console.WriteLine("เข้าได้");   // ต้องอายุถึงและมีบัตร ถึงจะเข้าได้
}
switch — ทางเลือกอื่นเมื่อเทียบค่าเดียวกันหลายแบบ: 
string day = "Monday";

switch (day)
{
    case "Monday":
        Console.WriteLine("วันจันทร์");
        break;
    case "Tuesday":
        Console.WriteLine("วันอังคาร");
        break;
    default:
        Console.WriteLine("วันอื่นๆ");
        break;
}
อ่านง่ายกว่า if/else if ยาวๆ เมื่อเทียบค่าตัวแปรเดียวกับหลายค่า อย่าลืม break; ท้ายแต่ละ case เพื่อบอกว่าจบเงื่อนไขนั้นแล้ว
ลองทำอีกอย่าง: เขียนโปรแกรมให้เกรดจากคะแนน (A ถ้า >= 80, B ถ้า >= 60, C ถ้าน้อยกว่านั้น) ตามตัวอย่าง else if ข้างบน แล้วลองเปลี่ยนค่า score หลายๆ ค่าดูว่าผลลัพธ์เปลี่ยนถูกไหม

int score = 65;

    Console.WriteLine("A");

07การทำซ้ำ (Loop)

ถ้าต้องการให้คอมพิวเตอร์ทำอะไรซ้ำๆ กันหลายรอบ เช่น print ข้อความ 5 ครั้ง แทนที่จะเขียน Console.WriteLine ซ้ำ 5 บรรทัด เราใช้ loop (การวนซ้ำ) แทน

for (int i = 1; i <= 5; i++)
{
    Console.WriteLine("รอบที่ " + i);
}

อ่านว่า "เริ่มจาก i เท่ากับ 1 ทำซ้ำไปเรื่อยๆ ตราบใดที่ i ยังน้อยกว่าหรือเท่ากับ 5 แล้วเพิ่มค่า i ทีละ 1 ในแต่ละรอบ" ผลลัพธ์คือจะ print คำว่า "รอบที่ 1" ถึง "รอบที่ 5" ออกมาทั้งหมด 5 บรรทัด

เปรียบเทียบ: เหมือนบอกให้ใครทำ squat 5 ครั้ง แทนที่จะบอกทีละครั้งว่า "squat 1 ครั้ง" ซ้ำ 5 รอบ เราแค่บอกครั้งเดียวว่า "ทำ squat 5 ครั้ง" loop ก็ทำหน้าที่แบบนั้น
while loop — ทำซ้ำโดยไม่รู้จำนวนรอบล่วงหน้า: for loop เหมาะกับตอนที่รู้แน่ชัดว่าจะวนกี่รอบ แต่บางสถานการณ์ไม่รู้จำนวนรอบล่วงหน้า เช่น "ทำไปเรื่อยๆ จนกว่าจะครบเงื่อนไข" ใช้ while แทน 
int total = 0;
int i = 1;

while (total < 20)
{
    total = total + i;
    i++;
}

Console.WriteLine(total);
อ่านว่า "ทำซ้ำไปเรื่อยๆ ตราบใดที่ total ยังน้อยกว่า 20" คอมพิวเตอร์จะเช็คเงื่อนไขก่อนทุกรอบ ถ้าเงื่อนไขเป็นเท็จเมื่อไหร่ก็หยุดทันที
break และ continue — ควบคุม loop เพิ่มเติม: 
for (int i = 1; i <= 10; i++)
{
    if (i == 5)
    {
        break;          // หยุด loop ทันทีเมื่อ i เท่ากับ 5
    }
    Console.WriteLine(i);
}
// ผลลัพธ์: print 1, 2, 3, 4 แล้วหยุด (ไม่ถึง 5)
break คือ "หยุด loop ทั้งหมดทันที" ส่วน continue คือ "ข้ามรอบนี้ไปทำรอบถัดไปเลย" โดยไม่หยุดทั้ง loop
ลองทำ: เขียน loop ที่ print ตัวเลข 1 ถึง 10 แต่ให้ print เฉพาะเลขคู่เท่านั้น (รวมความรู้จากหัวข้อ 6 กับ 7 เข้าด้วยกัน)
ดูเฉลย
for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0)
    {
        Console.WriteLine(i);
    }
}
ผลลัพธ์คือ 2, 4, 6, 8, 10 (รวม if จากหัวข้อ 6 เข้ากับ for loop จากหัวข้อ 7)
while — วนซ้ำตราบใดที่เงื่อนไขยังจริง: ใช้เมื่อไม่รู้แน่ชัดว่าจะวนกี่รอบ (ต่างจาก for ที่มักรู้จำนวนรอบล่วงหน้า) 
int count = 1;

while (count <= 5)
{
    Console.WriteLine("รอบที่ " + count);
    count++;   // ต้องเพิ่มค่าเอง ไม่งั้นจะวนไม่จบ (infinite loop)
}
ข้อควรระวัง: ถ้าลืมเขียน count++ เงื่อนไข count <= 5 จะเป็นจริงตลอดไป โปรแกรมจะวนไม่หยุดเรียกว่า infinite loop ต้องกด Ctrl+C เพื่อหยุดเอง
break และ continue: break คือ "หยุดวนทันที ออกจาก loop เลย" ส่วน continue คือ "ข้ามรอบนี้ไปทำรอบถัดไปเลย ไม่ต้องทำที่เหลือในรอบนี้" 
for (int i = 1; i <= 10; i++)
{
    if (i == 5)
    {
        break;   // พอ i ครบ 5 หยุด loop ทันที ไม่วนต่อจนถึง 10
    }
    Console.WriteLine(i);
}
ลองทำอีกอย่าง: เขียน while loop ที่บวกเลข 1+2+3+... ไปเรื่อยๆ จนกว่าผลรวม จะเกิน 50 แล้ว print ว่าผลรวมสุดท้ายคือเท่าไหร่ และบวกไปกี่รอบถึงเกิน
ดูเฉลย
int sum = 0;
int number = 1;

while (sum <= 50)
{
    sum = sum + number;
    number++;
}

Console.WriteLine(sum);
วนบวกไปเรื่อยๆ จนกว่า sum จะเกิน 50 แล้วหยุดเอง ไม่ต้องกำหนดจำนวนรอบล่วงหน้าแบบ for
08Method — การตั้งชื่อ "งาน" ที่ทำซ้ำได้

ถ้ามีชุดคำสั่งที่ต้องใช้ซ้ำๆ หลายที่ในโปรแกรม แทนที่จะเขียนซ้ำทุกครั้ง เราตั้งชื่อชุดคำสั่งนั้นไว้ครั้งเดียว แล้วเรียกใช้ชื่อนั้นซ้ำได้เรื่อยๆ ชุดคำสั่งที่ตั้งชื่อไว้แบบนี้เรียกว่า method

// สร้าง method ชื่อ Greet
static void Greet(string name)
{
    Console.WriteLine("สวัสดี " + name);
}

// เรียกใช้ method
Greet("Somchai");
Greet("Somying");

method Greet รับค่าเข้ามา 1 ค่า (เรียกว่า parameter) ชื่อ name แล้ว print คำทักทายออกมา พอเรียก Greet("Somchai") ก็เหมือนบอกว่า "ทำงาน Greet โดยใช้ค่า Somchai แทน name"

method ที่ return ค่ากลับมา: บาง method ไม่ได้แค่ print แต่ "คำนวณแล้วส่งผลลัพธ์กลับมา" ด้วย return เช่น 
static int Add(int a, int b)
{
    return a + b;
}

int result = Add(3, 5);   // result จะเก็บค่า 8
ลองทำ: เขียน method ชื่อ IsEven ที่รับตัวเลข 1 ตัว แล้ว return ค่า true/false ว่าเป็นเลขคู่ไหม (เอาความรู้จากหัวข้อ 6 มาใช้)
ดูเฉลย
static bool IsEven(int number)
{
    return number % 2 == 0;
}

Console.WriteLine(IsEven(4));   // True
Console.WriteLine(IsEven(7));   // False
รับหลาย parameter พร้อมกัน: method รับ parameter กี่ตัวก็ได้ คั่นด้วยเครื่องหมายจุลภาค 
static decimal CalculateTotal(int quantity, decimal unitPrice, decimal discount)
{
    decimal subtotal = quantity * unitPrice;
    return subtotal - discount;
}

decimal total = CalculateTotal(3, 100, 20);   // ส่งค่าตามลำดับ: 3, 100, 20
เวลาเรียกใช้ ต้องส่งค่าตามลำดับและจำนวนให้ตรงกับที่ method กำหนดไว้เป๊ะ
parameter ที่มีค่าเริ่มต้น (optional parameter): กำหนดค่าเริ่มต้นไว้ได้ ถ้าไม่ส่งค่ามาก็ใช้ค่านั้นแทน 
static void Greet(string name, string greeting = "สวัสดี")
{
    Console.WriteLine(greeting + " " + name);
}

Greet("Somchai");              // ใช้ค่าเริ่มต้น พิมพ์ "สวัสดี Somchai"
Greet("Somchai", "หวัดดี");     // ส่งค่าเอง พิมพ์ "หวัดดี Somchai"

class Product
{
    public string Name;
    public decimal Price;

    // method ที่อยู่ใน class เรียกว่า "การกระทำของ object นี้"
    public void ApplyDiscount(decimal percent)
    {
        Price = Price - (Price * percent / 100);
    }
}

Product item = new Product();
item.Name = "เสื้อยืด";
item.Price = 200;

CRUD กับ List — คำที่จะได้ยินบ่อยมากตอนเขียนเว็บแอป: CRUD ย่อมาจาก Create (สร้าง), Read (อ่าน), Update (แก้ไข), Delete (ลบ) เป็น 4 การกระทำพื้นฐานที่สุดที่ทำกับข้อมูลเกือบทุกระบบ ลองดูว่าแต่ละอย่างเขียนกับ List ยังไง: 
List<string> fruits = new List<string>();

// Create — เพิ่มของใหม่เข้าไป
fruits.Add("แอปเปิ้ล");
fruits.Add("กล้วย");

// Read — อ่านค่าออกมาดู (index เริ่มนับจาก 0 เสมอ)
Console.WriteLine(fruits[0]);   // แสดง "แอปเปิ้ล" (ตัวแรกคือ index 0)

// Update — แก้ไขค่าที่ตำแหน่งเดิม
fruits[0] = "ส้ม";              // เปลี่ยนตัวแรกจาก "แอปเปิ้ล" เป็น "ส้ม"

// Delete — ลบออกจาก List
fruits.Remove("กล้วย");         // ลบ "กล้วย" ออก

fruits.IndexOf("ส้ม")   // หาว่า "ส้ม" อยู่ตำแหน่ง (index) ไหน ถ้าไม่เจอได้ -1

11เว็บทำงานยังไง

ก่อนเขียนเว็บแอป ต้องเข้าใจภาพรวมก่อนว่าเว็บทำงานยังไง (ยังไม่มีโค้ดในหัวข้อนี้)

เปรียบเทียบ: ลองนึกภาพร้านอาหาร มี "ลูกค้า" (browser ที่เราใช้เปิดเว็บ) กับ "ครัว" (server เครื่องที่เก็บโปรแกรมและข้อมูลไว้) ลูกค้าสั่งอาหารผ่านบริกร (ส่ง "คำขอ" หรือ request ไปหา server) ครัวทำอาหารเสร็จแล้วส่งกลับมาผ่านบริกร (server ส่ง "คำตอบ" หรือ response กลับมา) ลูกค้าไม่เห็นว่าครัว ทำงานยังไงข้างใน เห็นแค่จานอาหารที่ได้รับ

เวลาเราเปิดเว็บไซต์ browser จะส่ง request ไปหา server ว่า "ขอหน้านี้หน่อย" server ประมวลผล (อาจไปดึงข้อมูลจากฐานข้อมูล คำนวณอะไรบางอย่าง) แล้วส่ง response กลับมาเป็นหน้าเว็บ ให้ browser แสดงผล

ขั้นตอน request → server ประมวลผล → response แบบนี้เกิดขึ้นทุกครั้งที่เราคลิกลิงก์หรือกดปุ่มบนเว็บ

12ASP.NET Core คืออะไรในภาพนั้น

จากหัวข้อ 11 ฝั่ง "ครัว" (server) ต้องมีคนเขียนโปรแกรมกำหนดไว้ว่า พอมี request ประเภทไหนเข้ามา จะต้องทำอะไรตอบกลับไป ASP.NET Core คือเครื่องมือ (framework) ที่ช่วยให้เราเขียนโปรแกรมฝั่งครัวนี้ได้ ด้วยภาษา C# ที่เพิ่งฝึกมาใน Part B

ทำไมต้องมี framework: ถ้าไม่มี ASP.NET Core เราต้องเขียนโค้ดจัดการเรื่องพื้นฐานทุกอย่างเอง ทั้งการรับ request, แปลงข้อมูล, ส่ง response กลับให้ถูกรูปแบบ ASP.NET Core จัดการเรื่องพื้นฐานเหล่านี้ให้แล้ว เราแค่โฟกัสที่ "พอมี request แบบนี้เข้ามา ให้ทำอะไร" พอ

ทุกความรู้จาก Part B (ตัวแปร, if/else, loop, method, class, List) จะถูกใช้จริงตอนเขียน ASP.NET Core เพราะข้างในก็คือโค้ด C# ธรรมดา แค่ทำงานอยู่ในกรอบของ framework ที่คอยรับ-ส่ง request/response ให้เรา

asp-for="NewProduct.Name" คือการบอกว่า input ช่องนี้ผูกกับ property ชื่อ Name ของ NewProduct โดยอัตโนมัติ ไม่ต้องเขียนโค้ดดึงค่าจากฟอร์มเอง ส่วน [BindProperty] บอกว่า property นี้จะรับค่าจากฟอร์มที่ submit เข้ามาให้เองอัตโนมัติเช่นกัน

OnPost() ต่างจาก OnGet() ในหัวข้อ 15 ตรงที่ OnGet ทำงานตอน "เปิดหน้า" ส่วน OnPost ทำงานตอน "กดปุ่ม submit ฟอร์ม"

ลองทำ: ลองกรอกฟอร์มแล้วกด submit เปิด terminal ดูว่าข้อความ "ได้รับสินค้า: ..." ปรากฏขึ้นมาพร้อมชื่อที่กรอกไปจริงไหม

{

DbSet<Product> Products คือการบอกว่า "มี table ชื่อ Products เก็บข้อมูลตาม class Product ที่สร้างไว้แล้วในหัวข้อ 9" AppDbContext คือจุดเดียวที่ใช้คุยกับฐานข้อมูลทั้งหมด

หัวข้อนี้คือการเอาความรู้ทั้งหมดจากหัวข้อ 13-17 มาประกอบเป็นเว็บแอปที่ใช้งานได้จริง มีฟังก์ชันครบ 4 อย่าง เรียกรวมกันว่า CRUD:

Update — แก้ไขข้อมูลเดิม (คล้ายฟอร์ม Create แต่โหลดค่าเดิมมาแสดงก่อน)

สร้าง migration เพื่อให้ EF Core สร้าง table จริงในฐานข้อมูลตามที่นิยามไว้ในหัวข้อ 17:

ตัวอย่างปุ่มลบใน list (Read) ที่เชื่อมกับฐานข้อมูลจริง:

public class ProductsModel : PageModel
{
    private readonly AppDbContext _db;
    public ProductsModel(AppDbContext db) { _db = db; }

    public List<Product> Products { get; set; } = new();

    public async Task OnGetAsync()
    {
        Products = await _db.Products.ToListAsync();
    }

    public async Task OnPostDeleteAsync(int id)
    {
        var product = await _db.Products.FindAsync(id);
        if (product is not null)
        {
            _db.Products.Remove(product);
            await _db.SaveChangesAsync();
        }
    }
}
คำว่า async/await ที่เพิ่งเห็น: เป็นวิธีบอกว่า "ระหว่างรอฐานข้อมูลตอบกลับ ให้เว็บแอปไปรับ request อื่นก่อนได้ ไม่ต้องหยุดรอเฉยๆ" เป็น pattern มาตรฐานที่ใช้ทุกครั้งที่คุยกับฐานข้อมูลใน ASP.NET Core แค่จำไว้ก่อนว่าต้องมีคำนี้คู่กับ method ที่เกี่ยวกับฐานข้อมูลเสมอ
ลองทำ: ทำให้โปรเจกต์ฝึกมีครบ 4 อย่าง (Create, Read, Update, Delete) ผ่านหน้าเว็บจริง ต่อกับฐานข้อมูล SQLite ที่ตั้งไว้ ใช้เวลาหัวข้อนี้นานกว่าหัวข้ออื่น เพราะเป็นการรวมทุกอย่างเข้าด้วยกัน

@* Pages/Products/Detail.cshtml *@
@page "{id:int}"
@model DetailModel
public class DetailModel : PageModel
{
    private readonly AppDbContext _db;
    public DetailModel(AppDbContext db) { _db = db; }

    public Product? Product { get; set; }

    public async Task<IActionResult> OnGetAsync(int id)
    {
        Product = await _db.Products.FindAsync(id);
        if (Product is null)
        {
            return NotFound();
        }
        return Page();
    }
}

@page "{id:int}" — บอกว่า URL ของหน้านี้ต้องมีตัวเลขต่อท้าย เช่น /Products/Detail/5 ส่วน :int คือการบังคับว่าค่านั้นต้องเป็นตัวเลขเท่านั้น ถ้าใส่ตัวอักษรมาจะไม่ match route นี้เลย

@if (TempData["Message"] != null)

TempData คือที่เก็บข้อมูลชั่วคราวที่ "อยู่ข้ามหน้า" ได้ 1 ครั้ง (ต่างจากตัวแปรปกติที่หายไปทันที ที่ redirect) เหมาะกับข้อความแจ้งเตือนแบบนี้โดยเฉพาะ

ข้อผิดพลาดที่เจอบ่อย: ลืมเช็ค Product is null หลัง FindAsync แล้วเอา Product ไปใช้ต่อทันที ถ้า id ที่ส่งมาไม่มีอยู่จริงในฐานข้อมูล จะได้ null กลับมา แล้วโปรแกรม error ทันทีที่พยายามอ่าน property ของ null (เรียกว่า NullReferenceException) ต้องเช็คก่อนเสมอ

ในหน้า list สินค้า เพิ่มลิงก์ไปหน้า Detail พร้อมส่ง id: 
@foreach (var product in Model.Products)

MODULE 3ฟอร์มและ Validation แบบเต็มรูปแบบ
4-5 วัน
  • Data Annotation — attribute สำหรับกำหนดกฎ validation บน model
  • แสดงข้อความ error ใต้แต่ละ field
  • validation ฝั่ง client (ก่อน submit) แบบไม่ต้องเขียน JavaScript เอง
กำหนดกฎ validation บน Model
public class Product
{
    public int Id { get; set; }

    [Required(ErrorMessage = "กรุณากรอกชื่อสินค้า")]
    [StringLength(100, ErrorMessage = "ชื่อสินค้าต้องไม่เกิน 100 ตัวอักษร")]
    public string Name { get; set; } = string.Empty;

    [Range(1, 1000000, ErrorMessage = "ราคาต้องอยู่ระหว่าง 1 ถึง 1,000,000")]
    public decimal Price { get; set; }

    [EmailAddress(ErrorMessage = "รูปแบบอีเมลไม่ถูกต้อง")]
    public string? SupplierEmail { get; set; }
}

[Required], [StringLength], [Range], [EmailAddress] คือ Data Annotation attribute ที่กำหนดกฎไว้ที่ตัว Model โดยตรง ASP.NET Core จะเช็คให้อัตโนมัติทั้งฝั่ง server และช่วยแสดงข้อความเตือนฝั่ง client ด้วย โดยไม่ต้องเขียนเช็คเองทีละ field

แสดงข้อความ error ในฟอร์ม
<form method="post">
    <label>ชื่อสินค้า</label>
    <input asp-for="NewProduct.Name" />
    <span asp-validation-for="NewProduct.Name" class="error-text"></span>

    <label>ราคา</label>
    <input asp-for="NewProduct.Price" />
    <span asp-validation-for="NewProduct.Price" class="error-text"></span>

    <button type="submit">บันทึก</button>
</form>

@section Scripts {
    <partial name="_ValidationScriptsPartial" />
}

asp-validation-for — Tag Helper ที่แสดงข้อความ error ของ field นั้นโดยอัตโนมัติ ถ้า validation ไม่ผ่าน (ดึงข้อความจาก ErrorMessage ที่ตั้งไว้บน Model)

_ValidationScriptsPartial — ไฟล์สำเร็จรูปที่มากับ template อยู่แล้ว เปิดใช้งาน validation แบบ real-time ก่อน submit (client-side validation) โดยไม่ต้องเขียน JavaScript เอง

ข้อผิดพลาดที่เจอบ่อย: เขียน Data Annotation บน Model แล้วลืมเช็ค ModelState.IsValid ใน OnPost ทำให้ข้อมูลที่ไม่ผ่านกฎ validation ถูกบันทึกลงฐานข้อมูล ไปแล้วโดยไม่รู้ตัว (client-side validation ป้องกันได้แค่กรณีปกติ แต่ป้องกันคนตั้งใจ bypass ไม่ได้ ต้องเช็คฝั่ง server เสมอ)
แบบฝึกหัด: เพิ่ม Data Annotation ให้ Model Product ครบทุก field ที่เหมาะสม แล้วทดสอบ submit ฟอร์มโดยเว้นช่องชื่อว่างไว้ ดูว่าข้อความ error แสดงถูกต้องไหม
ดูเฉลย
public class Product
{
    public int Id { get; set; }

    [Required(ErrorMessage = "กรุณากรอกชื่อสินค้า")]
    [StringLength(100)]
    public string Name { get; set; } = string.Empty;

    [Range(1, 1000000, ErrorMessage = "ราคาต้องมากกว่า 0")]

MODULE 4ข้อมูลที่เชื่อมกันหลาย Table (Relationship)
5-6 วัน
ทำไมต้องมี: ระบบจริงแทบไม่มี table เดียวโดดๆ เช่น 1 ออเดอร์มีสินค้าหลายชิ้น 1 ลูกค้ามีหลายออเดอร์ ต้องรู้วิธีออกแบบและ query ข้อมูลที่เชื่อมกันแบบนี้
  • ความสัมพันธ์แบบ one-to-many (หนึ่งลูกค้า มีหลายออเดอร์)
  • Foreign Key — คีย์ที่เชื่อมสอง table เข้าด้วยกัน
  • ดึงข้อมูลที่เชื่อมกันมาแสดงพร้อมกันด้วย Include
ออกแบบ Model ที่เชื่อมกัน
public class Customer
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;

    // 1 ลูกค้า มีได้หลายออเดอร์
    public List<Order> Orders { get; set; } = new();
}

public class Order
{
    public int Id { get; set; }
    public decimal TotalAmount { get; set; }

    // Foreign Key — บอกว่าออเดอร์นี้เป็นของลูกค้าคนไหน
    public int CustomerId { get; set; }
    public Customer? Customer { get; set; }
}

CustomerId คือ Foreign Key เก็บ id ของลูกค้าเจ้าของออเดอร์นี้ ส่วน Customer? Customer คือ "navigation property" ที่ทำให้เขียนโค้ดเข้าถึงข้อมูลลูกค้าจากออเดอร์ได้โดยตรง (เช่น order.Customer.Name) โดย EF Core จัดการ join table ให้เองเบื้องหลัง

ดึงข้อมูลที่เชื่อมกันมาแสดงพร้อมกัน
// ถ้าไม่ใช้ Include, order.Customer จะเป็น null เสมอ
var orders = await _db.Orders
    .Include(o => o.Customer)
    .ToListAsync();

foreach (var order in orders)
{
    Console.WriteLine(order.Customer.Name + " — " + order.TotalAmount);
}

.Include(o => o.Customer) คือการบอก EF Core ว่า "ตอน query Order ให้ดึงข้อมูล Customer ที่เกี่ยวข้องมาด้วยเลย" ถ้าลืมเขียนบรรทัดนี้ order.Customer จะเป็น null เสมอ แม้ในฐานข้อมูลจะมีข้อมูลลูกค้าจริงก็ตาม เพราะ EF Core ไม่ดึงข้อมูลที่เชื่อมกันมาให้อัตโนมัติ ต้องสั่งชัดเจนทุกครั้ง

ข้อผิดพลาดที่เจอบ่อยที่สุดในหัวข้อนี้: ลืม Include แล้วงงว่าทำไมข้อมูลที่เชื่อมกัน เป็น null ตลอด ทั้งที่ query สำเร็จไม่มี error ใดๆ เป็นปัญหาที่ทำให้เสียเวลา debug บ่อยที่สุดในหัวข้อนี้
แบบฝึกหัด: เพิ่ม Model Customer และผูกกับ Order ตามตัวอย่าง สร้าง migration ใหม่ แล้วทำหน้า list ออเดอร์ที่แสดงชื่อลูกค้าเจ้าของแต่ละออเดอร์ด้วย
ดูเฉลย
เพิ่ม DbSet ให้ AppDbContext ก่อน: 
public DbSet<Customer> Customers => Set<Customer>();
สร้าง migration: 
dotnet ef migrations add AddCustomerOrderRelation
dotnet ef database update
ใน PageModel ของหน้า list ออเดอร์ ต้องมี Include เสมอ ไม่งั้น Customer จะเป็น null: 
public async Task OnGetAsync()
{
    Orders = await _db.Orders.Include(o => o.Customer).ToListAsync();
}
แล้วในหน้า .cshtml แสดงด้วย @order.Customer?.Name (ใส่ ? กันไว้เผื่อกรณี ลืม Include หรือข้อมูลลูกค้าถูกลบไปแล้วจริงๆ จะได้ไม่ error ทันที)
MODULE 5ระบบ Login (Authentication / Authorization)
5-6 วัน
  • ความต่างระหว่าง Authentication (ยืนยันตัวตน) กับ Authorization (สิทธิ์การเข้าถึง)
  • ASP.NET Core Identity — ระบบ login สำเร็จรูปที่มากับ framework
  • จำกัดการเข้าถึงหน้าด้วย [Authorize]
Authentication vs Authorization: Authentication คือ "คุณเป็นใคร" (ล็อกอินสำเร็จหรือยัง) Authorization คือ "คุณทำอะไรได้บ้าง" (มีสิทธิ์เข้าหน้านี้ไหม) สองอย่างนี้แยกกันชัดเจน ล็อกอินสำเร็จ (authenticated) ไม่ได้แปลว่าเข้าได้ทุกหน้าเสมอไป
เพิ่ม ASP.NET Core Identity เข้าโปรเจกต์
dotnet add package Microsoft.AspNetCore.Identity.EntityFrameworkCore
// Program.cs
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlite("Data Source=app.db"));

builder.Services.AddDefaultIdentity<IdentityUser>(options =>
    options.SignIn.RequireConfirmedAccount = false)
    .AddEntityFrameworkStores<AppDbContext>();

// ...

app.UseAuthentication();   // ต้องมาก่อน UseAuthorization เสมอ
app.UseAuthorization();

AddDefaultIdentity<IdentityUser> — เปิดใช้ระบบ login สำเร็จรูปที่มีหน้า register/login/logout ให้พร้อมใช้ทันที ไม่ต้องเขียนเองตั้งแต่ศูนย์

app.UseAuthentication() ต้องอยู่ ก่อน app.UseAuthorization() เสมอใน middleware pipeline เพราะต้องรู้ก่อนว่า "ใครเข้ามา" ถึงจะเช็คต่อได้ว่า "เข้าได้ไหม" สลับลำดับผิดจะทำให้ authorization ทำงานไม่ถูกต้อง

จำกัดการเข้าถึงหน้า
[Authorize]
public class AdminModel : PageModel
{
    // เฉพาะคนที่ login แล้วเท่านั้นที่เข้าหน้านี้ได้
    // ถ้ายังไม่ login จะถูก redirect ไปหน้า login อัตโนมัติ
}
[Authorize(Roles = "Manager")]
public class ReportsModel : PageModel
{
    // เฉพาะคนที่มี role "Manager" เท่านั้น
}
แบบฝึกหัด: เพิ่ม Identity เข้าโปรเจกต์ฝึก ทดลอง register ผู้ใช้ใหม่ 1 คน login เข้าใช้งาน แล้วใส่ [Authorize] ที่หน้า Create สินค้า ทดสอบว่าคนที่ยังไม่ login เข้าหน้านั้นไม่ได้จริง
ดูเฉลย
ติดตั้งและตั้งค่าตามตัวอย่างในเนื้อหา จากนั้นเปิด URL /Identity/Account/Register (หน้านี้มาให้พร้อมกับ AddDefaultIdentity โดยไม่ต้องสร้างเอง) กรอกอีเมลและรหัสผ่านเพื่อสมัคร จากนั้นเพิ่ม attribute บนไฟล์ Create.cshtml.cs: 
[Authorize]
public class CreateModel : PageModel
{
    // ...
}
ทดสอบโดยเปิด browser แบบ Incognito/Private (เพื่อไม่ให้มี session login เดิมค้างอยู่) แล้วพิมพ์ URL ของหน้า Create ตรงๆ ควรถูก redirect ไปหน้า login อัตโนมัติ ถ้ายังเข้าได้ตรงๆ แปลว่าลืมใส่ app.UseAuthentication() ก่อน app.UseAuthorization() ใน Program.cs
MODULE 6Blazor — การจัดการ State ระหว่าง Component
4-5 วัน
  • ส่ง event จาก component ลูกกลับไปหา component แม่ (EventCallback)
  • แชร์ค่าข้ามหลาย component โดยไม่ต้องส่งผ่าน props ทีละชั้น (Cascading Parameter)
  • StateHasChanged — สั่งให้ UI วาดใหม่ด้วยตัวเอง
ส่ง event จากลูกกลับไปแม่
@* ProductRow.razor — component ลูก *@
<tr>
    <td>@Product.Name</td>
    <td><button @onclick="HandleDelete">ลบ</button></td>
</tr>

@code {
    [Parameter] public Product Product { get; set; } = default!;
    [Parameter] public EventCallback<int> OnDelete { get; set; }

    private async Task HandleDelete()
    {
        await OnDelete.InvokeAsync(Product.Id);
    }
}
@* ProductList.razor — component แม่ *@
@foreach (var product in products)
{
    <ProductRow Product="product" OnDelete="HandleProductDeleted" />
}

@code {
    private async Task HandleProductDeleted(int productId)
    {
        var product = products.First(p => p.Id == productId);
        products.Remove(product);
        await Db.SaveChangesAsync();
    }
}

[Parameter] public EventCallback<int> OnDelete — ประกาศว่า component ลูกนี้ "ยิง event กลับไป" ให้ component แม่ฟังได้ พร้อมส่งค่า int (ในที่นี้คือ id) กลับไปด้วย เทียบได้กับการส่ง callback function เข้าไปเป็น props

Cascading Parameter — แชร์ค่าข้ามหลายชั้นโดยไม่ต้องส่งทีละชั้น
@* App.razor หรือ Layout หลัก *>
<CascadingValue Value="currentUser">
    @Body
</CascadingValue>

@code {
    private string currentUser = "Somchai";
}
@* component ลูกลึกแค่ไหนก็รับได้ โดยไม่ต้องส่งผ่าน parameter ทีละชั้น *>
@code {
    [CascadingParameter] public string CurrentUser { get; set; } = "";
}

มีประโยชน์มากเมื่อค่านั้นต้องใช้ในหลาย component ที่ซ้อนกันลึกมาก เช่น ข้อมูลผู้ใช้ที่ login อยู่ โดยไม่ต้องส่งผ่าน parameter ทีละชั้นซึ่งจะรกและแก้ยากถ้ามีหลายชั้นมาก

ข้อผิดพลาดที่เจอบ่อย: แก้ค่าตัวแปรใน method ที่ไม่ได้ผูกกับ event ของ Blazor โดยตรง (เช่น callback จาก JavaScript หรือ Timer) แล้ว UI ไม่อัพเดทให้ ต้องเรียก StateHasChanged() เองเพื่อบอก Blazor ว่า "ค่าที่แสดงผลเปลี่ยนแล้ว ให้วาดใหม่"
แบบฝึกหัด: แปลงหน้า list สินค้าให้แยกเป็น component ย่อย ProductRow ตามตัวอย่าง พร้อมปุ่มลบที่ยิง event กลับไปหา component แม่
ดูเฉลย
สร้างไฟล์ ProductRow.razor และ ProductList.razor ตามตัวอย่างในเนื้อหาทุกประการ จุดที่มักพลาดบ่อยคือ ลืมประกาศ [Parameter] หน้า property ที่รับค่าจากแม่: 
@code {
    [Parameter] public Product Product { get; set; } = default!;
    [Parameter] public EventCallback<int> OnDelete { get; set; }
}
ถ้าลืม [Parameter] จะได้ error ตอน compile ทันทีว่า attribute ไม่ตรงกับที่ component แม่ส่งมา ทดสอบโดยกดปุ่มลบที่แถวใดแถวหนึ่ง สินค้าแถวนั้นควรหายไปจากหน้าจอทันทีโดยไม่ reload หน้าเลย
MODULE 7จัดการ Error และบันทึก Log
2-3 วัน
  • try/catch — ดักจับ error ไม่ให้โปรแกรมล่มทั้งระบบ
  • ILogger — ระบบบันทึก log มาตรฐานของ ASP.NET Core
  • หน้า error ที่เป็นมิตรกับผู้ใช้ (ไม่โชว์รายละเอียดทางเทคนิคให้ผู้ใช้ทั่วไปเห็น)
try/catch พื้นฐาน
public async Task<IActionResult> OnPostAsync()
{
    try
    {
        _db.Products.Add(NewProduct);
        await _db.SaveChangesAsync();
        return RedirectToPage("Index");
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "บันทึกสินค้าไม่สำเร็จ");
        ModelState.AddModelError("", "เกิดข้อผิดพลาด กรุณาลองใหม่อีกครั้ง");
        return Page();
    }
}

โค้ดใน try { } คือส่วนที่อาจพังได้ ถ้าพังจริงจะกระโดดไปทำใน catch { } ทันทีแทนที่จะทำให้ทั้งโปรแกรมล่ม เราจับ error ไว้ บันทึก log แล้วแสดงข้อความที่เข้าใจง่ายให้ผู้ใช้แทน

ILogger — inject เข้ามาใช้เหมือน service อื่น
public class ProductsModel : PageModel
{
    private readonly ILogger<ProductsModel> _logger;

    public ProductsModel(ILogger<ProductsModel> logger)
    {
        _logger = logger;
    }

    public void OnGet()
    {
        _logger.LogInformation("มีคนเปิดหน้า Products ตอน {time}", DateTime.Now);
    }
}

ระดับของ log มีหลายแบบ: LogInformation (ข้อมูลทั่วไป), LogWarning (สิ่งผิดปกติแต่ไม่ร้ายแรง), LogError (error จริง) เลือกใช้ตามความรุนแรงของเหตุการณ์

แบบฝึกหัด: เพิ่ม try/catch ในทุก OnPost ที่บันทึกข้อมูลลงฐานข้อมูลในโปรเจกต์ฝึก พร้อม log error เมื่อเกิดปัญหา
ดูเฉลย

Q'dotnet' is not recognized as a command / command not found
สาเหตุ

.NET SDK ยังไม่ได้ติดตั้ง หรือติดตั้งแล้วแต่ terminal ยังไม่รู้จัก path เพราะเปิด terminal ค้างไว้ก่อนติดตั้ง

วิธีแก้

โหลด SDK จาก dotnet.microsoft.com/download ติดตั้งให้เสร็จ แล้วปิด terminal เดิมและเปิดใหม่ (สำคัญมาก หลายคนพลาดตรงนี้ ลืมปิด-เปิดใหม่แล้วคิดว่าติดตั้งไม่สำเร็จ)

QAddress already in use / port ถูกใช้งานอยู่แล้ว
สาเหตุ

มี terminal เก่าที่รัน dotnet run/watch ค้างอยู่จากรอบก่อน ยังไม่ได้ปิด

วิธีแก้

หา terminal เก่าที่ยังรันค้างอยู่ กด Ctrl+C เพื่อหยุด หรือปิดหน้าต่าง terminal นั้นทิ้งไปเลย แล้วค่อยรันใหม่ในหน้าต่างเดียว

Qเปิด URL แล้วเจอ "Your connection is not private"
สาเหตุ

certificate สำหรับพัฒนา (development HTTPS certificate) ยังไม่ได้รับความเชื่อถือจากเครื่อง

วิธีแก้

ลองใช้ URL แบบ http (port 5000) แทน https (port 5001) ไปก่อนสำหรับการฝึก หรือรันคำสั่ง dotnet dev-certs https --trust เพื่อให้เครื่องเชื่อถือ certificate นี้

Error ตอนเขียน C# พื้นฐาน
Qerror CS1002: ; expected
สาเหตุ

ลืมใส่เครื่องหมาย ; ท้ายบรรทัดคำสั่ง เป็น error ที่พบบ่อยที่สุดของคนเริ่มเขียน C#

วิธีแก้

เช็คบรรทัดที่ error บอก (เลขบรรทัดมักตรงหรือใกล้เคียงจุดที่ลืมจริง) เติม ; ท้ายบรรทัดนั้น

Qerror CS0103: The name 'x' does not exist in the current context
สาเหตุ

ใช้ตัวแปรที่ยังไม่ได้ประกาศ หรือสะกดชื่อตัวแปรผิด (พิมพ์ใหญ่-เล็กไม่ตรงกันก็นับว่าคนละชื่อ เช่น Age กับ age คือคนละตัวแปรกันใน C#)

วิธีแก้

เช็คว่าประกาศตัวแปรนี้ไว้แล้วหรือยัง (มีบรรทัด int age = ... อยู่ก่อนบรรทัดที่ error ไหม) และเช็คตัวสะกดให้ตรงกันทุกตัวอักษรรวมถึงตัวพิมพ์ใหญ่-เล็ก

QUnhandled exception: System.FormatException ตอนใช้ int.Parse
สาเหตุ

พยายามแปลงข้อความที่ไม่ใช่ตัวเลขให้เป็น int เช่น int.Parse("abc") หรือข้อความมีช่องว่าง/ อักขระแปลกปนอยู่

วิธีแก้

ใช้ int.TryParse แทน ซึ่งไม่ throw error แต่คืนค่า true/false บอกว่าแปลงสำเร็จไหม:

if (int.TryParse(text, out int number))
{
    Console.WriteLine(number);
}
else
{
    Console.WriteLine("ไม่ใช่ตัวเลข");
}

เช็ค null ทุกครั้งหลัง query ข้อมูลที่อาจไม่เจอ ก่อนเอาไปใช้งานต่อเสมอ

Qโปรแกรมค้าง (deadlock) ตอนเรียก method แบบ async
สาเหตุ

เรียก async method แบบผิดวิธี เช่น ใช้ .Result หรือ .Wait() แทนที่จะใช้ await ทำให้ thread รอกันเองแบบวนไม่จบ

วิธีแก้
// ผิด — อาจทำให้ deadlock
var order = GetOrderAsync(id).Result;

// ถูก — ใช้ await เสมอ
var order = await GetOrderAsync(id);

กฎง่ายๆ: ถ้า method เป็น async ให้ใช้ await เรียกเสมอ อย่าใช้ .Result หรือ .Wait()
