Learning Plan — ASP.NET Core Basic แบบ Step by Step ผ่าน VS Code

แผนการเรียนรู้ตั้งแต่พื้นฐาน C# ไปจนถึงสร้าง web app เต็มรูปแบบด้วย Razor Pages และ Blazor ครอบคลุม full stack ภายใน ASP.NET Core ทั้งหมด (ไม่ต้องใช้ JavaScript framework แยก)

เป้าหมายจบแผน
เข้าใจ syntax C# พื้นฐาน + โครงสร้าง ASP.NET Core + สร้าง web app เต็มรูปแบบ (Razor Pages และ Blazor) ต่อ SQL Server ได้เอง — ครบ full stack ภายใน ASP.NET Core โดยไม่ต้องใช้ JavaScript framework แยก
เครื่องมือ
VS Code + C# Dev Kit + .NET SDK เท่านั้น (ตาม setup plan ที่ทำไปก่อนหน้านี้)
ระยะเวลารวมโดยประมาณ
5-7 สัปดาห์ ถ้าเรียนวันละ 1-1.5 ชั่วโมง (ปรับตามเวลาว่างจริงได้)
สมมติฐาน
มีพื้นฐานเขียนโปรแกรมมาก่อน (RPG/RDML) แต่ยังไม่เคยเขียน C# หรือ OOP มาก่อน
ศัพท์เฉพาะทั้งหมด Phase 0 — ปรับความคุ้นเคย Phase 1 — C# พื้นฐาน Phase 2 — OOP ใน C# Phase 3 — โครงสร้าง ASP.NET Core Phase 4 — Routing และ Controller Phase 5 — Async/Await Phase 6 — Model และ EF Core Phase 7 — โปรเจกต์จริง CRUD Phase 8 — Debug และ Test ใน VS Code Phase 9 — ก้าวต่อไป Phase 10 — Razor Pages พื้นฐาน Phase 11 — ฟอร์มและ validation Phase 12 — CRUD เต็มรูปแบบด้วย EF Core Phase 13 — Blazor แบบ real-time
GLOSSARYศัพท์เฉพาะของ ASP.NET Core ที่ต้องรู้จัก

รวมคำศัพท์ที่จะเจอบ่อยที่สุดตลอดแผนการเรียนนี้ แนะนำให้กลับมาเปิดดูทุกครั้งที่เจอคำที่ไม่คุ้น แทนที่จะข้ามไป เพราะคำเหล่านี้ปรากฏซ้ำตลอดทุก phase

ศัพท์ความหมาย
SDK (Software Development Kit)ชุดเครื่องมือที่ใช้ compile และรันโค้ด .NET ต้องติดตั้งแยกจาก VS Code เสมอ (VS Code เป็นแค่ editor ไม่มี SDK มาให้)
NuGetระบบจัดการ package/library ของ .NET เทียบเท่า npm ของ JavaScript หรือ pip ของ Python ใช้คำสั่ง dotnet add package เพื่อติดตั้ง
Solution (.sln)ไฟล์ที่รวมหลายโปรเจกต์เข้าด้วยกัน เช่น โปรเจกต์ API กับโปรเจกต์ Test อยู่ใน solution เดียวกัน ไม่บังคับต้องมีถ้าทำโปรเจกต์เดียว
Project (.csproj)ไฟล์ตั้งค่าของแต่ละโปรเจกต์ บอกว่าใช้ .NET version ไหน มี package/dependency อะไรบ้าง คล้าย package.json ของ Node.js
Program.csไฟล์จุดเริ่มต้นของโปรแกรม (entry point) ทุกอย่างเริ่มรันจากไฟล์นี้เสมอ
appsettings.jsonไฟล์เก็บค่า configuration เช่น connection string ของ database, API key ต่างๆ อ่านค่าได้จากทุกที่ในโปรเจกต์ผ่าน DI
launchSettings.jsonไฟล์ตั้งค่าเฉพาะตอน develop เช่น port ที่ใช้รัน, environment variable อยู่ในโฟลเดอร์ Properties/ ไม่ถูก deploy ขึ้น production
Kestrelweb server ที่มากับ ASP.NET Core เองใช้รับ request จริง ไม่ต้องติดตั้ง web server แยก (ต่างจาก PHP ที่มักต้องพึ่ง Apache/Nginx)
Middlewareโค้ดที่ทำงานคั่นระหว่างทางของทุก request ก่อนถึงปลายทาง เช่น เช็ค login, log การเข้าใช้งาน เรียงต่อกันเป็น "pipeline"
Dependency Injection (DI)แนวคิดที่ไม่ต้อง new object เองในทุกที่ที่ใช้ แต่ "ขอ" จาก framework ผ่าน constructor แทน ช่วยให้เปลี่ยนการ implement ได้ง่ายและ test ได้สะดวกขึ้น
Serviceclass ที่ถูกลงทะเบียนไว้ให้ DI จัดการ (ผ่าน builder.Services.Add...) แล้วเรียกใช้ผ่าน constructor ที่ไหนก็ได้ในโปรเจกต์
Controllerclass ที่รับ HTTP request เข้ามาแล้วตัดสินใจว่าจะทำอะไรต่อ (เทียบได้กับ RDML function ที่รับ input แล้วประมวลผล)
Action / Action methodmethod หนึ่งตัวภายใน Controller ที่ผูกกับ 1 endpoint เช่น GetById, Create
Routeเส้นทาง URL ที่ใช้เข้าถึง endpoint นั้นๆ กำหนดผ่าน attribute [Route], [HttpGet]
Modelclass ที่ใช้แทนโครงสร้างข้อมูล เช่น Order, Product มักตรงกับ 1 table ใน database
DTO (Data Transfer Object)class ที่ใช้รับ/ส่งข้อมูลระหว่าง client กับ server โดยเฉพาะ แยกจาก Model เพื่อไม่ให้ client เห็นหรือแก้ field ที่ไม่ควรแตะ (เช่น password hash)
DbContextclass ตัวแทนของการเชื่อมต่อ database ทั้งหมด เป็นจุดเดียวที่ query หรือบันทึกข้อมูลผ่าน EF Core
DbSet<T>property ภายใน DbContext ที่แทน 1 table เช่น DbSet<Order> Orders แทน table ชื่อ Orders
Migrationไฟล์ที่ EF Core generate ให้อัตโนมัติ บันทึกว่า table structure เปลี่ยนแปลงอย่างไรบ้าง ใช้สร้าง/แก้ table จริงใน database
LINQ (Language Integrated Query)วิธีเขียน query ข้อมูล (filter, sort, group) ด้วย syntax C# โดยตรง แทนการเขียน SQL string เอง
Task<T>ตัวแทนของงานที่ "กำลังทำอยู่และจะเสร็จในอนาคต" ใช้คู่กับ async/await เสมอ
async / awaitคำสั่งบอกว่า method นี้ทำงานแบบไม่บล็อก thread หลักระหว่างรอ I/O (เช่น รอ database ตอบกลับ)
IActionResulttype ที่ Controller method มักจะ return แทนที่จะ return ข้อมูลตรงๆ ครอบทั้งสถานะ HTTP (200, 404) และข้อมูลไว้ด้วยกัน
Ok() / NotFound() / BadRequest()helper method ใน Controller ที่สร้าง HTTP response พร้อม status code ที่ถูกต้องให้อัตโนมัติ
Attributesyntax ที่เขียนในเครื่องหมาย [ ] เหนือ class หรือ method เพื่อกำหนดพฤติกรรมพิเศษ เช่น [HttpGet], [Route], [ApiController]
CORS (Cross-Origin Resource Sharing)กลไกอนุญาตให้ frontend ที่รันคนละ URL/port เรียก backend ได้ ต้องตั้งค่าเปิดเองถ้าแยก frontend/backend
Environment (Development/Production)ตัวแปรบอกว่าโปรแกรมกำลังรันในโหมดไหน มีผลต่อ error message ที่แสดง (Development เห็น error ละเอียด, Production ซ่อนรายละเอียดเพื่อความปลอดภัย)
xUnitlibrary สำหรับเขียน unit test ที่นิยมที่สุดใน .NET ปัจจุบัน ใช้ attribute [Fact] กำหนดว่า method ไหนคือ test
— ศัพท์ฝั่ง UI (Razor Pages / Blazor) —
Razor Pagesวิธีสร้างหน้าเว็บใน ASP.NET Core โดยเขียน HTML ปนกับ C# ในไฟล์ .cshtml คู่กับไฟล์ logic .cshtml.cs
PageModelclass ที่เก็บ logic ของ Razor Page หนึ่งหน้า (อยู่ในไฟล์ .cshtml.cs) มี method อย่าง OnGet, OnPost ให้ override
Tag Helperattribute พิเศษในไฟล์ .cshtml ที่ขึ้นต้นด้วย asp- เช่น asp-for, asp-page-handler ใช้ผูก HTML เข้ากับ C# โดยไม่ต้องเขียน JavaScript
[BindProperty]attribute ที่บอกว่า property นี้จะรับค่าจากฟอร์มที่ submit เข้ามาโดยอัตโนมัติ
Blazorเฟรมเวิร์กสร้าง UI แบบ component ด้วย C# ล้วน (ไม่ใช้ JavaScript) เหมาะกับ UI ที่ต้องโต้ตอบแบบ real-time
Razor Component (.razor)ไฟล์ของ Blazor ที่รวม HTML และ C# ไว้ในไฟล์เดียว เทียบได้กับ Component ของ React แต่เขียนด้วย C#
@@code { }ส่วนของไฟล์ .razor ที่เก็บ property และ method (คล้ายส่วน logic ของ component)
@@bindผูกค่าตัวแปรเข้ากับ input แบบสองทางอัตโนมัติ ไม่ต้องเขียน event handler เอง
@@injectวิธี inject service (DI) เข้ามาใช้ในไฟล์ .razor โดยตรง
KICKOFFเริ่มสร้างโปรเจกต์แรกจริง (ทำตามทีละขั้นในเครื่องตัวเอง)

ก่อนเริ่ม Phase 0 อย่างเป็นทางการ ให้ลงมือสร้างโปรเจกต์จริงตามนี้ก่อน เพื่อให้มีของจริงไว้ทดลองระหว่างเรียนแต่ละ phase

1เช็คว่า .NET SDK พร้อมหรือยัง

เปิด terminal ใน VS Code (กด Ctrl+`) แล้วรัน:

dotnet --version

ควรเห็น: เลขเวอร์ชันแบบ 8.0.x หรือ 9.0.x (ขึ้นต้นด้วย 8 หรือมากกว่า)

ถ้าขึ้น error ว่าไม่รู้จักคำสั่ง dotnet แปลว่ายังไม่ได้ติดตั้ง SDK ต้องโหลดจาก dotnet.microsoft.com/download เลือก LTS version แล้วติดตั้งตาม installer ปกติก่อน

2เช็ค extension ใน VS Code

เปิด Extensions panel (Ctrl+Shift+X) พิมพ์ค้นหา C# Dev Kit — ถ้ายังไม่มีให้กด Install (publisher ต้องเป็น Microsoft)

3สร้างโปรเจกต์จริง

เลือก folder ที่จะเก็บงานฝึก (แนะนำแยกโฟลเดอร์ใหม่ ไม่ปนกับงานจริง) แล้วรัน:

mkdir learn-aspnetcore
cd learn-aspnetcore
dotnet new webapi -o FirstApi
cd FirstApi
code .

อธิบายทีละคำสั่ง:

dotnet new webapi -o FirstApi — สั่งให้ .NET สร้างโปรเจกต์ตาม template ชื่อ webapi (มี Controller ตัวอย่างมาให้แล้ว) ใส่ในโฟลเดอร์ชื่อ FirstApi

code . — เปิดโฟลเดอร์ปัจจุบันด้วย VS Code (จุดหมายถึง "โฟลเดอร์นี้")

เช็คก่อนไปต่อ Phase 0
  • dotnet --version ขึ้นเลขเวอร์ชันได้ปกติ ไม่ error
  • สร้างโปรเจกต์ FirstApi สำเร็จ ไม่มี error ระหว่างสร้าง
  • VS Code เปิดขึ้นมาเจอไฟล์ในโปรเจกต์ (Program.cs, Controllers/, appsettings.json ฯลฯ)
หมายเหตุ: ขั้นตอนนี้ต้องรันบนเครื่องจริงเอง เพราะเป็นคำสั่งที่ทำงานกับ environment ของแต่ละเครื่อง ถ้าเจอ error ระหว่างทำ ให้บันทึกข้อความ error ไว้เทียบกับ troubleshooting ทั่วไป หรือค้นหาข้อความ error นั้นตรงๆ ก่อนไปต่อ
PHASE 0ปรับความคุ้นเคยกับภาษา typed แบบใหม่
~1 วัน

ก่อนเริ่มเขียน C# จริง ควรเข้าใจว่า C# ต่างจาก RPG/RDML ตรงไหนบ้างในระดับแนวคิด เพื่อไม่ให้งงตอนเจอ syntax แปลกตา

  • C# เป็นภาษา object-oriented เต็มรูปแบบ ทุกอย่างอยู่ใน class ไม่มี "โปรแกรมลอยๆ" แบบ RPG
  • ใช้เครื่องหมาย { } กำหนดขอบเขตของ block แทนการเยื้อง column แบบ fixed-format RPG
  • ทุกบรรทัดคำสั่งจบด้วย ; เสมอ
  • C# เป็น strongly-typed เหมือน RPG (ประกาศ type ชัดเจน) แต่ syntax การประกาศต่างกัน
VS Code tip: เปิด Command Palette (Ctrl+Shift+P) พิมพ์ ".NET: New Project" จะช่วยสร้างโปรเจกต์ผ่าน UI แทนการพิมพ์คำสั่งเองได้ ถ้ายังไม่ชินกับ terminal
PHASE 1C# พื้นฐาน — ตัวแปร, type, control flow
3-4 วัน
  • ประกาศตัวแปรและ type พื้นฐาน (int, string, decimal, bool, DateTime)
  • if/else, switch, for, foreach, while
  • function/method และการส่งค่า parameter
  • nullable type (string?) — concept ที่ไม่มีใน RPG แต่สำคัญมากใน C#
ตัวอย่าง syntax
// ประกาศตัวแปร ต้องระบุ type เสมอ (หรือใช้ var ให้ compiler เดา type ให้)
int quantity = 10;
decimal price = 25.50m;
string customerName = "Somchai";
bool isActive = true;
var total = quantity * price;   // var เดา type เป็น decimal จากค่าที่ assign

// nullable — บอกว่าตัวแปรนี้เป็น null ได้
string? note = null;

// method
decimal CalculateTotal(int qty, decimal unitPrice)
{
    return qty * unitPrice;
}

// control flow
if (quantity > 0)
{
    Console.WriteLine("มีสินค้า");
}
else
{
    Console.WriteLine("สินค้าหมด");
}

foreach (var item in orderList)
{
    Console.WriteLine(item.Name);
}
แบบฝึกหัด: เขียนโปรแกรม console เล็กๆ (ไม่ต้องมี web) คำนวณราคารวมสินค้าจาก list ที่กำหนดเอง แล้วลอง print ผลลัพธ์ผ่าน Console.WriteLine รันด้วย dotnet run
พร้อมไป phase ถัดไปเมื่อ
  • เขียน method รับ parameter และ return ค่าได้เองโดยไม่ต้องเปิดตัวอย่าง
  • เข้าใจความต่างระหว่าง string กับ string?
PHASE 2OOP ใน C# — class, interface, dependency injection เบื้องต้น
4-5 วัน

phase นี้สำคัญที่สุด เพราะ ASP.NET Core ทั้งเฟรมเวิร์กสร้างอยู่บนแนวคิด OOP หากข้ามส่วนนี้จะอ่านโค้ดจริงไม่เข้าใจเลย

  • class, property, constructor
  • interface และทำไมต้องมี (สัญญาว่า class ไหนต้องมี method อะไรบ้าง)
  • dependency injection (DI) เบื้องต้น — concept หลักที่ ASP.NET Core ใช้ทุกที่
ตัวอย่าง syntax
// class พร้อม property แบบสั้น (auto-property)
public class Order
{
    public int Id { get; set; }
    public string CustomerName { get; set; } = string.Empty;
    public decimal TotalAmount { get; set; }
}

// interface — กำหนดว่า class ที่ implement ต้องมี method นี้
public interface IOrderRepository
{
    Order? GetById(int id);
    void Add(Order order);
}

// class ที่ implement interface ข้างบน
public class OrderRepository : IOrderRepository
{
    public Order? GetById(int id)
    {
        // logic ค้นหาจริง
        return null;
    }

    public void Add(Order order)
    {
        // logic บันทึกจริง
    }
}

// dependency injection — รับ interface เข้ามาทาง constructor
// ASP.NET Core จะ "เสียบ" ของจริงให้เองตอน runtime
public class OrderService
{
    private readonly IOrderRepository _repository;

    public OrderService(IOrderRepository repository)
    {
        _repository = repository;
    }
}
แบบฝึกหัด: สร้าง interface ICustomerRepository พร้อม class ที่ implement แล้วลองสร้าง class อีกตัวที่รับ interface นี้เข้ามาทาง constructor เหมือนตัวอย่างข้างบน
VS Code tip: พิมพ์ ctor แล้วกด Tab ใน C# Dev Kit จะ generate constructor ให้อัตโนมัติ ไม่ต้องพิมพ์เองทั้งหมด
PHASE 3โครงสร้าง ASP.NET Core — Program.cs และ middleware
2-3 วัน
  • ไฟล์ Program.cs คือจุดเริ่มต้นของทุกโปรเจกต์
  • concept "middleware pipeline" — request วิ่งผ่านหลายชั้นก่อนถึง controller
  • การลงทะเบียน service สำหรับ DI ใน Program.cs
Program.cs ตัวอย่าง (โครงสร้างจริงที่เจอในทุกโปรเจกต์)
var builder = WebApplication.CreateBuilder(args);

// === ส่วนลงทะเบียน service สำหรับ DI ===
builder.Services.AddControllers();
builder.Services.AddScoped<IOrderRepository, OrderRepository>();

var app = builder.Build();

// === ส่วน middleware pipeline (ลำดับสำคัญมาก) ===
app.UseHttpsRedirection();
app.UseAuthorization();
app.MapControllers();

app.Run();

อ่านจากบนลงล่าง: ส่วนแรก "ลงทะเบียน" ว่าโปรเจกต์นี้มี service อะไรบ้าง ส่วนที่สองกำหนดว่า request ที่เข้ามาแต่ละอันจะถูกประมวลผลผ่านขั้นตอนอะไรบ้างก่อนถึงปลายทาง

อธิบายลึกทีละบรรทัด

WebApplication.CreateBuilder(args) — สร้างตัว "builder" ที่ใช้ตั้งค่าทุกอย่างของแอปก่อนเริ่มรันจริง รับ args จาก command line เผื่อมีคนสั่งรันพร้อม parameter พิเศษ

builder.Services.AddControllers() — บอก framework ว่าโปรเจกต์นี้ต้องการใช้ระบบ Controller (ถ้าไม่เรียกบรรทัดนี้ Controller ที่เขียนไว้จะไม่ถูกเปิดใช้งานเลย แม้ไฟล์จะมีอยู่ก็ตาม)

builder.Services.AddScoped<...>() — ลงทะเบียน service เข้าสู่ระบบ DI คำว่า "Scoped" หมายถึง object ตัวนี้จะถูกสร้างใหม่ 1 ครั้งต่อ 1 request (ต่างจาก "Singleton" ที่สร้างครั้งเดียวใช้ตลอดอายุโปรแกรม และ "Transient" ที่สร้างใหม่ทุกครั้งที่มีคนขอ)

builder.Build() — ปิดขั้นตอนตั้งค่า แล้วสร้างแอปตัวจริงออกมาเป็นตัวแปร app

app.UseHttpsRedirection() — middleware ที่บังคับให้ request ที่เข้ามาแบบ http ถูก redirect ไปเป็น https อัตโนมัติ เพื่อความปลอดภัย

app.UseAuthorization() — middleware ที่เช็คสิทธิ์การเข้าถึงก่อนอนุญาตให้ request ผ่านไปถึง Controller (ถ้ายังไม่ทำระบบ login ยังไม่มีผลอะไร แต่ต้องมีบรรทัดนี้ไว้เผื่ออนาคต)

app.MapControllers() — จุดสุดท้ายของ pipeline บอกว่า "ถ้า request ผ่าน middleware ทุกด่านมาถึงตรงนี้ ให้ส่งต่อไปยัง Controller ที่ตรงกับ route ที่ขอมา"

app.Run() — เริ่มรัน Kestrel web server จริงๆ และรอรับ request เข้ามาตลอดเวลา (บรรทัดนี้ทำให้โปรแกรม "ค้าง" รออยู่ ไม่ใช่รันเสร็จแล้วปิดตัวแบบ console app ทั่วไป)

แบบฝึกหัด: สร้างโปรเจกต์ด้วย dotnet new webapi แล้วเปิด Program.cs อ่านทุกบรรทัด ลองเพิ่ม app.Use(...) ตัวใหม่ที่ print ข้อความก่อนทุก request เพื่อดู middleware ทำงานจริง
PHASE 4Routing และ Controller
3-4 วัน
  • attribute routing ([Route], [HttpGet], [HttpPost])
  • รับค่าจาก URL, query string, และ request body
  • return type ต่างๆ (Ok, NotFound, BadRequest)
ความหมายของแต่ละ attribute

[ApiController] — บอก framework ว่า class นี้คือ Controller สำหรับ Web API โดยเฉพาะ เปิดใช้ feature เสริมอัตโนมัติ เช่น validate ข้อมูลที่รับเข้ามาให้เองโดยไม่ต้องเขียนเช็คเอง (automatic model validation)

[Route("api/orders")] — กำหนด "prefix" ของ URL ทั้งหมดใน Controller นี้ ทุก endpoint ข้างในจะขึ้นต้นด้วย /api/orders เสมอ

[HttpGet("{id}")] — บอกว่า method นี้ตอบสนองต่อ HTTP GET เท่านั้น และ {id} คือส่วนหนึ่งของ URL ที่จะถูกส่งเข้ามาเป็น parameter ชื่อ id โดยอัตโนมัติ (ต้องตั้งชื่อ parameter ใน method ให้ตรงกับชื่อใน { })

[FromQuery] — บอกว่าค่านี้มาจาก query string (ส่วนหลัง ? ใน URL) เช่น ?keyword=abc

[FromBody] — บอกว่าค่านี้มาจาก JSON ที่ส่งมาใน request body (ปกติใช้กับ POST/PUT) framework จะแปลง JSON เป็น C# object ให้อัตโนมัติตามโครงสร้างของ class ที่ระบุไว้

ตัวอย่าง Controller ครบทุกรูปแบบการรับค่า
[ApiController]
[Route("api/orders")]
public class OrdersController : ControllerBase
{
    // รับค่าจาก URL path เช่น /api/orders/5
    [HttpGet("{id}")]
    public IActionResult GetById(int id)
    {
        if (id <= 0) return BadRequest("id ต้องมากกว่า 0");
        return Ok(new { id, name = "ตัวอย่าง" });
    }

    // รับค่าจาก query string เช่น /api/orders/search?keyword=abc
    [HttpGet("search")]
    public IActionResult Search([FromQuery] string keyword)
    {
        return Ok($"ค้นหา: {keyword}");
    }

    // รับค่าจาก request body (JSON)
    [HttpPost]
    public IActionResult Create([FromBody] Order order)
    {
        return CreatedAtAction(nameof(GetById), new { id = order.Id }, order);
    }
}
แบบฝึกหัด: สร้าง controller ชื่อ ProductsController ที่มี endpoint GET (ดึงตาม id), GET (ค้นหาด้วย query), และ POST (สร้างใหม่) แล้วทดสอบเรียกผ่านเบราว์เซอร์หรือ REST Client extension
VS Code tip: ติดตั้ง extension REST Client (publisher: Huachao Mao) สร้างไฟล์ .http เขียน request ทดสอบ API ได้โดยไม่ต้องออกจาก VS Code เลย ไม่ต้องพึ่ง Postman
PHASE 5Async/Await — จุดที่ต่างจาก RDML มากที่สุด
2-3 วัน
  • ทำไมต้องมี async (รองรับ concurrent request จำนวนมากโดยไม่บล็อก thread)
  • รูปแบบ Task<T>, async, await
  • กฎง่ายๆ: ถ้า method เรียก database หรือ I/O ควรเป็น async เสมอ
เทียบ synchronous กับ asynchronous
// synchronous (บล็อกจนกว่าจะเสร็จ) — ไม่ควรใช้ในงานจริงที่ต่อ database
public IActionResult GetOrderSync(int id)
{
    var order = _dbContext.Orders.Find(id);   // รอตรงนี้ thread ถูกจับไว้ทั้งหมด
    return Ok(order);
}

// asynchronous (ปล่อย thread ไปทำงานอื่นระหว่างรอ) — มาตรฐานที่ควรใช้จริง
public async Task<IActionResult> GetOrderAsync(int id)
{
    var order = await _dbContext.Orders.FindAsync(id);   // await = รอแบบไม่บล็อก thread
    return Ok(order);
}

ให้จำง่ายๆ ว่า await ไม่ใช่แค่ "รอ" เฉยๆ แต่คือการบอกว่า "ระหว่างรอสิ่งนี้ ให้ thread ไปรับ request อื่นก่อนได้" ต่างจาก RPG ที่โปรแกรมหนึ่งครอบครอง job/thread เดียวตลอดการทำงาน

แบบฝึกหัด: แก้ controller จาก Phase 4 ให้ทุก method เป็น async (แม้ยังไม่ต่อ database จริง ก็ใช้ await Task.Delay(100) จำลองการรอไปก่อนเพื่อฝึก syntax)

// การ query ด้วย LINQ

    .Take(10)
    .ToListAsync();
ความหมายของแต่ละส่วนใน LINQ query

db.Orders — เข้าถึง table Orders ผ่าน DbContext (db คือชื่อตัวแปร DbContext ที่ถูก inject เข้ามา)

.Where(o => o.TotalAmount > 1000) — กรองแถวที่ TotalAmount มากกว่า 1000 เทียบได้กับ SQL WHERE TotalAmount > 1000 ส่วน o => คือ "lambda expression" อ่านว่า "สำหรับแต่ละแถว (เรียกว่า o) ให้เช็คเงื่อนไขนี้"

.OrderByDescending(o => o.CreatedAt) — เรียงจากใหม่ไปเก่า เทียบเท่า SQL ORDER BY CreatedAt DESC

.Take(10) — เอาแค่ 10 แถวแรก เทียบเท่า SQL TOP 10 หรือ LIMIT 10

.ToListAsync() — แปลงผลลัพธ์เป็น List และรันจริง (query ก่อนหน้าทั้งหมดยังไม่ถูกรันจริง จนกว่าจะเรียก ToListAsync หรือ method ลักษณะนี้ เรียกว่า "deferred execution" คือ query จะถูกประกอบขึ้นก่อน แล้วค่อยยิงไป database ทีเดียวตอนจบ)

public class ProductsModel : PageModel
{
    public List<Product> Products { get; set; } = new();

    public void OnGet()
    {
        // ตอนนี้ hardcode ไปก่อน ต่อ database จริงใน Phase 12

            new Product { Name = "สินค้า A", Price = 100 },

ความหมายของ syntax สำคัญ

@page — บอกว่าไฟล์นี้คือ Razor Page ที่เข้าถึงได้ผ่าน URL โดยตรง (ต้องมีบรรทัดนี้เสมอ เป็นบรรทัดแรกของไฟล์ .cshtml)

@model ProductsModel — ผูกไฟล์ .cshtml นี้เข้ากับ class ProductsModel ที่อยู่ในไฟล์ .cshtml.cs คู่กัน ทำให้เรียกใช้ Model.Products ในหน้า HTML ได้

@foreach — เขียน C# loop ปนอยู่ใน HTML ได้ตรงๆ โดยขึ้นต้นด้วย @

OnGet() — method พิเศษที่ Razor Pages เรียกอัตโนมัติทุกครั้งที่มีคนเปิดหน้านี้ด้วย HTTP GET (ถ้ามี OnPost() คู่กัน จะถูกเรียกตอนมีการ submit ฟอร์ม)

แบบฝึกหัด: สร้างหน้า Razor Page ใหม่ชื่อ Orders แสดง list ออเดอร์แบบ hardcode ข้อมูลไว้ก่อน (ยังไม่ต่อ database) ให้มีทั้งไฟล์ .cshtml และ .cshtml.cs คู่กันตามตัวอย่าง
พร้อมไป phase ถัดไปเมื่อ
  • เข้าใจว่าทำไมต้องมีไฟล์ .cshtml และ .cshtml.cs คู่กันเสมอ
  • เขียน @foreach วน list มาแสดงใน HTML ได้เอง
PHASE 11Razor Pages — ฟอร์มและการรับข้อมูลกลับ
3-4 วัน

  • [BindProperty] — รับค่าจากฟอร์มเข้ามาเป็น property อัตโนมัติ

@page
@model CreateModel

<form method="post">
    <label>ชื่อสินค้า</label>
    <input asp-for="NewProduct.Name" />

    <label>ราคา</label>
    <input asp-for="NewProduct.Price" />

// Create.cshtml.cs
public class CreateModel : PageModel
{
    [BindProperty]
    public Product NewProduct { get; set; } = new();

    public void OnGet() { }

    public IActionResult OnPost()
    {
        if (!ModelState.IsValid)
        {
            return Page();   // ส่งกลับไปหน้าเดิมพร้อมข้อความ error
        }

        // บันทึกข้อมูลจริง (ต่อ EF Core ใน Phase 12)
        return RedirectToPage("Products");
    }
}
ความหมายของ syntax สำคัญ

asp-for="NewProduct.Name" — Tag Helper ที่ผูก input นี้เข้ากับ property NewProduct.Name โดยอัตโนมัติ ทั้งตอนแสดงค่าเดิมและตอนรับค่าใหม่กลับมา ไม่ต้องเขียน JavaScript ผูกข้อมูลเอง

[BindProperty] — บอกว่า property นี้จะรับค่าจากฟอร์มที่ submit เข้ามาอัตโนมัติ ไม่ต้องเขียนโค้ดดึงค่าจาก request เอง

ModelState.IsValid — เช็คว่าข้อมูลที่ submit เข้ามาผ่านกฎ validation ที่กำหนดไว้บน property หรือไม่ (เช่น [Required] เหนือ property ที่ห้ามว่าง)

แบบฝึกหัด: เพิ่มหน้าฟอร์มสำหรับสร้างออเดอร์ใหม่ในโปรเจกต์ฝึกจาก Phase 10 พร้อม validation อย่างน้อย 1 field (เช่น ชื่อลูกค้าห้ามว่าง)

public class ProductsModel : PageModel
{
    private readonly AppDbContext _db;

    // รับ DbContext ผ่าน DI เหมือนที่เรียนใน Phase 2-3
    public ProductsModel(AppDbContext db)
    {
        _db = db;
    }

    public List<Product> Products { get; set; } = new();

    public async Task OnGetAsync()
    {
        Products = await _db.Products.ToListAsync();
    }

    public async Task<IActionResult> OnPostDeleteAsync(int id)
    {
        var product = await _db.Products.FindAsync(id);
        if (product is not null)
        {
            _db.Products.Remove(product);
            await _db.SaveChangesAsync();
        }
        return RedirectToPage();
    }
}

ความหมายของ syntax สำคัญ

OnPostDeleteAsync — ชื่อ method ตามด้วยคำว่า "Delete" ทำให้ Razor Pages รู้ว่า method นี้คือ handler พิเศษ ต้องเรียกผ่าน asp-page-handler="Delete" เท่านั้น แยกจาก OnPostAsync ปกติที่ไม่มีคำต่อท้าย

asp-route-id="@product.Id" — ส่งค่า id ของแถวนั้นไปพร้อมกับการ submit form เพื่อบอกว่าจะลบแถวไหน

แบบฝึกหัด: ทำให้โปรเจกต์ฝึกมี CRUD ครบ 4 อย่างผ่านหน้าเว็บจริง (list, สร้างใหม่, แก้ไข, ลบ) ต่อกับ SQLite หรือ SQL Server LocalDB เหมือนที่ฝึกไว้ใน Phase 6
พร้อมไป phase ถัดไปเมื่อ
  • ทำ CRUD ครบทั้ง 4 อย่างผ่านหน้าเว็บได้เองโดยไม่ต้องเปิดตัวอย่างดู
  • เข้าใจว่า handler พิเศษ (เช่น OnPostDeleteAsync) ทำงานต่างจาก OnPostAsync ปกติอย่างไร

Razor Pages เหมาะกับหน้าที่ submit แล้ว reload หน้าใหม่ทุกครั้ง ถ้าอยากได้ UI ที่อัพเดททันที โดยไม่ reload หน้า (เช่น filter ตาราง, นับจำนวนแบบ real-time) ให้ใช้ Blazor แทน ยังคงเป็น C# 100% เหมือนเดิม

  • Component ใน Blazor คือไฟล์ .razor ที่รวม HTML + C# ไว้ในไฟล์เดียว
  • @code { } block — ที่เก็บ property และ method ของ component
  • event binding ด้วย @onclick, two-way binding ด้วย @bind
  • วงจรชีวิตของ component — OnInitializedAsync

ความหมายของ syntax สำคัญ

@inject AppDbContext Db — วิธี inject service (DI) เข้ามาใช้ใน component โดยตรง คล้ายการ inject ผ่าน constructor ใน Controller แต่ syntax ต่างกันเพราะเป็นไฟล์ .razor

@bind="keyword" — ผูกค่าใน input เข้ากับตัวแปร keyword แบบสองทาง (พิมพ์ในช่อง input แล้วตัวแปรเปลี่ยนทันที ไม่ต้องเขียน event handler เอง)

@bind:event="oninput" — กำหนดว่าจะอัพเดทค่าทันทีที่พิมพ์ (ปกติ @bind เฉยๆ จะอัพเดท ตอนออกจากช่อง input เท่านั้น)

FilteredProducts — เป็น computed property (คำนวณใหม่ทุกครั้งที่ถูกเรียก) ทำให้ UI กรองข้อมูลใหม่ทันทีที่ keyword เปลี่ยน โดยไม่ต้อง reload หน้าเลย

แบบฝึกหัด: แปลงหน้า list สินค้าจาก Phase 12 ให้เป็น Blazor component ที่มีช่องค้นหาแบบ real-time (พิมพ์แล้ว list กรองทันทีโดยไม่ต้องกดปุ่ม submit)
