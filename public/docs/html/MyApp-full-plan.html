01 Discovery & Requirements 🟡 ตัวอย่าง — รออนุมัติจริง

Scope

ทำ: ระบบจัดการงานภายในทีมขนาดเล็ก มี desktop app ให้พนักงานใช้บันทึก/ติดตามงาน และ API กลางให้ระบบอื่นดึงข้อมูลได้

ไม่ทำ (non-goals): ไม่ทำ mobile app, ไม่ทำ real-time chat, ไม่รองรับ multi-tenant ในเวอร์ชันแรก

User Stories

  • ในฐานะพนักงาน ฉันต้องการสร้าง/แก้ไขงานของตัวเองผ่านหน้าต่าง desktop ได้
  • ในฐานะหัวหน้าทีม ฉันต้องการดู dashboard สรุปงานทั้งทีมผ่าน API ที่เชื่อมกับระบบอื่น

Platform Target

WPF (Windows only) สำหรับ desktop + ASP.NET Core Web API สำหรับ backend กลาง

Constraints

  • ต้องใช้งาน offline ได้บางส่วนฝั่ง desktop (sync ทีหลัง)
  • Data ต้องอยู่ใน on-prem database ตาม policy บริษัท

Dependencies ภายนอก

SQL Server on-prem, Active Directory สำหรับ auth (พิจารณาใน Phase 2)

  • อนุมัติแล้ว (ตัวอย่าง)
02 Architecture & Design 🟡 ตัวอย่าง

Pattern

MVVM ด้วย CommunityToolkit.Mvvm (ฝั่ง WPF) + Controller-based REST (ฝั่ง API)

DI Container

Microsoft.Extensions.DependencyInjection ใช้ร่วมกันทั้ง 2 track

Data Layer

EF Core + SQL Server, migration แบบ code-first

06 Testing & QA ⬜ ยังไม่เริ่ม
  • Unit test ViewModel/Service logic (MyApp.Core.Tests)
  • Integration test API ผ่าน WebApplicationFactory (MyApp.Api.Tests)
  • Manual test checklist: สร้างงาน → แก้ไข → ปิดงาน (WPF)
  • Bug list / known issues
07 Code Review & Hardening ⬜ ยังไม่เริ่ม
  • Review MVVM separation / null safety / async correctness
  • Input validation ฝั่ง API (model validation, [ApiController] auto 400)
  • Performance: startup time WPF, response time API endpoint หลัก
  • Security: connection string ไม่ hardcode, AD token handling ปลอดภัย
08 Documentation ⬜ ยังไม่เริ่ม
  • README (build/run instructions)
  • ADR สรุปการตัดสินใจสำคัญ (อ้างอิง Decision Log)
  • User guide สำหรับพนักงานที่ใช้ WPF app
  • API reference (Swagger หรือ Postman collection)
09 Packaging & Release ⬜ ยังไม่เริ่ม
  • Icon / branding สำหรับ WPF app
  • Packaging WPF: MSIX สำหรับแจกในองค์กร
  • Packaging API: Docker image + publish profile
  • Version bump + release notes
10 Deployment & Post-release ⬜ ยังไม่เริ่ม
  • Auto-update mechanism สำหรับ WPF (เช่น Squirrel หรือ MSIX auto-update)
  • Deploy API ขึ้น server/CI pipeline + health check endpoint
  • Crash reporting / telemetry
  • รวบรวม feedback → เพิ่มลง backlog รอบถัดไป (วนกลับ Phase 1)
Decision Log
เลือก EF Core แทน Dapper — ทีมคุ้นเคยกับ EF Core มากกว่า และ migration แบบ code-first ช่วยลดเวลา setup ในช่วงแรก แลกกับ raw performance ที่ Dapper ทำได้ดีกว่าเล็กน้อย
แยก MyApp.Api เป็นโปรเจ็คเสริม ไม่บังคับ — เผื่อทีมที่ต้องการแค่ desktop app อย่างเดียวไม่ต้องแบก dependency ของ ASP.NET Core
