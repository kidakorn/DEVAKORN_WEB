ใช้ VS Code ได้ไหม

ได้ทั้งคู่ครับ ไม่จำเป็นต้องใช้ Visual Studio (full IDE)

ทั้ง Django และ ASP.NET Core พัฒนาบน VS Code ได้เต็มรูปแบบ รวมถึง debug แบบตั้ง breakpoint และ step-through ได้ปกติ ต่างกันที่ extension ที่ต้องติดตั้งเพิ่มและความลื่นไหลของ tooling

Django (VS Code)
  • ติดตั้ง extension Python ของ Microsoft (จำเป็น)
  • เพิ่ม Pylance สำหรับ autocomplete และ type checking
  • debug ผ่านไฟล์ launch.json เลือก template "Django" ได้ทันที
  • ตั้ง breakpoint ในไฟล์ .py ได้ปกติ เห็นค่าตัวแปรระหว่าง request จริง
  • ไม่มี built-in database designer แบบ visual ต้องพึ่ง extension เสริมหรือ pgAdmin/DBeaver แยก
ASP.NET Core (VS Code)
  • ติดตั้ง extension C# Dev Kit ของ Microsoft (จำเป็น มาแทน OmniSharp เดิม)
  • ต้องติดตั้ง .NET SDK แยกจาก VS Code (ตัว editor ไม่รวม SDK มาให้)
  • debug ผ่าน launch.json ที่ C# Dev Kit generate ให้อัตโนมัติ
  • IntelliSense และ refactor tools ใกล้เคียง Visual Studio ตัวเต็มมากขึ้นเรื่อยๆ ในเวอร์ชันหลัง
  • บาง feature ขั้นสูง (เช่น visual designer ของ Blazor) ยังทำได้ดีกว่าใน Visual Studio ตัวเต็ม
สรุป: ทั้งสอง stack ทำงานบน VS Code ได้จริงและไม่ต้องพึ่ง Visual Studio เลย ความแตกต่างหลักคือ Django ใช้ Python extension ที่เบาและติดตั้งเร็วกว่า ส่วน ASP.NET Core ต้องติดตั้ง .NET SDK เพิ่มก่อนเสมอ แต่พอตั้งค่าเสร็จแล้วประสบการณ์ debug ทั้งคู่ใกล้เคียงกันมาก

โครงสร้างโปรเจกต์เริ่มต้น

Django — สร้างโปรเจกต์
คำสั่ง terminal
django-admin startproject myproject
cd myproject
python manage.py startapp orders
python manage.py runserver
ได้โครงสร้างโฟลเดอร์แบบ "project" ที่มีหลาย "app" ย่อยอยู่ข้างใน แต่ละ app คือหน่วยงานหนึ่ง (เช่น orders, users) แยกไฟล์ตาม convention: models.py, views.py, urls.py
ASP.NET Core — สร้างโปรเจกต์
คำสั่ง terminal
dotnet new webapi -o MyProject
cd MyProject
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet run
ได้โปรเจกต์เดียว (ไม่แยกเป็นหลาย app ย่อยแบบ Django) จัดโฟลเดอร์เองตาม convention ของทีม เช่น Controllers/, Models/, Services/ ปกติจะ add package ผ่าน NuGet เพิ่มตามที่ต้องใช้

Routing / URL

Django — urls.py
from django.urls import path
from . import views

urlpatterns = [
    path("orders/", views.order_list),
    path("orders/<int:order_id>/", views.order_detail),
]
กำหนด URL แยกเป็นไฟล์ต่างหาก (urls.py) แล้วชี้ไปยัง function ใน views.py เห็นภาพรวมเส้นทาง URL ทั้งหมดของ app ได้ในที่เดียว
ASP.NET Core — Controller attribute
[ApiController]
[Route("api/orders")]
public class OrdersController : ControllerBase
{
    [HttpGet("{orderId}")]
    public IActionResult GetOrder(int orderId)
    {
        // logic
    }
}
กำหนด route ด้วย attribute เหนือ class และ method โดยตรง (decorator-style) ไม่มีไฟล์ routing กลางแยกต่างหาก ต้องไล่ดูทีละ controller เพื่อเห็น route ทั้งหมด

Model และ ORM

Django — models.py
from django.db import models

class Order(models.Model):
    customer_name = models.CharField(max_length=100)
    total_amount = models.DecimalField(max_digits=10, decimal_places=2)
    created_at = models.DateTimeField(auto_now_add=True)

    def __str__(self):
        return self.customer_name
field ของ table ถูกกำหนดเป็น attribute ของ class ตรงๆ ไม่ต้องเขียน type แยก Python เป็น dynamically-typed จึงไม่บังคับ type annotation แต่ Django field type (CharField, DecimalField) ทำหน้าที่กำหนดชนิดข้อมูลแทน
ASP.NET Core — Model class (C#)
public class Order
{
    public int Id { get; set; }
    public string CustomerName { get; set; } = string.Empty;
    public decimal TotalAmount { get; set; }
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
}
C# เป็น strongly-typed ต้องระบุ type ของทุก property ชัดเจน (string, decimal, DateTime) compiler จะเช็คความถูกต้องของ type ให้ตั้งแต่ก่อนรัน ใกล้เคียงความรู้สึกกำหนด field แบบ DDS หรือ RPG data structure มากกว่า Python
Django — Query ข้อมูล
orders = Order.objects.filter(total_amount__gt=1000)
order = Order.objects.get(id=5)
Order.objects.create(customer_name="Somchai", total_amount=1500)
ASP.NET Core — Query ข้อมูล (EF Core)
var orders = await db.Orders
    .Where(o => o.TotalAmount > 1000)
    .ToListAsync();

var order = await db.Orders.FindAsync(5);
db.Orders.Add(new Order { CustomerName = "Somchai", TotalAmount = 1500 });
await db.SaveChangesAsync();
สังเกตว่า Django ORM เขียนสั้นและอ่านคล้ายประโยคภาษาอังกฤษ (filter, get, create) ส่วน EF Core ของ ASP.NET Core ใช้ LINQ ซึ่งมีรูปแบบคล้าย SQL ปนกับ lambda expression และเกือบทุก query ต้องใช้ await เพราะเป็น async by default ซึ่งเป็นแนวคิดที่ RPG/RDML ไม่มี (ต้องทำความเข้าใจเพิ่มว่า await คือ "รอผลลัพธ์แบบไม่บล็อก thread หลัก" ไม่ใช่แค่ "รอ" ธรรมดา)

View / Controller (จัดการ request)

Django — views.py
from django.http import JsonResponse
from .models import Order

def order_detail(request, order_id):
    order = Order.objects.get(id=order_id)
    return JsonResponse({
        "customer_name": order.customer_name,
        "total_amount": str(order.total_amount),
    })
view คือ function ธรรมดา รับ request เข้ามา return response ออกไป อ่านเป็นลำดับ บนลงล่างตรงไปตรงมา ไม่มี async ปนถ้าไม่ตั้งใจเขียนเอง
ASP.NET Core — Controller method
[HttpGet("{orderId}")]
public async Task<IActionResult> GetOrder(int orderId)
{
    var order = await db.Orders.FindAsync(orderId);
    if (order is null) return NotFound();

    return Ok(new {
        order.CustomerName,
        order.TotalAmount
    });
}
method อยู่ภายใน class (controller) ต้องจัดการ case ที่หาไม่เจอเอง (NotFound) และเกือบทุก method เป็น async (มี Task<...> ครอบ) ซึ่งเป็นรูปแบบมาตรฐานของ ASP.NET Core

ตัวอย่าง CRUD เต็มรูปแบบ (Create + Read)

Django — Create + Read ครบ flow
from django.shortcuts import get_object_or_404
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
import json

@csrf_exempt
def order_create(request):
    data = json.loads(request.body)
    order = Order.objects.create(
        customer_name=data["customer_name"],
        total_amount=data["total_amount"],
    )
    return JsonResponse({"id": order.id}, status=201)

def order_list(request):
    orders = Order.objects.all().order_by("-created_at")
    result = [
        {"id": o.id, "customer_name": o.customer_name}
        for o in orders
    ]
    return JsonResponse(result, safe=False)
ASP.NET Core — Create + Read ครบ flow
public record CreateOrderDto(string CustomerName, decimal TotalAmount);

[HttpPost]
public async Task<IActionResult> CreateOrder(CreateOrderDto dto)
{
    var order = new Order {
        CustomerName = dto.CustomerName,
        TotalAmount = dto.TotalAmount
    };
    db.Orders.Add(order);
    await db.SaveChangesAsync();
    return CreatedAtAction(nameof(GetOrder), new { orderId = order.Id }, order);
}

[HttpGet]
public async Task<IActionResult> ListOrders()
{
    var orders = await db.Orders
        .OrderByDescending(o => o.CreatedAt)
        .Select(o => new { o.Id, o.CustomerName })
        .ToListAsync();
    return Ok(orders);
}
จุดที่ต่างชัดเจนคือ ASP.NET Core นิยมประกาศ record (DTO) แยกสำหรับรับข้อมูล เข้ามาโดยเฉพาะ เพื่อให้ type-safe ตั้งแต่ต้นทาง ส่วน Django รับข้อมูลจาก request.body แบบ JSON ดิบแล้ว parse เอง ยืดหยุ่นกว่าแต่ไม่มีการเช็ค type ให้อัตโนมัติเท่า C#

การจัดการ Async — จุดที่ต่างจาก RDML มากที่สุด

Django
Django แบบดั้งเดิม (และที่ใช้กันส่วนใหญ่) เขียนแบบ synchronous คือรันทีละบรรทัดจากบนลงล่าง เหมือนที่คุ้นเคยจาก RPG/RDML ทุกประการ ไม่ต้องเรียนรู้ async/await เพิ่ม เว้นแต่จะเลือกใช้ Django async views ซึ่งเป็น feature เสริมที่ไม่บังคับใช้
ASP.NET Core
ASP.NET Core ออกแบบมาให้เขียนแบบ asynchronous เป็นมาตรฐานตั้งแต่ต้น (เกือบทุก method ที่เกี่ยวกับ database หรือ I/O จะมี async/await ปนอยู่เสมอ) ข้อดีคือ performance รองรับผู้ใช้พร้อมกันได้ดีกว่า แต่ต้องใช้เวลาทำความเข้าใจแนวคิดนี้ ก่อนจะเขียนโค้ดได้คล่องมือ
สรุปจุดนี้: ถ้าอยากได้ความรู้สึกใกล้เคียง RDML ที่สุด (โค้ดรันเป็นลำดับ ไม่ต้องคิดเรื่อง "รอแบบไม่บล็อก") Django จะปรับตัวง่ายกว่า ASP.NET Core ในช่วงแรกอย่างชัดเจน แต่ถ้าทีมพร้อมลงทุนเวลาเรียนรู้ async/await ตั้งแต่ต้น ASP.NET Core จะให้ผลลัพธ์ด้าน performance และ type-safety ที่ดีกว่าในระยะยาว
